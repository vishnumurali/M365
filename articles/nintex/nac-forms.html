NAC Forms – Responsive Forms with Rules, Variables, Data Lookups and Repeating Sections

Design Nintex Automation Cloud forms, covering the responsive designer, controls, rules (show/hide, required, validation), form variables and expressions, data lookup control from SharePoint, repeating sections, file upload and signatures, themes, and public vs authenticated forms.

NAC forms are responsive, built in the browser and typically used as the start event of a workflow (or as task forms). They can be public (anonymous, e.g. supplier registration) or require sign-in.

#Data lookup from SharePoint

The Data lookup control reads from a connector (SharePoint list, Salesforce…) using a connection, so users pick from live data (e.g. Plants list). You can filter it by another control's value for cascading choices.

#Rules examples

Rule Condition Action
Show QA head section Severity equals Critical Show group QA Head
Require due date Severity is Critical or Major Required: Due date
Validate amount Amount > 10,000 and CFO approval is empty Validation message

#Repeating sections

Repeating sections produce collections of objects in the workflow start event (e.g. line items). Loop over them with Loop for each to create child SharePoint items.

Migrating classic repeating sections

Classic Nintex Forms stored repeating data as XML in a list column. In NAC the same data arrives as a collection, so model it as a child list in SharePoint (parent ID lookup) rather than XML text.

#Interview questions

Q1How do NAC forms pass data to the workflow?

The form is the workflow's start event: every form control becomes a start event variable (repeating sections become collections, file uploads and signatures become file variables), available to all workflow actions.

Q2How do you show live SharePoint data in a NAC form dropdown?

Use the Data lookup control with a SharePoint Online connection, choose the list and display column, and optionally filter by another control's value for cascading lookups.
