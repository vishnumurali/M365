#The approval actions compared

Action Outcomes Use when
Request approval Approve / Reject Classic single or group approval; LazyApproval support
Request review Continue only Someone must look and acknowledge
Flexi task Custom outcomes (Approve, Reject, Need more info, Escalate) Most flexible; branch per outcome
Assign to-do task Complete Non-decision work item

Task options include behaviour for multiple assignees (first response applies, all must respond, majority) and escalation (delegate or auto-complete after a time).

Available inline functions differ slightly between Nintex versions (2010, 2013+, Office 365). Use the Insert reference → Inline functions tab in the designer to see the exact list and signatures for your version.

#Regular expression and collections

Split approvers 'a@x.com;b@x.com' into a collectionText
Regular expression:
  Pattern: ;
  Operation: Split
  Input text: {Variable:ApproverEmails}
  Store result in: colApprovers (Collection)

For each (colApprovers) → Request approval to {Variable:CurrentApprover}
Collection operation: Count → varApproverCount

#Web request (calling REST)

Update another list via SharePoint REST from Nintex (on-prem)Text
URL:      {Common:WebUrl}/_api/web/lists/getbytitle('Audit')/items
Method:   POST
Headers:  Accept: application/json;odata=nometadata
          Content-Type: application/json;odata=nometadata
Body:     {"Title":"Deviation {ItemProperty:ID} approved by {Common:Initiator}"}
Credentials: {WorkflowConstant:SvcSharePoint}
Store response content in: varResponse

#NAC equivalents (for migration)

Nintex for SharePoint / O365 NAC
Request approval / Flexi task Express approval, Assign a task (custom outcomes)
Set a condition / Run if Branch by condition / Run if
State machine Branch by stage
Loop / For each Loop for each / Loop n times / Loop condition
Query list / Update item SharePoint Online connector actions
Web request / Call web service Call a web service, or an Xtension
Regular expression / Collection operation Text actions (Regex), Collection actions
Workflow constants Connections + workflow variables / data tables
UDAs Component workflows

#Interview questions

Q1When do you use Flexi task instead of Request approval?

When you need custom outcomes beyond approve/reject (for example "Approve", "Reject", "Request info", "Escalate to QA head") and different branches per outcome.

Q2How do you call a REST API from a Nintex on-prem workflow?

With the Web request action (method, headers, body, credentials via workflow constants), then parse the response with Query JSON/Query XML or regular expressions into variables.
