Nintex Best Practices & Troubleshooting – Design, Performance, Governance and Common Errors

Field-tested guidance for Nintex on-prem, Office 365 and NAC, covering naming and documentation, error handling, avoiding chatty loops, task and history hygiene, service accounts, versioning, and a troubleshooting table of frequent errors.

#Troubleshooting

Symptom Likely cause Fix
Workflow stuck "In progress" at a Pause Timer job / workflow timer service not running Check Workflow timer jobs; on-prem restart SPTimerV4
"Failed on start (retrying)" Permissions, missing columns, corrupted definition Check history, republish, verify initiator rights
LazyApproval replies ignored Incoming email not configured, reply words not recognized Configure inbound email; check approved/declined vocabulary
Slow designer / site Huge history lists, many running instances Purge with NWAdmin; terminate orphans
Web request 401 Wrong credentials / auth type Use workflow constant credentials; check NTLM vs claims
NAC: connection errors Expired connection or permissions on SharePoint Re-authorize connection; verify site permissions of the connection account
NAC: workflow not starting from SharePoint event Event subscription missing or site not registered Re-publish workflow; check start event configuration

#Governance

  • Maintain an inventory of workflows: owner, purpose, list or site, last run, dependencies.
  • Use service accounts for connections and constants, never personal accounts.
  • Define who may publish to production sites (on-prem: Nintex permissions per site).
  • Review long-running instances monthly and terminate abandoned ones.

#Interview questions

Q1What are the first things you check when a Nintex workflow is stuck?

The workflow history and status page for the last executed action, timer services and workflow timer jobs (on-prem), permissions of the initiator or connection account, and whether the workflow is waiting for an event (pause, item update, task) that never happens.

Q2How do you make Nintex workflows maintainable?

Descriptive action names and comments, small single-purpose workflows (UDAs/component workflows), central configuration (constants, lists), consistent error handling and notifications, status columns on items, and exported versions kept in source control.
