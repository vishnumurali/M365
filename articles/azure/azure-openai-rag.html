Azure OpenAI over SharePoint Content – Retrieval-Augmented Generation (RAG) Done Securely

Build a custom AI assistant over SharePoint documents with Azure OpenAI and Azure AI Search, covering ingestion and chunking, embeddings, security trimming by permissions, prompt design, citations, evaluation, and when to use Microsoft 365 Copilot or Copilot Studio instead.

Before building custom AI, check whether Microsoft 365 Copilot, SharePoint agents or Copilot Studio with SharePoint knowledge already meet the need. They respect permissions out of the box. Build custom RAG when you need a specific UX, special data sources, custom models or full control.

#Security trimming is non-negotiable

If you index content without ACLs, the assistant can leak confidential documents to anyone. Store permitted principals with each chunk and filter every query, or use Copilot, which enforces permissions natively.

#Quality checklist

  • Chunking that respects headings, with titles and paths in each chunk.
  • Hybrid search + semantic ranker for better retrieval than vectors alone.
  • System prompt: answer only from sources, cite them, say "I don't know".
  • Evaluation set of real questions, measuring groundedness, relevance and citation accuracy.
  • Content hygiene: remove outdated versions, because garbage in, confident garbage out.

#Interview questions

Q1What is retrieval-augmented generation (RAG)?

A pattern where a search step retrieves relevant passages from your content (often hybrid keyword and vector search) and passes them to the language model with the question, so answers are grounded in your data, with citations, instead of relying only on the model's training.

Q2How do you prevent a custom RAG app from exposing documents users can't access?

Index permission information (users and groups allowed) with every chunk and filter queries by the current user's group memberships (security trimming). Or use Microsoft 365 Copilot or Copilot Studio with SharePoint knowledge, which respect SharePoint permissions natively.
