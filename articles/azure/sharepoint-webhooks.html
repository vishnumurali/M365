SharePoint Webhooks with Azure Functions – Subscriptions, Validation, GetChanges and Renewal

The complete, production-ready pattern for reacting to SharePoint list changes, covering webhook subscription creation, the validation handshake, queue-based processing, GetChanges with change tokens, renewing subscriptions before 180 days, security with clientState, and monitoring.

SharePoint webhooks notify your HTTPS endpoint when items in a list or library change. They are the modern replacement for remote event receivers in SharePoint Online. Notifications are deliberately minimal ("something changed in list X"), so your code asks SharePoint what changed with GetChanges.

#Architecture

#1 · Create the subscription

REST (app-only token or user with list permissions)HTTP
POST https://contoso.sharepoint.com/sites/quality/_api/web/lists/getbytitle('Deviations')/subscriptions
Accept: application/json;odata=nometadata
Content-Type: application/json

{
  "resource": "https://contoso.sharepoint.com/sites/quality/_api/web/lists/getbytitle('Deviations')",
  "notificationUrl": "https://fn-codex-webhooks.azurewebsites.net/api/spWebhook?code=<function-key>",
  "expirationDateTime": "2027-03-31T00:00:00Z",
  "clientState": "f6c2…secret-shared-with-receiver"
}
Or with PnP PowerShellPowerShell
Add-PnPWebhookSubscription -List "Deviations" -NotificationUrl "https://fn-codex-webhooks.azurewebsites.net/api/spWebhook?code=..." `
  -ExpirationDate (Get-Date).AddDays(170) -ClientState $env:WEBHOOK_CLIENT_STATE
Get-PnPWebhookSubscription -List "Deviations"

#2 · Receiver (validation + enqueue)

See the full TypeScript and C# receivers in Remote event receivers → webhooks. Key rules:

  • Echo validationtoken as text/plain with 200 within 5 seconds.
  • For notifications, verify clientState, enqueue and return 200 immediately.
  • If your endpoint fails, SharePoint retries (5 times, 5 minutes apart).

#3 · Processor with GetChanges

processor.ts (queue trigger, Node v4)TypeScript
import { app, InvocationContext } from '@azure/functions';
import { TableClient } from '@azure/data-tables';
import { DefaultAzureCredential } from '@azure/identity';

const tokens = new TableClient(process.env.TABLE_URL!, 'ChangeTokens', new DefaultAzureCredential());

app.storageQueue('processChanges', {
  queueName: 'sp-changes', connection: 'AzureWebJobsStorage',
  handler: async (msg: any, ctx: InvocationContext) => {
    const listId = msg.resource;                                   // list GUID
    const siteUrl = `https://contoso.sharepoint.com${msg.siteUrl}`;
    const stored = await tokens.getEntity<any>('lists', listId).catch(() => null);
    const startToken = stored?.token ?? `1;3;${listId};${Date.now() * 10000 + 621355968000000000 - 600000000};-1`; // 1 min ago

    const res = await spFetch(`${siteUrl}/_api/web/lists('${listId}')/GetChanges`, {
      method: 'POST',
      body: JSON.stringify({ query: { Item: true, Add: true, Update: true, DeleteObject: true,
                                      ChangeTokenStart: { StringValue: startToken } } })
    });
    const changes: any[] = (await res.json()).value;
    for (const c of changes) {
      // ChangeType: 1 Add, 2 Update, 3 DeleteObject
      await handleItemChange(siteUrl, listId, c.ItemId, c.ChangeType);   // must be idempotent
    }
    if (changes.length) {
      const last = changes[changes.length - 1].ChangeToken.StringValue;
      await tokens.upsertEntity({ partitionKey: 'lists', rowKey: listId, token: last }, 'Replace');
    }
  }
});

spFetch acquires an app-only token for SharePoint (certificate or managed identity with Sites.Selected) and calls REST.

#4 · Renew before expiry

Timer: extend subscriptions weeklyC#
[Function("RenewWebhooks")]
public async Task Run([TimerTrigger("0 0 3 * * 1")] TimerInfo t)   // Mondays 03:00
{
    foreach (var sub in await _sp.GetSubscriptionsAsync("Deviations"))
        if (sub.ExpirationDateTime < DateTime.UtcNow.AddDays(30))
            await _sp.UpdateSubscriptionAsync(sub.Id, DateTime.UtcNow.AddDays(170));
}
Webhook gotchas
  • Maximum expiration is 180 days, so renewal is mandatory.
  • Notifications are batched and delayed (often seconds to a minute), not instant.
  • Webhooks cover list items and files only (no site-level events). Use Graph change notifications for other resources.
  • Process idempotently: the same change can be reported more than once.

#Interview questions

Q1Why do SharePoint webhook notifications not include the changed item data?

To keep notifications lightweight and secure. The receiver must call GetChanges with a stored change token to find which items changed and how, then read the items with its own permissions.

Q2What happens if your webhook endpoint is down?

SharePoint retries the notification several times (5 retries, 5 minutes apart). Because you track a change token, the next successful GetChanges call still returns all changes since the last processed token, so nothing is lost.

Q3What is the maximum lifetime of a webhook subscription?

180 days. Production solutions run a scheduled renewal job that extends subscriptions well before expiry and recreates any that disappeared.
