Delegation in Power Apps – The 500/2000 Row Limit Explained (and How to Beat It)

What delegation is, why non-delegable formulas silently return wrong results, delegable functions per data source (SharePoint, Dataverse, SQL), the data row limit, warning signs, and proven patterns to build apps over large lists.

Delegation means Power Apps asks the data source to do the work (filter, sort, count) and only downloads the matching rows. When a formula is not delegable, Power Apps downloads only the first N rows (the data row limit: 500 by default, up to 2,000) and processes them locally. Anything beyond N is silently ignored.

500default data row limit (non-delegable queries)
2,000maximum configurable limit
0errors shown to users when results are incomplete

Always look for the blue underline and delegation warning in Power Apps Studio. It is the only signal you get.

#Patterns that work at scale

Bad vs goodPower Fx
// ❌ Not delegable on SharePoint: Search + Lower inside Filter
Filter(Deviations, Lower(Title) = Lower(txtSearch.Text) || txtSearch.Text in Description)

// ✅ Delegable: indexed Status + StartsWith, then shape locally
With(
    { rows: Filter(Deviations, Status.Value = "Open", StartsWith(Title, txtSearch.Text)) },
    AddColumns(rows, "DaysOpen", DateDiff(Created, Now(), TimeUnit.Days))
)
ClearCollect is not a workaround

ClearCollect(col, BigList) is limited by the same row limit (or requires looping tricks that are slow and fragile). Collections are for small reference data or offline caches, not for copying big lists.

#Interview questions

Q1What happens when a formula isn't delegable?

Power Apps retrieves only the first N rows (the data row limit, 500 by default, configurable up to 2,000) and evaluates the formula locally on those rows. Results can be incomplete without any error, and Studio shows only a design-time delegation warning.

Q2How would you implement search over a 100,000-item SharePoint list?

Use delegable StartsWith on an indexed column, narrow results with indexed filters (status, date, owner), or call a server-side search through a Power Automate flow (SharePoint search or Graph) and return the results. For heavy search requirements, consider Dataverse or SQL as the store.

Q3Is CountRows delegable on SharePoint?

No. On SharePoint it counts only up to the row limit. Use a flow, a list view count or a pre-computed value, or move to Dataverse, where CountRows on a filtered table is delegable.
