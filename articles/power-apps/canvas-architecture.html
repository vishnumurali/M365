Canvas App Architecture – Screens, Controls, Data Flow and App Lifecycle Events

How a canvas app is structured and executed, covering the player, App.OnStart vs App.Formulas vs StartScreen, screen lifecycle, controls and properties, data sources and caching, and a reference architecture for a SharePoint-backed request app.

A canvas app is a set of screens containing controls whose properties are formulas. The Power Apps player (browser, mobile app, Teams or SharePoint embed) loads the app package, evaluates formulas and talks to connectors.

#Runtime architecture

#Startup: OnStart vs Formulas vs StartScreen

Property Use for Tip
App.Formulas Named formulas: fxUser = User(); fxIsAdmin = ...; Lazy, cached, auto-updating; preferred over OnStart variables
App.OnStart Imperative init: ClearCollect reference data Keep it short; it delays the first screen
App.StartScreen Choose the first screen by Param("screen") Replaces Navigate in OnStart
Screen.OnVisible Load screen-specific data Use Concurrent() for parallel loads
App.OnError Global error handling and logging Combine with IfError locally
App.Formulas (named formulas)Power Fx
fxUserEmail = Lower(User().Email);
fxIsQualityLead = !IsBlank(LookUp(QualityLeads, Lower(Email) = fxUserEmail));
fxOpenCount = CountRows(Filter(Deviations, Status.Value <> "Closed"));
Screen.OnVisible – parallel loadingPower Fx
Concurrent(
    ClearCollect(colAreas, Areas),
    ClearCollect(colMyOpen, Filter(Deviations, Owner.Email = fxUserEmail && Status.Value <> "Closed")),
    Set(varProfile, Office365Users.MyProfileV2())
)

#Reference architecture: SharePoint request app

Keep the app thin

Put long-running or privileged logic in Power Automate (run with a service connection) or an API, and keep the app focused on UI and validation. It improves performance and avoids giving users rights they should not have on the data source.

#Interview questions

Q1Why are named formulas (App.Formulas) preferred over variables set in OnStart?

They are declarative, evaluated lazily only when needed, cached and recalculated automatically when dependencies change, and they don't block app startup. OnStart variables run imperatively before the first screen and can go stale.

Q2What does Concurrent() do?

It runs several behaviour formulas in parallel, for example multiple ClearCollect calls on screen load, which reduces total load time compared with sequential execution.
