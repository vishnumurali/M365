Canvas vs Model-Driven vs SPFx vs Power Pages – A Decision Guide

Choose the right app technology with a decision tree and comparison matrix covering audience, data source, UI control, offline, licensing, ALM and performance, with typical scenarios mapped to recommendations.

Most project failures with Power Platform start with the wrong app type. Use this guide before you build.

#Decision tree

#Comparison matrix

#Typical scenarios

Scenario Recommendation
Leave/expense request with SharePoint list + approval Canvas app (or customized list form) + Power Automate
Inventory management with items, warehouses, movements, audit Model-driven app on Dataverse
Intranet dashboard on the home page SPFx web part
Supplier onboarding portal for external vendors Power Pages
Field inspection app with photos, offline Canvas app on Dataverse (offline)
Complex form replacing InfoPath Canvas (SharePoint form or standalone) or SPFx form customizer

#Interview questions

Q1When is a model-driven app a better choice than a canvas app?

When the solution is data-heavy and process-driven on Dataverse (many related tables, role-based security, business process flows, auditing) and a consistent, responsive UI is acceptable. You configure the data model instead of building screens.

Q2Can you combine app types?

Yes. Model-driven apps can include custom pages (canvas technology), canvas apps can be embedded in SharePoint and Teams, and SPFx pages can embed Power Apps. Choose per user journey, not per project.
