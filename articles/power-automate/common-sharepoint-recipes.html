15 Common SharePoint Flow Recipes – Reminders, Archiving, Folders, Permissions & More

Ready-made patterns for everyday SharePoint automation, covering overdue reminders, weekly digests, archiving old items, auto-creating folders, unique reference numbers, permissions on submit, copying files, syncing lists, and notifying on metadata changes.

1 · Overdue reminders

Daily recurrence → Get items (DueDate lt today, Status ne Closed) → group by owner → one email each.

2 · Weekly digest

Recurrence Monday 08:00 → items created last 7 days → HTML table → email/Teams.

3 · Archive old items

Monthly → items Closed and Modified lt -12 months → copy to Archive list → delete.

4 · Folder per project

Item created in Projects → Create new folder in Documents/{Title} → set permissions.

5 · Reference number

Item created → compose DEV-yyyy-00000 from ID → update item (trigger condition: RefNo empty).

6 · Lock after approval

Approved → break inheritance → readers only + approver group edit.

7 · Copy approved doc

Library item Approved → Copy file to Published site library → set metadata.

8 · Field change alert

Created or modified → Get changes for an item → if Status changed → notify.

9 · Expiring contracts

Daily → EndDate within 30 days → reminder to owner, escalation at 7 days.

10 · Sync two lists

Item modified in master → find by key in replica → update or create.

11 · Teams post on news

Page published in Site Pages (PromotedState = 2) → post to channel.

12 · Form to list

Microsoft Forms response → Get response details → create item (+ attachments to folder).

13 · Email to library

Email arrives with attachment in shared mailbox → save attachment → set metadata.

14 · New user onboarding

Item in Onboarding list → create tasks in Planner + Teams welcome + add to groups (Graph).

15 · Version cleanup

Scheduled → for large libraries trim versions via REST (or use version limits).

#Recipe deep dive: overdue reminders grouped by owner

Key expressionsText
Get items filter:  DueDate lt '@{formatDateTime(utcNow(),'yyyy-MM-dd')}' and Status ne 'Closed'
Select (owners):   item()?['Owner']?['Email']
Distinct owners:   union(body('Select_owners'), body('Select_owners'))
Filter array:      @equals(item()?['Owner']?['Email'], items('Apply_to_each'))
Count in subject:  length(body('Filter_array'))
Link column:       concat('<a href="', item()?['{Link}'], '">Open</a>')
Make HTML tables look professional

Create the table with Create HTML table, then wrap it in a Compose with a <style> block (borders, padding, header colour) and use the Compose output as the email body. See HTML table reports.

#Recipe deep dive: unique reference numbers without race conditions

PatternText
Trigger: When an item is created (trigger condition: @empty(triggerOutputs()?['body/RefNo']))
Compose: concat('DEV-', formatDateTime(utcNow(),'yyyy'), '-', formatNumber(triggerOutputs()?['body/ID'], '00000'))
Update item: RefNo = outputs('Compose')

Using the SharePoint ID guarantees uniqueness without a counter list, so you avoid the race conditions of "read counter, increment, write".

#Interview questions

Q1How do you send one reminder email per owner instead of one per item?

Get the overdue items, build a distinct list of owners (Select the emails, then union(x, x)), loop over the owners, use Filter array to collect each owner's items, render an HTML table, and send one email per owner.

Q2What's the safest way to generate unique sequential reference numbers?

Derive them from the SharePoint item ID, which is unique and assigned by SharePoint. Counter lists updated by concurrent flows can produce duplicates unless you serialize with trigger concurrency set to 1.
