Workflow Manager & SharePoint Workflow Manager – Installing the 2013 Workflow Platform

How the SharePoint 2013 workflow platform runs outside SharePoint, covering the Workflow Manager and Service Bus architecture, installation and registration, the move to SharePoint Workflow Manager (2023), and troubleshooting stuck workflows.

SharePoint 2013 moved the new workflow engine out of SharePoint. "SharePoint 2013 workflows" run in a separate farm, Workflow Manager, which talks to SharePoint over REST and OAuth. SharePoint 2010-style workflows still run inside SharePoint itself.

In 2023 Microsoft released SharePoint Workflow Manager (SPWFM), a supported successor to the ageing Workflow Manager 1.0 + Service Bus 1.1. It is built for SharePoint Server Subscription Edition, 2019 and 2016.

#Architecture

  • Workflow definitions (XAML) are published from SPD or Visual Studio into SharePoint, which pushes them to Workflow Manager.
  • Workflow instances run in Workflow Manager. When they need SharePoint data they call SharePoint REST with an OAuth token (S2S trust).
  • SharePoint calls Workflow Manager to start instances and deliver events (item changed, task completed).

#Installation outline (SharePoint Workflow Manager)

Register Workflow Manager with SharePoint (run on a SharePoint server)PowerShell
# HTTPS with a trusted certificate is strongly recommended
Register-SPWorkflowService -SPSite "https://sp.contoso.com" `
  -WorkflowHostUri "https://wfm.contoso.com:12290" `
  -ScopeName "SharePoint" -Force

# Verify the proxy is connected
Get-SPWorkflowServiceApplicationProxy | Select-Object DisplayName, Status
$proxy = Get-SPWorkflowServiceApplicationProxy
$proxy.GetWorkflowServiceAddress((Get-SPSite "https://sp.contoso.com"))
Health check on the Workflow Manager serverPowerShell
Get-WFFarm | Select-Object Endpoints, HttpsPort, RunAsAccount
Get-WFFarmStatus            # all services should be Running
Keep the client on every SharePoint server

The Workflow Manager Client (or SPWFM client) must be installed on all SharePoint servers, including new ones you add later. A missing client on one front end causes intermittent "workflow cannot start" errors.

#Troubleshooting stuck workflows

Symptom Likely cause Fix
2013 platform missing in SPD Not registered, or proxy not connected to the web app Register-SPWorkflowService, check proxy group
"Started" forever, no history Workflow Manager cannot call back to SharePoint (DNS, certificate, firewall, OAuth) Test from WFM server to SharePoint URL; check trust certs; check Get-WFFarmStatus
401 in WFM event log User profile missing for the initiator, App Management service missing UPS synced, App Management + Subscription Settings services running
Suspended with HTTP 500 REST call in the workflow failed Read workflow status page details, fix URL or permissions, resume
After SharePoint upgrade, all workflows broken New farm not re-registered, scope mismatch Re-register with the same scope name, republish definitions

#The future

  • SharePoint Online: 2013 workflows were retired on 2 April 2026. Use Power Automate or Nintex Automation Cloud.
  • On-premises SE: SharePoint Workflow Manager keeps 2013-style workflows supported, but no new features are coming. Treat them as legacy and plan the move to Power Automate (with the on-premises data gateway) or Nintex.

#Interview questions

Q1Where do SharePoint 2013 workflows execute?

In Workflow Manager (now SharePoint Workflow Manager), a separate service farm with its own SQL databases. SharePoint stores the definitions and tasks and communicates with Workflow Manager over HTTPS with OAuth server-to-server trust.

Q2What is the role of the Workflow Manager client on SharePoint servers?

It contains the assemblies SharePoint needs to talk to Workflow Manager. It must be installed on every SharePoint server, otherwise starting or publishing workflows fails on servers without it.

Q3Why did Microsoft release SharePoint Workflow Manager in 2023?

Workflow Manager 1.0 and Service Bus 1.1 were old, depended on outdated components and were reaching end of support. SharePoint Workflow Manager gives on-premises customers (especially Subscription Edition) a supported engine for existing 2013-style workflows.
