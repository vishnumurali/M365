Boundaries, Limits & the 5,000-Item List View Threshold

The SharePoint Server limits that bite in real projects, covering the list view threshold, unique permissions, content database size, file size and lookup columns, plus why they exist and how to design around them.

SharePoint limits come in three flavours: boundaries (hard, cannot be exceeded), thresholds (configurable defaults), and supported limits (tested guidance). Most production incidents trace back to a handful of them.

5,000list view threshold (items scanned per query, users)
20,000threshold for admins / auditors (default)
50,000unique permission scopes per list (recommended ≤ 5,000)
12lookup, people & managed metadata columns per view (threshold)
200 GBcontent DB for general collaboration (guidance)
15 GBmax file size (SharePoint 2019 / SE)

#Why the 5,000-item threshold exists

SQL Server escalates row locks to a table lock when a single query touches roughly 5,000 rows. All list items for a content database live in the same AllUserData table, so one unindexed query on a big list could lock the table for every site in that database. The list view threshold (LVT) stops queries that would scan more than 5,000 rows.

The threshold is about rows scanned, not rows stored

A list can hold millions of items, up to 30 million per list. You just cannot run a query that has to scan more than 5,000 of them without an index.

#Designing around the threshold

CSOM paging through a large list safelyC#
var list = ctx.Web.Lists.GetByTitle("Deviations");
var query = new CamlQuery
{
    // ORDER BY ID uses the built-in index; RowLimit keeps each page under the threshold
    ViewXml = "<View Scope='RecursiveAll'><Query><OrderBy><FieldRef Name='ID'/></OrderBy></Query><RowLimit Paged='TRUE'>2000</RowLimit></View>"
};
do
{
    var page = list.GetItems(query);
    ctx.Load(page, p => p.ListItemCollectionPosition, p => p.Include(i => i.Id, i => i["Title"], i => i["Status"]));
    ctx.ExecuteQuery();
    foreach (var item in page) { /* process */ }
    query.ListItemCollectionPosition = page.ListItemCollectionPosition;   // null when done
} while (query.ListItemCollectionPosition != null);

#Other limits that matter

Limit Value (2016/2019/SE) Type Design tip
Items per list 30,000,000 Supported Use indexes, archive
Unique permissions per list 50,000 (recommend ≤ 5,000) Supported Break inheritance at folder/library, not item level
Security principals per scope 5,000 Supported Grant to groups, never individuals
Lookup columns per view 12 Threshold Fewer lookups/people columns per view
Content DB size 200 GB general; up to 4 TB for specific scenarios Supported Split site collections across DBs
Site collections per content DB 10,000 max (2,500 non-personal recommended) Supported Plan DB-per-department
File size 15 GB (2019/SE), 10 GB (2016), 2 GB (2013) Boundary Configure upload limits in web app & IIS
Path length (URL) 400 characters (2019+, decoded), 260 (2013/2016) Boundary Watch deep folder structures during migration
Versions per item 400,000 major; 511 minor Boundary Limit versions in library settings
Indexed columns per list 20 Boundary Index only filter/sort columns
Same concepts in SharePoint Online

SharePoint Online has the same 5,000 LVT (not configurable) but adds automatic indexing for some views and supports up to 30M items per list. The design rules transfer one-to-one. See Large lists in SPO.

#Interview questions

Q1Why does SharePoint enforce a 5,000-item list view threshold?

Because SQL Server escalates locks to a table-level lock at about 5,000 rows, and all list items in a content database share one table. An unindexed query on a large list could block every site in that database. The threshold protects farm performance.

Q2A view on a 60,000-item list fails. How do you fix it?

Index the columns used in the view's filter, make sure the first filter uses an indexed column and returns fewer than 5,000 items, use folders or metadata navigation, and avoid sorting on unindexed columns. For code, page with RowLimit and ListItemCollectionPosition.

Q3What is the recommended limit for unique permissions in a list, and why?

The supported limit is 50,000 unique scopes per list, but Microsoft recommends staying at or under about 5,000. Many scopes slow permission checks, ACL recalculation and search crawls. Grant permissions to groups at library or folder level instead of breaking inheritance on items.
