User Profile Service & Managed Metadata – Profiles, Sync, Term Store & Taxonomy

How profile data flows from Active Directory into SharePoint, how My Sites and audiences use it, and how the Managed Metadata Service term store, content type hub and managed navigation work, with PowerShell and CSOM examples.

Two service applications quietly power much of SharePoint's "smart" behaviour: the User Profile Service (UPS) knows who people are, and the Managed Metadata Service (MMS) knows what content is about.

#User Profile Service

Option Available in Notes
Active Directory Import 2013 → SE Fast, one-way, AD only. Good default.
Microsoft Identity Manager (MIM) 2016 2016 → SE External sync engine for complex mappings, multiple sources and write-back. Replaced the built-in FIM sync from 2010/2013.
Custom import (CSOM/PowerShell) All Push extra attributes (e.g. cost centre from HR) into profile properties.
Set a custom profile property for many users from CSVPowerShell
$site = Get-SPSite "https://mysites.contoso.com"
$ctx  = Get-SPServiceContext $site
$upm  = New-Object Microsoft.Office.Server.UserProfiles.UserProfileManager($ctx)

Import-Csv "C:\HR\costcentres.csv" | ForEach-Object {
  $account = "i:0#.w|contoso\$($_.SamAccountName)"
  if ($upm.UserExists($account)) {
    $p = $upm.GetUserProfile($account)
    $p["CostCentre"].Value = $_.CostCentre
    $p.Commit()
  }
}
$site.Dispose()
Profile property privacy

Each profile property has a privacy level (Everyone → Only Me) and a replicable flag. Sensitive HR attributes should not default to Everyone, because they will appear in people search.

#Managed Metadata Service (MMS)

The MMS hosts the term store, a central, hierarchical taxonomy shared by every site that uses the MMS proxy.

#What MMS gives you

  • Managed metadata columns where users pick from a controlled vocabulary with type-ahead, synonyms and translations.
  • Enterprise keywords, a folksonomy that lets users add free tags.
  • The content type hub, which publishes content types from one site collection to all subscribing sites through timer jobs.
  • Managed navigation, where site navigation is driven by a term set (friendly URLs on publishing sites).
  • Search refiners, because managed metadata becomes great refiners.
Create terms with CSOM (Microsoft.SharePoint.Client.Taxonomy)C#
using (var ctx = new ClientContext("https://sp.contoso.com"))
{
    var session = TaxonomySession.GetTaxonomySession(ctx);
    var store   = session.GetDefaultSiteCollectionTermStore();
    var group   = store.Groups.GetByName("Enterprise");
    var set     = group.TermSets.GetByName("Departments");

    var finance = set.CreateTerm("Finance", 1033, Guid.NewGuid());
    finance.CreateTerm("Accounts Payable", 1033, Guid.NewGuid());
    finance.CreateTerm("Treasury", 1033, Guid.NewGuid());
    finance.CreateLabel("Fin", 1033, false);   // synonym

    store.CommitAll();
    ctx.ExecuteQuery();
}
Export a term set (for migration or backup) with PnP PowerShellPowerShell
Connect-PnPOnline -Url "https://sp.contoso.com" -CurrentCredentials   # on-prem PnP (legacy module)
Export-PnPTermGroupToXml -Out "C:\Export\Enterprise-terms.xml" -Identity "Enterprise"
Term IDs matter in migrations

Managed metadata field values store the term GUID. If you recreate a term store by hand in the target, all values break. Migrate the term store with its GUIDs (ShareGate, PnP export/import with IDs) before you migrate content.

#How UPS and MMS work together

  • Profile properties such as Department and Office can be bound to term sets, so profiles use the same vocabulary as documents.
  • Audiences can be built from profile property rules ("Department = Finance") and used to target navigation and web parts.
  • People search refiners (department, skills) come from the profile store and are often backed by terms.

#Interview questions

Q1What is the difference between AD Import and MIM synchronization?

AD Import is built into SharePoint: fast, one-way, Active Directory only, with simple mappings. Microsoft Identity Manager is an external sync engine for multiple sources, complex transformations and write-back. It replaced the built-in FIM sync starting with SharePoint 2016.

Q2What is a content type hub?

A site collection designated in the MMS proxy settings whose content types are published to all site collections that consume that MMS. Timer jobs (Content Type Hub and Content Type Subscriber) push updates, giving consistent content types across the farm.

Q3Why do managed metadata values break after a migration?

The column stores the term ID (GUID), not just the label. If the target term store has terms with different GUIDs, values cannot be resolved. Migrate the term store with the original IDs first, then content.
