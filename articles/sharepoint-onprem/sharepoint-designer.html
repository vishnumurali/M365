What is SharePoint Designer? Architecture, Workflows, Data Views & End of Support

SharePoint Designer 2007–2013 explained, covering how it connects to sites, what it was used for (workflows, data views, external content types, page edits), the 2010 vs 2013 workflow platforms inside it, governance risks, and its July 2026 end of support.

SharePoint Designer (SPD) is a free desktop tool that connects directly to a SharePoint site and lets power users and developers build no-code workflows, data views, external content types and edit pages and master pages. It descends from FrontPage and shipped in three versions: 2007, 2010 and 2013 (2013 is the last; it works with SharePoint 2013, 2016, 2019, SE and SharePoint Online).

#Architecture: how SPD talks to SharePoint

SPD does not deploy anything to servers. Everything it creates is stored in the site (as files, list items or workflow definitions), so a site collection admin can use it without farm access. That convenience is also its biggest governance problem.

#Calling REST from a 2013 workflow

SPD 2013 workflows can call REST through the Call HTTP Web Service action with dictionaries:

SPD 2013: update another list via REST (action sequence)Text
1. Build Dictionary → RequestHeaders
     Accept        = application/json;odata=nometadata
     Content-Type  = application/json;odata=nometadata
     IF-MATCH      = *
     X-HTTP-Method = MERGE
2. Build Dictionary → RequestBody   { Status = "Approved" }
3. Call HTTP Web Service
     URL     = [%Workflow Context:Current Site URL%]_api/web/lists/getbytitle('Requests')/items([%Current Item:RequestID%])
     Method  = POST
     RequestHeaders = Variable: RequestHeaders
     RequestContent = Variable: RequestBody
     ResponseCode   → Variable: code
4. App Step (wrap the call) when the workflow needs elevated (app) permissions

#Governance risks

  • Anyone with Design/Full Control could open a site in SPD and change pages, master pages or workflows in production. Many outages started this way.
  • No source control. Workflows and pages lived only in the site, with no history beyond versioning.
  • Unghosted (customized) pages. Editing a page in SPD stores a full copy in the content DB, so it no longer receives updates from the file system. That causes upgrade surprises.

Admins can restrict SPD per web application (Central Admin → General Application Settings → Configure SharePoint Designer settings) or per site collection:

Disable SharePoint Designer for a web applicationPowerShell
$wa = Get-SPWebApplication "https://sp.contoso.com"
$wa.AllowDesigner = $false                  # block SPD entirely
$wa.AllowRevertFromTemplate = $false        # block detaching pages
$wa.AllowMasterPageEditing = $false
$wa.ShowURLStructure = $false
$wa.Update()

#End of support and what replaces it

SharePoint Designer 2013 reached end of support on 14 July 2026

No further fixes. It still connects to many sites, but workflows built on the 2013 platform no longer run in SharePoint Online, and 2010 workflows have been gone since 2020.

SPD use Modern replacement
Workflows Power Automate (cloud flows, approvals), Nintex Automation Cloud
Data View web parts List / Document library web parts + view formatting, Power BI, SPFx
Custom list forms Form formatting / conditional formulas, Power Apps forms, SPFx form customizer
External content types Power Apps with connectors, Graph connectors, SPFx + API
Page / master page edits Modern pages, themes, SPFx application customizer

See Mapping legacy workflow actions to Power Automate and Workflow migration strategies.

#Interview questions

Q1What is the difference between a list workflow, a reusable workflow and a site workflow in SPD?

A list workflow is bound to one list. A reusable workflow is bound to a content type (or all), can be attached to many lists, and can be exported as a WSP. A site workflow is not tied to an item and is started manually or by schedule for site-level tasks.

Q2What does the App Step do in a SharePoint 2013 workflow?

It runs the enclosed actions with the workflow app's permissions instead of the initiating user's. It is used when the workflow must update items the user cannot edit. The site feature "Workflows can use app permissions" must be enabled, and the workflow app must be granted rights.

Q3Why was SharePoint Designer considered a governance risk?

It allowed site owners to change production pages, master pages and workflows directly, with no source control or deployment process. Customized (unghosted) pages also broke during upgrades. Admins often restricted it at web application or site collection level.
