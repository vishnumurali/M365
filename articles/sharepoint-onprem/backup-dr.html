Backup, Restore & Disaster Recovery for SharePoint Server

What to back up (and what not), farm vs granular vs SQL backups, restoring a deleted site collection or document, unattached content database recovery, and designing DR with SQL AlwaysOn, with scripts.

A SharePoint farm is mostly SQL Server databases plus configuration on the servers. A good recovery plan protects both, and it is defined by two numbers: RPO (how much data you can lose) and RTO (how fast you must be back).

#Recovery layers, from fastest to slowest

#What to back up

Item How Notes
Content databases SQL Server backups (full + diff + log) The heart of your data, so use full recovery model
Service app DBs (MMS, Secure Store, UPS, BDC, Search admin) SQL backups Secure Store also needs the passphrase
Configuration DB, Central Admin content DB SQL or farm backup Only useful for restoring the same farm; not for DR farms
Search index Farm backup (Backup-SPFarm) or rebuild by crawling Index restore must match the topology
Customizations Source control + WSP packages + scripts Do not rely on backups to recover code
IIS, web.config, certificates Scripts, documentation, cert export Rebuild servers from scripts
Farm configuration Backup-SPConfigurationDatabase + documentation For rebuilds
Site collection and farm backupsPowerShell
# Granular: one site collection (good up to ~100 GB)
Backup-SPSite -Identity "https://sp.contoso.com/sites/finance" -Path "\\backup\sp\finance_$(Get-Date -f yyyyMMdd).bak" -UseSqlSnapshot

# Restore it (to the same or another URL/content DB)
Restore-SPSite -Identity "https://sp.contoso.com/sites/finance-restored" -Path "\\backup\sp\finance_20261001.bak" -DatabaseName "WSS_Content_Restore" -Force

# Farm-level backup (config + content + service apps + search)
Backup-SPFarm -Directory "\\backup\spfarm" -BackupMethod Full

#Restoring a single document from last week

When the recycle bins are empty, restore last week's SQL backup of the content DB to a temporary database name (do not attach it to a web app), then export from it:

Recover from an unattached content databasePowerShell
$db = Get-SPContentDatabase -ConnectAsUnattachedDatabase -DatabaseName "WSS_Content_HR_Restore" -DatabaseServer "SQL01"
# Export a list or library (or a whole web) from the unattached DB
Export-SPWeb -Identity "https://sp.contoso.com/sites/hr" -ItemUrl "/sites/hr/Policies" `
  -Path "C:\recover\policies.cmp" -UnattachedContentDatabase $db -IncludeVersions All
# Import into the live site (or a staging site first)
Import-SPWeb -Identity "https://sp.contoso.com/sites/hr" -Path "C:\recover\policies.cmp" -UpdateVersions Overwrite

#Disaster recovery design

Keep both farms at the same patch level

The DR farm must have the same build, language packs and customizations as production. A content database from a newer build cannot be attached to an older farm.

#Interview questions

Q1How do you restore a single deleted document when the recycle bins are empty?

Restore a SQL backup of the content database to a new database name, connect to it as an unattached content database, use Export-SPWeb -UnattachedContentDatabase (or Central Admin granular recovery) to export the library or item, and import it into the live site.

Q2Why don't you replicate the configuration database to a DR farm?

The configuration database is farm-specific: it contains server names, topology and service instances. A DR farm has its own configuration database. You replicate content and selected service application databases instead.

Q3What is the difference between RPO and RTO?

RPO (recovery point objective) is the maximum acceptable data loss measured in time, which drives backup or replication frequency. RTO (recovery time objective) is how quickly service must be restored, which drives standby farms and automation.
