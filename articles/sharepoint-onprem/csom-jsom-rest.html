CSOM, JSOM & REST – Client-Side CRUD in C# and JavaScript

The three classic client APIs side by side, with the same create, read, update and delete operations in C# CSOM, JavaScript JSOM and REST (fetch), plus request digests, ETags, batching and when to pick which.

SharePoint 2010 introduced the Client Object Model so code could run outside the server: in the browser (JSOM), in .NET apps (CSOM) and in Silverlight. SharePoint 2013 added the REST API at /_api. All three talk to the same server endpoint (/_vti_bin/client.svc) and are available in SharePoint Server and SharePoint Online.

CSOM (.NET) JSOM (JavaScript) REST (/_api)
Language C#, PowerShell JS in SharePoint pages Any
Batching ExecuteQuery sends all queued ops executeQueryAsync $batch (multipart)
Payload XML XML JSON (OData v3)
Auth Windows, SharePointOnlineCredentials (legacy), access tokens Page cookie Cookie + digest, or bearer token
Best for Back-end tools, migrations, PnP Legacy pages (2010–2016) SPFx, scripts, Power Automate HTTP

#The same CRUD in three APIs

#Create

CSOM – create itemC#
using (var ctx = new ClientContext("https://sp.contoso.com/sites/quality"))
{
    // On-prem Windows auth: ctx.Credentials = CredentialCache.DefaultNetworkCredentials;
    List list = ctx.Web.Lists.GetByTitle("Deviations");
    ListItem item = list.AddItem(new ListItemCreationInformation());
    item["Title"] = "Temperature excursion – Cold room 2";
    item["Area"] = "Warehouse";
    item["DueDate"] = DateTime.Today.AddDays(7);
    item.Update();
    ctx.Load(item, i => i.Id);
    ctx.ExecuteQuery();                       // one round trip
    Console.WriteLine($"Created {item.Id}");
}
JSOM – create itemJavaScript
var ctx = SP.ClientContext.get_current();
var list = ctx.get_web().get_lists().getByTitle("Deviations");
var item = list.addItem(new SP.ListItemCreationInformation());
item.set_item("Title", "Temperature excursion – Cold room 2");
item.set_item("Area", "Warehouse");
item.update();
ctx.load(item);
ctx.executeQueryAsync(
  function () { console.log("Created", item.get_id()); },
  function (sender, args) { console.error(args.get_message()); });
REST – create itemJavaScript
async function getDigest(siteUrl) {
  const r = await fetch(`${siteUrl}/_api/contextinfo`, { method: "POST", headers: { Accept: "application/json;odata=nometadata" } });
  return (await r.json()).FormDigestValue;
}

const site = "https://sp.contoso.com/sites/quality";
const res = await fetch(`${site}/_api/web/lists/getbytitle('Deviations')/items`, {
  method: "POST",
  headers: {
    Accept: "application/json;odata=nometadata",
    "Content-Type": "application/json;odata=nometadata",
    "X-RequestDigest": await getDigest(site)
  },
  body: JSON.stringify({ Title: "Temperature excursion – Cold room 2", Area: "Warehouse" })
});
console.log("Created", (await res.json()).Id);
Note

odata=nometadata vs odata=verbose Older samples send odata=verbose and must include __metadata: { type: "SP.Data.DeviationsListItem" } in the body. With nometadata (SharePoint 2013 SP1+ and SPO) you can skip __metadata. The responses are smaller too.

#Read with filters

CSOM – read with CAML + IncludeC#
var query = new CamlQuery { ViewXml =
  @"<View><Query><Where><Eq><FieldRef Name='Status'/><Value Type='Choice'>Submitted</Value></Eq></Where>
    <OrderBy><FieldRef Name='Created' Ascending='FALSE'/></OrderBy></Query><RowLimit>100</RowLimit></View>" };
ListItemCollection items = ctx.Web.Lists.GetByTitle("Deviations").GetItems(query);
ctx.Load(items, col => col.Include(i => i.Id, i => i["Title"], i => i["Author"]));   // load only what you need
ctx.ExecuteQuery();
foreach (var i in items)
    Console.WriteLine($"{i.Id}: {i["Title"]} by {((FieldUserValue)i["Author"]).LookupValue}");
JSOM – read with CAMLJavaScript
var q = new SP.CamlQuery();
q.set_viewXml("<View><Query><Where><Eq><FieldRef Name='Status'/><Value Type='Choice'>Submitted</Value></Eq></Where></Query><RowLimit>100</RowLimit></View>");
var items = list.getItems(q);
ctx.load(items, "Include(Id, Title, Author)");
ctx.executeQueryAsync(function () {
  var e = items.getEnumerator();
  while (e.moveNext()) { var it = e.get_current(); console.log(it.get_id(), it.get_item("Title")); }
}, onError);
REST – OData $select / $filter / $expandJavaScript
const url = `${site}/_api/web/lists/getbytitle('Deviations')/items` +
  `?$select=Id,Title,Status,Author/Title,Author/EMail&$expand=Author` +
  `&$filter=Status eq 'Submitted'&$orderby=Created desc&$top=100`;
const data = await (await fetch(url, { headers: { Accept: "application/json;odata=nometadata" } })).json();
data.value.forEach(i => console.log(i.Id, i.Title, i.Author.Title));
// Next page: data["odata.nextLink"]

#Update

CSOM – updateC#
ListItem item = ctx.Web.Lists.GetByTitle("Deviations").GetItemById(42);
item["Status"] = "In Review";
item.Update();                 // or item.SystemUpdate() (2013+) / item.UpdateOverwriteVersion()
ctx.ExecuteQuery();
JSOM – updateJavaScript
var item = list.getItemById(42);
item.set_item("Status", "In Review");
item.update();
ctx.executeQueryAsync(onOk, onError);
REST – MERGE with IF-MATCHJavaScript
await fetch(`${site}/_api/web/lists/getbytitle('Deviations')/items(42)`, {
  method: "POST",
  headers: {
    Accept: "application/json;odata=nometadata",
    "Content-Type": "application/json;odata=nometadata",
    "X-RequestDigest": await getDigest(site),
    "X-HTTP-Method": "MERGE",
    "IF-MATCH": "*"            // or the item's ETag for optimistic concurrency
  },
  body: JSON.stringify({ Status: "In Review" })
});   // 204 No Content on success

#Delete

CSOM – delete / recycleC#
ListItem item = ctx.Web.Lists.GetByTitle("Deviations").GetItemById(42);
item.Recycle();        // or item.DeleteObject() for permanent delete
ctx.ExecuteQuery();
JSOM – deleteJavaScript
list.getItemById(42).deleteObject();
ctx.executeQueryAsync(onOk, onError);
REST – DELETE (or /recycle)JavaScript
await fetch(`${site}/_api/web/lists/getbytitle('Deviations')/items(42)/recycle()`, {
  method: "POST",
  headers: { "X-RequestDigest": await getDigest(site), Accept: "application/json;odata=nometadata" }
});
// Permanent: POST .../items(42) with "X-HTTP-Method": "DELETE", "IF-MATCH": "*"

#Special column types cheat sheet

Column type CSOM value REST body
Person (single) new FieldUserValue { LookupId = 12 } "OwnerId": 12
Person (multi) FieldUserValue[] "ReviewersId": [12, 15] (verbose: { results: [12,15] })
Lookup new FieldLookupValue { LookupId = 3 } "ProductId": 3
Managed metadata TaxonomyFieldValue + SetFieldValueByValue Use ValidateUpdateListItem with `"Label
Hyperlink new FieldUrlValue { Url, Description } "Link": { "Url": "...", "Description": "..." } (nometadata)
Date DateTime (UTC aware) ISO 8601 string "2026-10-08T00:00:00Z"
ValidateUpdateListItem: one endpoint for awkward fields

POST /_api/web/lists/getbytitle('X')/items(1)/ValidateUpdateListItem accepts form values as strings for every field type (people as claims JSON, taxonomy as Label|GUID, dates as local strings) and can set Created/Modified with bNewDocumentUpdate. It is invaluable for migrations.

#Which one should I use in 2026?

  • SPFx (browser): REST through SPHttpClient or PnPjs. JSOM is legacy.
  • Back-end .NET: PnP Core SDK or CSOM for .NET Standard with modern auth, or Microsoft Graph SDK where Graph covers the scenario.
  • Scripts: PnP PowerShell or CLI for Microsoft 365.
  • Low-code: Power Automate "Send an HTTP request to SharePoint" (REST).

See the API landscape and the REST API cheat sheet.

#Interview questions

Q1What does ExecuteQuery do in CSOM?

CSOM is batch-based. Calls such as GetByTitle, Load and property sets are queued locally. ExecuteQuery() (or executeQueryAsync in JSOM) sends the whole batch to client.svc/ProcessQuery in one request and populates the loaded objects. Accessing a property you did not Load throws PropertyOrFieldNotInitializedException.

Q2Why do REST POST requests need an X-RequestDigest?

It is SharePoint's anti-CSRF token for cookie-authenticated requests. Get it from /_api/contextinfo (or _spPageContextInfo/__REQUESTDIGEST on classic pages) and send it on every write. Requests authenticated with an OAuth bearer token do not need it.

Q3How do you update a list item in REST without overwriting someone else's change?

Read the item's ETag (odata.etag) and send it in IF-MATCH. If the item changed in between, SharePoint returns 412 Precondition Failed. IF-MATCH: * skips the concurrency check.
