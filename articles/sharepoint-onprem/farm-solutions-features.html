Farm Solutions (WSP) & Features – Packaging, Scopes, Receivers & Upgrades

How full-trust customizations are packaged and deployed, covering WSP anatomy, feature scopes, element manifests, feature receivers, upgrade actions and a deployment pipeline, plus how to retire them before moving to the cloud.

From MOSS 2007 onwards, customizations were shipped as solution packages (.wsp) containing one or more Features. A WSP is just a CAB file with a manifest.xml. A Feature is a unit of functionality that you activate at a specific scope.

#Anatomy of a WSP

Feature scope Activated on Typical contents
Farm The whole farm Delegate controls, farm-wide timer jobs
WebApplication One web application web.config mods, web-app timer jobs
Site A site collection Site columns, content types, web parts gallery, master pages
Web One site Lists, pages, custom actions

#Elements: declarative provisioning

Elements.xml – site column, content type and listXML
<?xml version="1.0" encoding="utf-8"?>
<Elements xmlns="http://schemas.microsoft.com/sharepoint/">
  <Field ID="{8A1C3D2E-5B4F-4E6A-9C7D-1E2F3A4B5C6D}" Name="DeviationArea" StaticName="DeviationArea"
         DisplayName="Area" Type="Choice" Group="Contoso Quality" Required="TRUE">
    <CHOICES><CHOICE>Production</CHOICE><CHOICE>Warehouse</CHOICE><CHOICE>Lab</CHOICE></CHOICES>
  </Field>

  <!-- Content type ID: 0x01 (Item) + 00 + new GUID without braces/dashes -->
  <ContentType ID="0x0100A7B8C9D0E1F2435465768798A9B0C1D2" Name="Deviation" Group="Contoso Quality" Inherits="TRUE">
    <FieldRefs>
      <FieldRef ID="{8A1C3D2E-5B4F-4E6A-9C7D-1E2F3A4B5C6D}" Name="DeviationArea" />
    </FieldRefs>
  </ContentType>

  <ListInstance Title="Deviations" Url="Lists/Deviations" TemplateType="100" FeatureId="00bfea71-de22-43b2-a848-c05709900100" OnQuickLaunch="TRUE" />
</Elements>

#Feature receivers: imperative logic

Feature receiver: bind content type, add indexes, clean up on deactivateC#
[Guid("2f1d0c4e-7a6b-4f55-9a7e-3c2b1a0d9e8f")]
public class QualityFeatureEventReceiver : SPFeatureReceiver
{
    public override void FeatureActivated(SPFeatureReceiverProperties properties)
    {
        var web = (SPWeb)properties.Feature.Parent;          // Web-scoped feature
        SPList list = web.Lists.TryGetList("Deviations");
        SPContentType ct = web.AvailableContentTypes["Deviation"];
        if (list != null && ct != null && list.ContentTypes[ct.Name] == null)
        {
            list.ContentTypesEnabled = true;
            list.ContentTypes.Add(ct);
            list.Fields["Area"].Indexed = true;               // index before the list grows!
            list.Fields["Area"].Update();
            list.Update();
        }
    }

    public override void FeatureDeactivating(SPFeatureReceiverProperties properties)
    {
        // Decide carefully: deleting lists on deactivate destroys business data.
        // Usually remove only things that are safe to remove (custom actions, timer jobs).
    }

    public override void FeatureUpgrading(SPFeatureReceiverProperties properties,
                                          string upgradeActionName, IDictionary<string, string> parameters)
    {
        if (upgradeActionName == "AddStatusField")
        {
            var web = (SPWeb)properties.Feature.Parent;
            var list = web.Lists["Deviations"];
            if (!list.Fields.ContainsField("Status"))
                list.Fields.Add("Status", SPFieldType.Choice, required: false);
        }
    }
}
Feature.xml upgrade actions (versioned features)XML
<Feature xmlns="http://schemas.microsoft.com/sharepoint/" Version="1.1.0.0" ...>
  <UpgradeActions>
    <VersionRange BeginVersion="1.0.0.0" EndVersion="1.1.0.0">
      <CustomUpgradeAction Name="AddStatusField" />
      <ApplyElementManifests>
        <ElementManifest Location="NewPages\Elements.xml" />
      </ApplyElementManifests>
    </VersionRange>
  </UpgradeActions>
</Feature>
Run feature upgrades after Update-SPSolutionPowerShell
Update-SPSolution -Identity "Contoso.Quality.wsp" -LiteralPath "C:\Deploy\Contoso.Quality.wsp" -GACDeployment
# Find feature instances that need upgrade and upgrade them
$web = Get-SPWeb "https://sp.contoso.com/sites/quality"
$web.QueryFeatures([Microsoft.SharePoint.SPFeatureScope]::Web, $true) | ForEach-Object { $_.Upgrade($false) }
$web.Dispose()

#Retiring farm solutions (cloud readiness)

Farm solutions cannot move to SharePoint Online. Before migrating, map each component:

Farm component Modern replacement
Visual web part SPFx web part
Custom action / ribbon button (JS) SPFx ListView Command Set
Delegate control / master page tweaks SPFx Application Customizer
Event receiver Webhook + Azure Function or Power Automate
Timer job Azure Function (timer trigger) or scheduled Power Automate flow
Content types / fields via XML PnP provisioning template or site scripts
Custom field type SPFx field customizer + column formatting
Application pages in LAYOUTS SPFx full-page app or a Power App

#Interview questions

Q1What are the four feature scopes?

Farm, WebApplication, Site (site collection) and Web (site). The scope decides where the feature is activated and what its elements can provision.

Q2What is the difference between Add-SPSolution and Install-SPSolution?

Add-SPSolution uploads the WSP to the farm's solution store in the configuration database. Install-SPSolution deploys it to servers through a timer job: assemblies to the GAC or bin, files to the hive, and web.config changes.

Q3How do you upgrade an already-activated feature?

Increase the feature Version, add UpgradeActions (custom upgrade actions handled in FeatureUpgrading, ApplyElementManifests, AddContentTypeField), deploy with Update-SPSolution, then call SPFeature.Upgrade() on each feature instance.
