Business Connectivity Services (BCS) – External Content Types & External Lists

Surface SQL Server, WCF and custom .NET data inside SharePoint as external lists, with the BCS architecture, Secure Store authentication modes, building an external content type in SharePoint Designer, CRUD code and its modern replacements.

Business Connectivity Services (BCS) (called Business Data Catalog in MOSS 2007) lets SharePoint read and write data that lives outside SharePoint, such as a SQL table, a WCF service or a custom .NET API, and show it as an external list that looks almost like a normal list.

#Architecture

An External Content Type (ECT) describes an entity, for example Customer, with fields, an identifier and operations:

Operation (stereotype) Required for
Read List (Finder) Showing the external list
Read Item (SpecificFinder) Opening an item, external data columns
Create / Update / Delete Editing from SharePoint
Association Related entities (Customer → Orders)

#Authentication options

Mode How it works When to use
User's identity (PassThrough) The user's Windows identity flows to SQL Requires Kerberos constrained delegation (double hop)
BDC identity / RevertToSelf The app pool account connects Simple but risky (all users get the app pool's rights); disabled by default
Secure Store (impersonated) SharePoint maps the user or group to stored credentials Most common: a group of users maps to one SQL login
Create a Secure Store target application for BCSPowerShell
$ctx = Get-SPServiceContext "https://sp.contoso.com"
$f1 = New-SPSecureStoreApplicationField -Name "SQL User" -Type UserName -Masked:$false
$f2 = New-SPSecureStoreApplicationField -Name "SQL Password" -Type Password -Masked:$true
$app = New-SPSecureStoreTargetApplication -Name "CRMSql" -FriendlyName "CRM SQL" `
          -ContactEmail "spadmin@contoso.com" -ApplicationType Group
$admins = New-SPClaimsPrincipal -Identity "CONTOSO\sp_admins" -IdentityType WindowsSamAccountName
$users  = New-SPClaimsPrincipal -Identity "CONTOSO\Sales" -IdentityType WindowsSamAccountName
New-SPSecureStoreApplication -ServiceContext $ctx -TargetApplication $app `
   -Fields $f1, $f2 -Administrator $admins -CredentialsOwnerGroup $users
# Then set the credentials once (Central Admin or Update-SPSecureStoreGroupCredentialMapping)

#Building an ECT in SharePoint Designer (no code)

  1. Open the site in SharePoint Designer 2013 → External Content Types → New.
  2. Add Connection → SQL Server → choose Connect with Impersonated Custom Identity and enter the Secure Store target app ID.
  3. Right-click the table → Create All Operations. This generates Read List, Read Item, Create, Update and Delete.
  4. Pick the identifier column and set filters, especially a Limit filter so that Read List does not try to return a million rows.
  5. Save, then Create Lists & Form to generate an external list.
  6. In Central Admin → BDC service → set permissions on the ECT (Execute, Selectable in clients).
Throttling is on purpose

BCS throttles result sizes, by default 2,000 rows for database connectors (configurable with Set-SPBusinessDataCatalogThrottleConfig). Add filters instead of raising limits blindly, because external lists are not designed for huge tables.

#Reading an external list with CSOM

External lists look like lists but behave differently: no versioning, no workflows on items (2013 workflows can call the external system via HTTP instead), and queries must use the ECT's filters.

Read an external list (CSOM)C#
using (var ctx = new ClientContext("https://sp.contoso.com/sites/sales"))
{
    var list  = ctx.Web.Lists.GetByTitle("Customers");
    var query = new CamlQuery
    {
        ViewXml = "<View><Query><Where><Eq><FieldRef Name='Country'/><Value Type='Text'>India</Value></Eq></Where></Query><RowLimit>100</RowLimit></View>"
    };
    var items = list.GetItems(query);
    ctx.Load(items);
    ctx.ExecuteQuery();
    foreach (var item in items)
        Console.WriteLine($"{item["CustomerId"]}  {item["Name"]}");
}

#Modern alternatives (SharePoint Online and new builds)

Need Modern approach
Show SQL data in a page SPFx web part calling an Azure Function / API (see SPFx + Azure SQL)
Edit external data in a low-code way Power Apps with the SQL Server connector (gateway for on-prem SQL)
Sync data into SharePoint lists Power Automate or Dataflows into Dataverse / lists
Search external data in Microsoft 365 Microsoft Graph connectors (formerly Microsoft Search connectors)
Virtual (no-copy) access in Dataverse Virtual tables

BCS in SharePoint Online exists in a limited form (OData and WCF via Azure, no SQL connector through Secure Store in the classic way) and is rarely chosen for new work.

#Interview questions

Q1What are the minimum operations an external content type needs for an external list?

Read List (Finder) and Read Item (SpecificFinder). Create, Update and Delete are needed only if users edit data.

Q2How do you avoid the double-hop problem with BCS and SQL Server?

Either configure Kerberos constrained delegation so the user's identity flows to SQL, or use Secure Store with impersonated custom or group credentials so SharePoint connects with mapped credentials.

Q3What would you use instead of BCS in SharePoint Online?

For display and edit, an SPFx web part backed by an Azure Function or API, or Power Apps with a gateway. For search, Microsoft Graph connectors. For copying data, Dataflows or Power Automate.
