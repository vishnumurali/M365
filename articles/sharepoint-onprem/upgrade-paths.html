Upgrade Paths – 2010 → 2013 → 2016 → 2019 → Subscription Edition (Database Attach)

How SharePoint version upgrades work, covering why there is no in-place upgrade, the database-attach method step by step, supported hops (including the 2016 → SE shortcut), service application upgrades, customizations and a project checklist.

SharePoint Server does not support in-place upgrades between major versions. You build a new farm, then bring content across by database attach: restore the old databases into the new farm's SQL Server and mount them, and SharePoint upgrades the schema. Third-party migration tools such as ShareGate are the alternative when you want to restructure or skip versions.

#Supported hops

From To Native path
2010 SE 2010 → 2013 → 2016 → SE (three DB-attach hops)
2013 SE 2013 → 2016 → SE (two hops)
2016 SE Direct DB attach
2019 SE Direct DB attach
Skipping versions with tools

Each native hop needs a temporary farm, so 2010 → SE natively means building 2013 and 2016 farms just to upgrade databases. Migration tools (ShareGate, AvePoint, Quest) copy content directly from old to new and let you clean up as you go. See On-prem to on-prem.

#The database-attach process

#Step by step

1. On the SOURCE farm: inventory + set read-only for the final runPowerShell
Get-SPContentDatabase | Select-Object Name, WebApplication, CurrentSiteCount,
  @{n='SizeGB';e={[math]::Round($_.DiskSizeRequired/1GB,1)}} | Export-Csv C:\upg\dbs.csv -NoTypeInformation
# Final cut-over: make DBs read-only in SQL (users can still read)
# ALTER DATABASE [WSS_Content_HR] SET READ_ONLY WITH NO_WAIT
2. On the TARGET farm: service apps from restored databasesPowerShell
# Managed Metadata
$pool = Get-SPServiceApplicationPool "SharePoint Services App Pool"
$mms  = New-SPMetadataServiceApplication -Name "Managed Metadata Service" -ApplicationPool $pool -DatabaseName "SP2016_Service_MMS"
New-SPMetadataServiceApplicationProxy -Name "MMS Proxy" -ServiceApplication $mms -DefaultProxyGroup

# Secure Store (then re-apply the master key passphrase)
$ss = New-SPSecureStoreServiceApplication -Name "Secure Store" -ApplicationPool $pool -DatabaseName "SP2016_Service_SecureStore" -AuditingEnabled
$ssp = New-SPSecureStoreServiceApplicationProxy -Name "Secure Store Proxy" -ServiceApplication $ss -DefaultProxyGroup
Update-SPSecureStoreApplicationServerKey -ServiceApplicationProxy $ssp -Passphrase $passphrase

# User Profile (profile + social DBs; sync DB is recreated)
New-SPProfileServiceApplication -Name "User Profile Service" -ApplicationPool $pool `
  -ProfileDBName "SP2016_Profile" -SocialDBName "SP2016_Social" -ProfileSyncDBName "SE_Sync"
3. Deploy customizations, then test each content DBPowerShell
# Deploy the SAME (or SE-compatible) WSPs first, so tests find the features
Add-SPSolution C:\deploy\Contoso.Intranet.wsp; Install-SPSolution Contoso.Intranet.wsp -GACDeployment -AllWebApplications

$wa = "https://sp.contoso.com"
Test-SPContentDatabase -Name "WSS_Content_HR" -WebApplication $wa |
  Select-Object Category, Error, UpgradeBlocking, Message, Remedy | Format-List

Typical Test-SPContentDatabase findings:

Category Meaning Action
MissingFeature A feature ID used in sites is not installed Deploy the WSP, or remove the feature from sites in the source
MissingWebPart Web part class not found Deploy, or remove the web part from pages
MissingAssembly Event receiver assembly missing Deploy, or remove the receiver registration
MissingSetupFile Ghosted file references a missing file Deploy the file or delete the orphan
SiteOrphan Orphaned site in the DB Repair before upgrade
4. Mount (this performs the schema upgrade)PowerShell
Mount-SPContentDatabase -Name "WSS_Content_HR" -WebApplication $wa -DatabaseServer "SQLSE-AG" -Verbose
# Logs: %ProgramFiles%\Common Files\Microsoft Shared\Web Server Extensions\16\LOGS\Upgrade-*.log
Get-SPSite -ContentDatabase "WSS_Content_HR" -Limit All | Select-Object Url, CompatibilityLevel
5. Site collection upgrade (only needed for 2010 → 2013 compatibility levels)PowerShell
# 2013 farms could host 2010-mode (14) sites; those must be upgraded to 15 before moving to 2016
Get-SPSite -Limit All | Where-Object CompatibilityLevel -eq 14 | Upgrade-SPSite -VersionUpgrade -Unthrottled

#Planning checklist

  • Inventory: sites, sizes, customizations (WSPs, features, web parts), workflows, InfoPath forms, add-ins, event receivers, BCS models, authentication modes.
  • Clean up in the source: delete unused sites, orphaned features and broken web parts. A smaller upgrade is a faster upgrade.
  • Customizations: rebuild or retarget WSPs for the new version (.NET Framework, API changes). Decide what to retire.
  • Authentication: classic-mode web apps (2010) must be converted to claims before 2013+ (Convert-SPWebApplication).
  • Trial upgrade with production DB copies and time each step to build a realistic cut-over plan.
  • Search: plan a full crawl on the new farm (index size × time).
  • URLs and DNS: same URLs mean easy user adoption, so plan certificates and DNS cut-over.
  • Rollback: keep the source farm read-only but available until sign-off.
SharePoint 2016 and 2019 are out of support since 14 July 2026

If you are still on 2016 or 2019, the direct DB-attach path to Subscription Edition is the fastest supported route. If your strategy is cloud, go straight to SharePoint Online migration instead of upgrading first.

#Interview questions

Q1Why does SharePoint use database attach instead of in-place upgrade?

In-place upgrades of complex multi-server farms were risky and hard to roll back. Database attach lets you build and test a clean new farm, upgrade databases one at a time, rehearse with copies, and keep the old farm available as a rollback.

Q2What does Test-SPContentDatabase do?

It checks a content database against the target web application before mounting and reports missing features, web parts, assemblies, setup files, orphans and whether issues are upgrade-blocking. It does not modify the database.

Q3What is the supported path from SharePoint 2013 to Subscription Edition?

2013 → 2016 → SE via database attach (two hops). A direct 2013 → SE hop is not supported natively. A third-party migration tool can copy content directly.

Q4Which service application databases can be upgraded with database attach?

Commonly Managed Metadata, Secure Store, User Profile (Profile and Social), Business Data Connectivity and Search Administration (with care). Others, such as usage and state, are recreated.
