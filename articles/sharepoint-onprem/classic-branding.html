Classic Branding – Master Pages, Page Layouts, Design Manager & JSLink

How classic SharePoint sites were branded and customized, covering master pages, page layouts, publishing, alternate CSS, Design Manager, Client-Side Rendering (JSLink) and Script Editor web parts, plus the risks they create in upgrades and how to modernize them.

Before modern pages, SharePoint looked the way its master page said it should. Brand-heavy intranets in 2007–2016 replaced master pages, built page layouts for publishing sites, and injected JavaScript everywhere. These techniques still exist on-premises and cause most of the "why does my migrated site look broken?" tickets.

#The classic page model

Technique Where Notes
Custom master page _catalogs/masterpage Full control; must be re-applied/updated on every version upgrade
Page layouts Master page gallery, tied to content types Publishing feature required
Design Manager (2013) Convert HTML designs to master pages Removed from SharePoint 2019 modern experiences; deprecated
Composed looks / themes Site settings → Change the look Lightweight; colour palette (.spcolor) + font scheme
Alternate CSS URL Site settings → Master page Quick and dirty overrides
JSLink / CSR Field, view, form web parts Render fields with JavaScript templates (2013+)
Script/Content Editor web part Any page "Inline" JS and HTML; powerful but ungoverned

#JSLink / Client-Side Rendering example

CSR lets you replace how a field renders in views and forms, for example coloured status badges:

status-badge.js (referenced via the field or list view web part JSLink property)JavaScript
(function () {
  var colors = { "Submitted": "#2563eb", "In Review": "#d97706", "Closed": "#059669", "Rejected": "#dc2626" };

  function renderStatus(ctx) {
    var value = ctx.CurrentItem.Status || "";
    var color = colors[value] || "#64748b";
    return "<span style='display:inline-block;padding:2px 10px;border-radius:12px;color:#fff;background:" +
      color + "'>" + SPHttpUtility.HtmlEncode(value) + "</span>";
  }

  SPClientTemplates.TemplateManager.RegisterTemplateOverrides({
    Templates: {
      Fields: {
        "Status": { View: renderStatus, DisplayForm: renderStatus }
      }
    }
  });
})();

Set it with PowerShell or CSOM: $field.JSLink = "~sitecollection/SiteAssets/status-badge.js".

The modern equivalent is JSON, not JavaScript

In SharePoint Online and modern lists in 2019/SE, use column formatting JSON for the same badges, with no script and no deployment. See Column formatting.

#Modernization map

Classic Modern (SPO / SE modern sites)
Custom master page header/footer SPFx Application Customizer (Top/Bottom placeholders)
Brand colours, fonts Tenant themes (Add-SPOTheme) + brand center / site branding
Page layouts Page templates + section layouts + Page Properties web part
JSLink field rendering Column formatting JSON or SPFx Field Customizer
JSLink view rendering View formatting JSON
Script Editor web part SPFx web part (governed, packaged)
Publishing navigation (term-driven) Hub navigation, global navigation, audience targeting

Use the PnP page transformation tooling to convert classic wiki, web part and publishing pages to modern pages. See Classic to modern transformation.

#Interview questions

Q1What is the difference between a master page and a page layout?

A master page defines the shared chrome (header, navigation, footer, placeholders) for all pages in a site. A page layout defines the content area structure of publishing pages: field controls and web part zones bound to a content type. A publishing page = master page + page layout + page content.

Q2What replaced JSLink in modern SharePoint?

Declarative column and view formatting (JSON) for most visual needs, and SPFx field customizers when code is required. JSLink does not run on modern list views.

Q3Why are custom master pages discouraged even on-premises?

Every version upgrade and many cumulative updates change the out-of-the-box master pages. Custom copies drift, break features (ribbon, suite bar, accessibility) and must be retested and rebuilt. Themes, alternate CSS and SPFx-style customizers are far less fragile.
