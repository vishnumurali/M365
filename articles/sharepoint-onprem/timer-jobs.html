Custom Timer Jobs – Scheduling Background Work on the Farm

Build, schedule, deploy and debug SPJobDefinition timer jobs in C#, with lock types, schedules, persisted properties, and the cloud-era replacements based on Azure Functions and scheduled flows.

SharePoint has its own scheduler: the SharePoint Timer Service (OWSTIMER.EXE) runs on every server and executes timer jobs. Out of the box it handles hundreds of jobs (search, workflow, usage, content type hub). You can add your own by inheriting from SPJobDefinition.

Typical custom jobs include nightly reminders for overdue tasks, archiving closed items, syncing a list from an ERP database, and generating reports.

#How timer jobs run

Lock type Behaviour Use for
SPJobLockType.Job Runs on one server per schedule Most business jobs
SPJobLockType.ContentDatabase Runs once per content DB (in parallel) Jobs that scan sites in each DB
SPJobLockType.None Runs on every server where provisioned Server-local work (cleaning a local cache)

#The job class

OverdueReminderJob.csC#
public class OverdueReminderJob : SPJobDefinition
{
    public const string JobName = "Contoso - Overdue Deviation Reminders";

    // Required parameterless constructor (for serialization)
    public OverdueReminderJob() : base() { }

    public OverdueReminderJob(SPWebApplication webApp)
        : base(JobName, webApp, null, SPJobLockType.Job)
    {
        Title = JobName;
    }

    // Persisted settings are stored with the job definition in the config DB
    [Persisted] public string SiteUrl;

    public override void Execute(Guid targetInstanceId)
    {
        using (var site = new SPSite(SiteUrl))
        using (var web = site.OpenWeb())
        {
            var list = web.Lists["Deviations"];
            var q = new SPQuery
            {
                Query = "<Where><And>" +
                        "<Lt><FieldRef Name='DueDate'/><Value Type='DateTime'><Today/></Value></Lt>" +
                        "<Neq><FieldRef Name='Status'/><Value Type='Choice'>Closed</Value></Neq>" +
                        "</And></Where>",
                RowLimit = 2000
            };
            foreach (SPListItem item in list.GetItems(q))
            {
                var owner = new SPFieldUserValue(web, item["Owner"] as string);
                if (owner.User == null || string.IsNullOrEmpty(owner.User.Email)) continue;
                SPUtility.SendEmail(web, false, false, owner.User.Email,
                    $"Overdue deviation: {item.Title}",
                    $"Deviation <b>{item.Title}</b> was due on {item["DueDate"]:d}. <a href='{web.Url}/{item.Url}'>Open it</a>.");
            }
        }
    }
}

#Installing the job with a feature receiver

Timer jobs are usually installed by a WebApplication-scoped feature, so the job definition belongs to that web app:

Feature receiver: create schedule and remove the job on deactivateC#
public override void FeatureActivated(SPFeatureReceiverProperties properties)
{
    var webApp = (SPWebApplication)properties.Feature.Parent;
    DeleteJob(webApp);

    var job = new OverdueReminderJob(webApp)
    {
        SiteUrl = "https://sp.contoso.com/sites/quality",
        Schedule = new SPDailySchedule { BeginHour = 6, BeginMinute = 0, EndHour = 6, EndMinute = 30 }
    };
    job.Update();
}

public override void FeatureDeactivating(SPFeatureReceiverProperties properties)
    => DeleteJob((SPWebApplication)properties.Feature.Parent);

private static void DeleteJob(SPWebApplication webApp)
{
    foreach (var j in webApp.JobDefinitions.Where(j => j.Name == OverdueReminderJob.JobName).ToList())
        j.Delete();
}

Other schedules: SPMinuteSchedule { Interval = 15 }, SPHourlySchedule, SPWeeklySchedule, SPMonthlySchedule, SPOneTimeSchedule.

Restart the timer service after deploying new DLLs

OWSTIMER.EXE caches assemblies. After Update-SPSolution, restart the SharePoint Timer Service on every server (Restart-Service SPTimerV4). Otherwise the old code keeps running, which is the classic "my fix did not deploy" mystery.

#Running, monitoring and debugging

Run now, check historyPowerShell
$job = Get-SPTimerJob | Where-Object Name -eq "Contoso - Overdue Deviation Reminders"
Start-SPTimerJob $job
$job.HistoryEntries | Select-Object -First 5 StartTime, EndTime, Status, ErrorMessage

Debug by attaching Visual Studio to OWSTIMER.EXE on the server where the job runs (not w3wp), set breakpoints in Execute, then use Start-SPTimerJob.

#Cloud replacements

Timer job pattern Replacement
Nightly reminders or emails Scheduled Power Automate flow (Recurrence → Get items with OData filter → Send email)
Heavy batch processing Azure Function timer trigger (CRON) with an app-only Entra app (Sites.Selected)
Sync from ERP Azure Function or Data Factory / Dataflows → Dataverse or list
Per-site maintenance Azure Function + PnP Core SDK iterating sites from Graph
Azure Function timer trigger equivalent (isolated worker)C#
[Function("OverdueReminders")]
public async Task Run([TimerTrigger("0 0 6 * * *")] TimerInfo timer)   // 06:00 daily (UTC by default)
{
    // Graph app-only: query items with an OData filter on an indexed DueDate column
    var items = await _graph.Sites[_siteId].Lists["Deviations"].Items.GetAsync(r =>
    {
        r.QueryParameters.Expand = new[] { "fields($select=Title,DueDate,Status,OwnerLookupId)" };
        r.QueryParameters.Filter = $"fields/DueDate lt '{DateTime.UtcNow:yyyy-MM-dd}' and fields/Status ne 'Closed'";
        r.Headers.Add("Prefer", "HonorNonIndexedQueriesWarningMayFailRandomly");
    });
    // ...send mail via Graph /users/{id}/sendMail
}

#Interview questions

Q1What is the difference between SPJobLockType.Job, ContentDatabase and None?

Job runs the job on one server per schedule. ContentDatabase runs once for each content database, possibly in parallel, and targetInstanceId identifies the DB. None runs on every server where the job is provisioned.

Q2Your updated timer job code is not running after deployment. Why?

OWSTIMER.EXE loads assemblies once and keeps them in memory. Restart the SharePoint Timer Service (SPTimerV4) on all servers after deploying the new WSP.

Q3How do you store configuration for a timer job?

Use fields marked with [Persisted] on the job definition (serialized into the config DB), or a hierarchical object store, a property bag or a configuration list read at runtime.
