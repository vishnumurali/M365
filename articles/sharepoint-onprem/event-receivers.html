Event Receivers (Classic) – Synchronous & Asynchronous Handlers in C#

Everything about full-trust event receivers, covering receiver base classes, -ing vs -ed events, before and after properties, cancelling with errors, preventing recursion, registration in XML and code, the JavaScript-side equivalents, and the modern replacements.

An event receiver is a class whose methods SharePoint calls when something happens: an item is added, a file is checked in, a list is deleted, a site is created. Classic receivers are full-trust C# code deployed in a farm solution. They run inside SharePoint (the w3wp worker process for synchronous events, and usually the same process on a background thread for asynchronous ones).

#What a receiver can listen to

#Synchronous (-ing) vs asynchronous (-ed)

-ing (synchronous) -ed (asynchronous)
Timing Before commit After commit
Can cancel ✅ properties.Status = SPEventReceiverStatus.CancelWithError ❌
ListItem available Adding: ❌ null; Updating: ✅ (old values) ✅
AfterProperties New values (internal names) Values as saved
Runs on Request thread (user waits) Background thread (can be made sync with <Synchronization>)

#A complete receiver

DeviationReceiver.csC#
public class DeviationReceiver : SPItemEventReceiver
{
    // 1) Validate before saving
    public override void ItemAdding(SPItemEventProperties properties)
    {
        string title = properties.AfterProperties["Title"] as string;
        if (string.IsNullOrWhiteSpace(title) || title.Trim().Length < 5)
        {
            properties.Status = SPEventReceiverStatus.CancelWithError;
            properties.ErrorMessage = "Title must have at least 5 characters.";
            return;
        }
        // 2) Stamp values before insert (no extra update, no recursion)
        properties.AfterProperties["Status"] = "Submitted";
    }

    // 3) Block edits to closed items
    public override void ItemUpdating(SPItemEventProperties properties)
    {
        var current = properties.ListItem?["Status"] as string;      // BEFORE values
        var incoming = properties.AfterProperties["Status"] as string; // may be null if not changed
        if (current == "Closed" && incoming != "Reopened")
        {
            properties.Status = SPEventReceiverStatus.CancelWithError;
            properties.ErrorMessage = "Closed deviations are read-only. Set status to 'Reopened' first.";
        }
    }

    // 4) After insert: compute a reference number using the new ID
    public override void ItemAdded(SPItemEventProperties properties)
    {
        SPListItem item = properties.ListItem;
        EventFiringEnabled = false;                 // prevent ItemUpdated recursion
        try
        {
            item["ReferenceNo"] = $"DEV-{DateTime.UtcNow:yyyy}-{item.ID:D5}";
            item.SystemUpdate(false);               // no new version, keeps Editor
        }
        finally
        {
            EventFiringEnabled = true;
        }
    }
}
Elements.xml – bind to all lists of template 100 in the webXML
<Elements xmlns="http://schemas.microsoft.com/sharepoint/">
  <Receivers ListTemplateId="100" Scope="Web">
    <Receiver>
      <Name>DeviationItemAdding</Name>
      <Type>ItemAdding</Type>
      <Assembly>$SharePoint.Project.AssemblyFullName$</Assembly>
      <Class>Contoso.Quality.DeviationReceiver</Class>
      <SequenceNumber>10000</SequenceNumber>
    </Receiver>
    <Receiver>
      <Name>DeviationItemAdded</Name>
      <Type>ItemAdded</Type>
      <Assembly>$SharePoint.Project.AssemblyFullName$</Assembly>
      <Class>Contoso.Quality.DeviationReceiver</Class>
      <SequenceNumber>10000</SequenceNumber>
      <Synchronization>Synchronous</Synchronization>  <!-- run -ed event on the request thread -->
    </Receiver>
  </Receivers>
</Elements>

#Binding to one specific list in code

ListTemplateId binds to every list of that template. To bind to one list, register in a feature receiver:

Bind a receiver to a single listC#
SPList list = web.Lists["Deviations"];
string asm = typeof(DeviationReceiver).Assembly.FullName;
string cls = typeof(DeviationReceiver).FullName;
if (!list.EventReceivers.Cast<SPEventReceiverDefinition>().Any(r => r.Class == cls && r.Type == SPEventReceiverType.ItemAdding))
{
    list.EventReceivers.Add(SPEventReceiverType.ItemAdding, asm, cls);
    list.EventReceivers.Add(SPEventReceiverType.ItemAdded, asm, cls);
}

#The JavaScript side

Client-side code cannot host a classic receiver, but there are three JavaScript patterns you will meet in the same projects:

Classic forms: PreSaveAction validation (2010–2019 list forms)JavaScript
// Add via a Script Editor web part on NewForm.aspx / EditForm.aspx, or via JSLink.
// SharePoint calls PreSaveAction() before submitting; return false to cancel.
function PreSaveAction() {
  var title = document.querySelector("input[id^='Title_']").value.trim();
  if (title.length < 5) {
    alert("Title must have at least 5 characters.");
    return false;
  }
  return true;
}
JSOM: register a REMOTE event receiver on a listJavaScript
// Runs in a SharePoint page (SP.js loaded). Registers an RER endpoint for ItemAdded.
var ctx = SP.ClientContext.get_current();
var list = ctx.get_web().get_lists().getByTitle("Deviations");
var info = new SP.EventReceiverDefinitionCreationInformation();
info.set_receiverName("DeviationItemAdded");
info.set_eventType(SP.EventReceiverType.itemAdded);
info.set_receiverUrl("https://apps.contoso.com/Services/DeviationReceiver.svc");
info.set_sequenceNumber(1000);
info.set_synchronization(SP.EventReceiverSynchronization.asynchronous);
list.get_eventReceivers().add(info);
ctx.executeQueryAsync(
  function () { console.log("Remote receiver registered"); },
  function (s, a) { console.error(a.get_message()); });
REST: list the receivers registered on a listJavaScript
const r = await fetch(`${_spPageContextInfo.webAbsoluteUrl}/_api/web/lists/getbytitle('Deviations')/EventReceivers`,
  { headers: { Accept: "application/json;odata=nometadata" } });
const { value } = await r.json();
console.table(value.map(x => ({ name: x.ReceiverName, type: x.EventType, cls: x.ReceiverClass, url: x.ReceiverUrl })));

#Pitfalls and best practices

  • Recursion: set EventFiringEnabled = false around updates in -ed events and restore it in finally.
  • Internal names: AfterProperties uses internal field names (Due_x0020_Date, not "Due Date").
  • Null ListItem in ItemAdding: the item does not exist yet, so use AfterProperties.
  • Documents vs items: for library uploads, ItemAdding fires before the metadata is set (Office clients set columns in a later update), so validate document metadata in ItemUpdating or ItemCheckingIn as well.
  • Long-running work: never block a sync receiver with web service calls. Queue the work (list, timer job, Service Bus).
  • Bulk operations: imports of 100,000 items call your receiver 100,000 times, so keep receivers lightweight or disable them during migration.
  • Error handling: an unhandled exception in a sync receiver shows the user an error. In async receivers it is only logged to ULS. Log with SPDiagnosticsService.

#Interview questions

Q1Why is properties.ListItem null in ItemAdding?

Because the item has not been created yet. The synchronous event runs before the insert. Use properties.AfterProperties (internal field names) to read or modify incoming values.

Q2How do you stop an ItemUpdated receiver from triggering itself?

Set this.EventFiringEnabled = false before updating the item, use SystemUpdate(false) where appropriate, and restore EventFiringEnabled = true in a finally block.

Q3How can you make an "-ed" event run synchronously, and why would you?

Set <Synchronization>Synchronous</Synchronization> in the receiver registration, or SPEventReceiverSynchronization.Synchronous in code. The -ed event then runs on the request thread before the response returns. This is useful when the next page load must already see the computed values (for example a reference number), at the cost of slower saves.

Q4What is the difference between registering with ListTemplateId and binding to a list in code?

ListTemplateId in Elements.xml binds the receiver to all lists of that template in the feature's scope. Code (list.EventReceivers.Add) binds to one specific list. It is usually run from a feature receiver.
