SharePoint & Microsoft 365 Timeline, 2001–2026

Every major release, platform shift and retirement from SharePoint Portal Server 2001 to the agents era, in one interactive timeline with context on why each change happened.

SharePoint started as a document-management portal on top of Exchange storage. Twenty-five years later it is the content backbone of Microsoft 365: it stores Teams files, feeds Copilot, and hosts low-code apps and agents. Knowing that path explains why so many technologies on this site exist, and why some are being retired.

25 yearsfrom Portal Server 2001 to 2026
8 server versions2001, 2003, 2007, 2010, 2013, 2016, 2019, SE
4 dev modelsFarm → Sandbox → Add-ins → SPFx
3 workflow enginesWF 3.5 (2010), Workflow Manager (2013), Power Automate

#The four eras at a glance

#Year by year

  1. 2001Server

    SharePoint Portal Server 2001

    Built on the Exchange Web Storage System. It offered document management, search and digital dashboards with "web parts". SharePoint Team Services shipped with FrontPage 2002 for team collaboration.

  2. 2003Server

    Windows SharePoint Services 2.0 & SharePoint Portal Server 2003

    A rewrite on SQL Server + ASP.NET. WSS became a free Windows Server component, and the site/list/library model we still use today appeared.

  3. 2003Forms

    InfoPath 2003

    An XML-based electronic forms designer. Its forms became the default way to build complex SharePoint forms for the next decade.

  4. 2006–07Server

    MOSS 2007 & WSS 3.0

    Content types, site columns, Features & Solutions (WSP), Workflow Foundation workflows, InfoPath Forms Services, Excel Services, the BDC, publishing (CMS merged in), and recycle bins.

  5. 2007Tools

    SharePoint Designer 2007

    Replaced FrontPage for SharePoint. Power users could build no-code declarative workflows and data views.

  6. 2007–08Ecosystem

    Nintex Workflow 2007

    A drag-and-drop browser workflow designer for MOSS. Nintex became the de-facto enterprise workflow add-on for SharePoint.

  7. 2008Cloud

    BPOS

    Microsoft's Business Productivity Online Suite offered hosted SharePoint, the ancestor of SharePoint Online.

  8. 2010Server

    SharePoint 2010

    Ribbon UI, the service application architecture, sandboxed solutions, the Client Object Model (CSOM/JSOM), ListData.svc REST, BCS, Managed Metadata, claims authentication and reusable SPD workflows.

  9. 2011Cloud

    Office 365

    SharePoint Online (2010-based) launched as part of Office 365, beginning the move to multi-tenant SharePoint.

  10. 2012–13Server

    SharePoint 2013

    The app (add-in) model (SharePoint-hosted and provider-hosted), OAuth, the /_api REST endpoint, Workflow Manager (WF 4.5), integrated FAST search, Design Manager, Distributed Cache and remote event receivers.

  11. 2014Cloud

    Sandboxed code deprecated

    Code-based sandboxed solutions were deprecated in SharePoint Online, which pushed developers to add-ins and JavaScript.

  12. 2015Dev

    Microsoft Graph

    The unified graph.microsoft.com endpoint reached general availability. It became the strategic API across Microsoft 365.

  13. 2016Server

    SharePoint Server 2016

    MinRole topologies, zero-downtime patching, cloud hybrid search, and larger file limits. At "The Future of SharePoint" event Microsoft previewed the SharePoint Framework.

  14. 2016Cloud

    Modern experiences, PowerApps & Microsoft Flow

    Modern document libraries, lists, team sites and pages rolled out. PowerApps and Microsoft Flow reached general availability.

  15. 2017Dev

    SharePoint Framework (SPFx) GA

    Client-side web parts (and later extensions) built with TypeScript and React became the supported customization model. Communication sites and Microsoft Teams launched.

  16. 2018Server

    Hub sites & SharePoint Server 2019

    Hub sites brought the flat information architecture. SharePoint 2019 brought modern sites, lists and SPFx to on-premises.

  17. 2019Low-code

    Power Platform & Power Automate

    Microsoft Flow was renamed Power Automate and the Power Platform brand unified PowerApps, Power Automate, Power BI and Power Virtual Agents.

  18. 2020Cloud

    Dataverse, Microsoft Lists, 2010 workflows retired

    The Common Data Service was renamed Microsoft Dataverse. Microsoft Lists launched. SharePoint 2010 workflows were turned off in SharePoint Online. Nintex acquired K2.

  19. 2021Server

    SharePoint Server Subscription Edition

    Moved on-premises to a continuous, feature-update model with modern authentication (OIDC) and TLS 1.3. Microsoft Viva launched. SharePoint 2010 reached end of support.

  20. 2022Ecosystem

    Nintex Automation Cloud

    Nintex Workflow Cloud was rebranded as Nintex Automation Cloud (NAC), the target for Nintex for Office 365 migrations.

  21. 2023AI

    Copilot, SharePoint Premium, Copilot Studio

    Microsoft 365 Copilot reached general availability for enterprises. Syntex evolved into SharePoint Premium. Power Virtual Agents became Copilot Studio. Microsoft announced the retirement of SharePoint Add-ins. SharePoint 2013 reached end of support.

  22. 2024AI

    SharePoint Embedded & agents

    SharePoint Embedded (headless containers for ISV and LOB apps) reached general availability. SharePoint agents arrived. SharePoint 2013 workflows and Azure ACS were disabled for new tenants. PnP PowerShell moved to customer-owned Entra app registrations.

  23. 2025Cloud

    Clean-up year

    Organizations raced to replace add-ins, ACS-based apps, 2013 workflows and InfoPath forms ahead of the 2026 deadlines, and adopted Copilot readiness controls such as SharePoint Advanced Management.

  24. 2026Milestone

    The big retirement year

    2 Apr 2026: SharePoint Add-ins, Azure ACS for SharePoint Online and SharePoint 2013 workflows were retired in SPO. 14 Jul 2026: SharePoint Server 2016 and 2019, SharePoint Designer 2013 and InfoPath 2013 reached end of support. Subscription Edition is now the only supported on-premises version.

Important

The retirement and end-of-support dates above reflect Microsoft announcements as of 2026. Lifecycle dates occasionally change, so always confirm on the official Microsoft Lifecycle and Message Center pages before you commit a project plan.

#How the development model evolved

The direction never changed: move custom code out of the SharePoint process. First code moved into a sandbox, then into remote web servers, then into the browser (SPFx) and serverless cloud services. Each step made SharePoint more stable and easier to upgrade, and it is why Microsoft could move SharePoint Online to continuous updates.

#What this means for you in 2026

  • Running SharePoint 2016 or 2019? You are out of support. Plan an upgrade to Subscription Edition or a migration to SharePoint Online. See Upgrade paths and On-prem to Online migration.
  • Still have add-ins or ACS apps in SPO? They have stopped working. Rebuild them as SPFx + Entra ID apps. See Provider-hosted add-in challenges & migration.
  • 2013 workflows or InfoPath forms? Move them to Power Automate, Nintex Automation Cloud or Power Apps. See InfoPath retirement.
  • Getting ready for Copilot? Fix oversharing first. See Content readiness for Copilot.

#Test yourself

Q1Which SharePoint version introduced the add-in (app) model and the /_api REST endpoint?

SharePoint 2013 (RTM October 2012). It also introduced Workflow Manager and remote event receivers.

Q2Why did Microsoft deprecate farm and sandboxed solutions for SharePoint Online?

Code running inside the SharePoint process could destabilize shared, multi-tenant infrastructure and block upgrades. Moving code to remote hosts (add-ins), then to the browser (SPFx) and to serverless services, let SharePoint Online update continuously and safely.

Q3Which on-premises SharePoint version is still supported after July 2026?

SharePoint Server Subscription Edition. SharePoint 2016 and 2019 reached end of extended support on 14 July 2026.
