Graph Batching, Delta Queries and Graph Explorer – Efficient Data Access Patterns

Reduce round trips with JSON $batch (20 requests, dependencies), sync changes with delta queries for drives, lists, users and groups, and prototype quickly with Graph Explorer, with code and pitfalls.

#JSON batching

Up to 20 requests in one call, with dependenciesHTTP
POST https://graph.microsoft.com/v1.0/$batch
Content-Type: application/json

{
  "requests": [
    { "id": "1", "method": "GET", "url": "/sites/contoso.sharepoint.com:/sites/quality?$select=id" },
    { "id": "2", "method": "GET", "url": "/me/memberOf?$select=displayName&$top=50" },
    { "id": "3", "dependsOn": ["1"], "method": "POST", "url": "/sites/{site-id}/lists/{list-id}/items",
      "headers": { "Content-Type": "application/json" }, "body": { "fields": { "Title": "Batched" } } }
  ]
}

Each response carries its own status. Check every item, retry individual 429s, and keep in mind a batch is not transactional.

#Delta queries

Resource Delta endpoint
Files in a library /drives/{drive-id}/root/delta
List items /sites/{site-id}/lists/{list-id}/items/delta
Users / groups /users/delta, /groups/delta
Calendar events /me/calendarView/delta
Drive delta sync loop (Graph JS SDK)TypeScript
let url = savedDeltaLink ?? `/drives/${driveId}/root/delta?$select=id,name,file,deleted,lastModifiedDateTime,parentReference`;
do {
  const page = await client.api(url).get();
  for (const item of page.value) item.deleted ? await removeFromIndex(item.id) : await upsertIndex(item);
  url = page['@odata.nextLink'] ?? null;
  if (page['@odata.deltaLink']) savedDeltaLink = page['@odata.deltaLink'];
} while (url);
await persist(savedDeltaLink);
Prototype in Graph Explorer

Graph Explorer lets you sign in, run queries, consent to scopes, view code snippets (C#, JS, PowerShell) and see required permissions, which is the fastest way to design calls before coding.

#Interview questions

Q1What's the limit and behaviour of Graph JSON batching?

Up to 20 requests per batch, executed in any order unless you specify dependsOn. Each request returns its own status code (some can fail or be throttled while others succeed), and batches are not atomic.

Q2How does a delta query work?

The first call returns all items (paged) and ends with a @odata.deltaLink. Calling that link later returns only items changed or deleted since, plus a new deltaLink, which makes efficient incremental sync possible.
