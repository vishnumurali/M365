#Token anatomy (decoded JWT)

Access token claims you check in APIsJSON
{
  "aud": "api://deviation-api",            // audience = your API
  "iss": "https://login.microsoftonline.com/<tenant-id>/v2.0",
  "tid": "<tenant-id>",
  "oid": "<user-object-id>",
  "scp": "user_impersonation",             // delegated scopes (space-separated)
  "roles": ["Deviations.ReadWrite"],       // app roles (application or assigned to user)
  "azp": "<client app id>",                // calling app
  "exp": 1791460489
}

#Common errors

Error Meaning
AADSTS65001 Consent missing for the requested scope
AADSTS50011 Redirect URI mismatch
AADSTS700016 App not found in tenant (wrong client ID or tenant)
AADSTS7000215 Invalid client secret (expired or wrong)
401 from API with valid token Wrong aud (token requested for a different resource)
403 from Graph Scope or role missing, or the user lacks access

#Interview questions

Q1When do you use the on-behalf-of flow?

When a middle-tier API receives a user's token (e.g. from SPFx) and must call another API (Graph, SharePoint) as that user. It exchanges the incoming token for a new token for the downstream resource, preserving the user's identity and permissions.

Q2What is the difference between scp and roles claims?

scp lists delegated scopes granted to the app for the signed-in user. roles lists app roles assigned to the application (application permissions) or to the user/group for the API. APIs authorize based on the appropriate claim.
