What are Dataflows? Standard vs Analytical Dataflows, Power Query Online and Dataflow Gen2

Dataflows explained, covering Power Query Online as the engine, standard dataflows that load into Dataverse, analytical dataflows that land in a data lake for Power BI, Dataflow Gen2 in Microsoft Fabric, refresh, gateways and typical use cases.

A dataflow is a cloud ETL (extract, transform, load) job built with Power Query Online, the same query engine as Excel and Power BI. It connects to sources (SharePoint, SQL, Excel, OData, files, Salesforce…), shapes the data, and loads it into a destination on a schedule.

#Three flavours

Standard Analytical Dataflow Gen2
Built in Power Apps maker portal Power BI service Microsoft Fabric
Destination Dataverse Data lake (Power BI storage / ADLS) Lakehouse, Warehouse, SQL, more
Typical use App data migration and sync Reusable BI data prep Enterprise data engineering
Licence Power Apps / Power Automate Power BI Pro/Premium Fabric capacity

#A typical standard dataflow

#When to use dataflows

  • Migrate list data into Dataverse when an app outgrows SharePoint.
  • Keep reference data (products, cost centres) in Dataverse synchronized from ERP exports or SQL.
  • Shared, governed data preparation for Power BI.
  • Replace hand-written ETL scripts for simple to moderate transformations.

#Interview questions

Q1What is the difference between a standard and an analytical dataflow?

A standard dataflow loads its output into Dataverse tables (for apps). An analytical dataflow stores output in a data lake (Power BI or your ADLS Gen2) as reusable entities for Power BI datasets and analytics.

Q2Which engine do dataflows use?

Power Query Online, the same M-language engine as Power BI Desktop and Excel's Get & Transform, running in the cloud with refresh scheduling and gateway support.
