Tables & Columns in Dataverse – Types, Choices, Keys and Naming Conventions

Design Dataverse tables properly, covering standard/activity/virtual/elastic table types, ownership (user/team vs organization), every column type with tips, global vs local choices, alternate keys, autonumber and naming conventions.

#Table types and ownership

Table type Use
Standard Most business data (Deviation, Product)
Activity Time-based interactions (email, task, appointment); appear in timelines
Virtual Data stays in an external system, surfaced as a table
Elastic Massive volume, NoSQL-backed (Cosmos DB) for logs/IoT-like data
Ownership Meaning Choose when
User or team Each row has an Owner; security can be user/BU-scoped Data belongs to people or teams
Organization No owner; access is all-or-nothing per role Reference data (Plants, Categories)
Ownership can&#39;t be changed later

Decide ownership when creating the table. Switching from organization to user-owned later means recreating the table.

#Column types cheat sheet

Type Notes
Text / Multiline text / Rich text Max lengths configurable; email, URL, phone formats
Whole number / Decimal / Float / Currency Currency adds base-currency conversion fields
Date and time / Date only Behaviour: User local, Date only, Time-zone independent (set carefully)
Choice / Choices Single or multi-select option sets; local or global (reusable)
Yes/No Two options with labels
Lookup N:1 relationship to another table; Customer and Owner are polymorphic
File / Image Stored in file capacity (blob)
Formula Power Fx expression computed on read
Calculated / Rollup Classic calculated and aggregated columns
Autonumber DEV-{SEQNUM:5}-{DATETIMEUTC:yyyy} style numbering

#Alternate keys

An alternate key (one or more columns) uniquely identifies rows besides the GUID. It is essential for integrations and upserts:

Upsert by alternate key (Web API)HTTP
PATCH [org]/api/data/v9.2/cr8a1_products(cr8a1_sku='SKU-10042')
Content-Type: application/json

{ "cr8a1_name": "Pressure sensor X2", "cr8a1_unitcost": 42.5 }

#Naming conventions

  • Publisher prefix for every custom component (ci_ for Contoso Inventory), set in the publisher before creating anything.
  • Singular table names (Deviation), plural display collection names (Deviations).
  • Schema names in PascalCase (ci_DueDate); logical names are lowercase automatically.
  • Prefer global choices for values shared across tables (Severity, Status).

#Interview questions

Q1What is the difference between user-owned and organization-owned tables?

User- or team-owned tables have an Owner column, and security roles can grant access at user, business unit, parent-child BU or organization depth. Organization-owned tables have no owner, so access is either granted for all rows or none. They suit reference data.

Q2Why define alternate keys?

To identify rows by business keys (SKU, employee number) for integrations, enabling upsert and lookup binding without knowing GUIDs, and to enforce uniqueness.

Q3What should you watch out for with Date and time columns?

The behaviour setting: User local converts between time zones, Date only stores a date without time-zone shifts, and Time-zone independent stores the literal value. A wrong behaviour causes off-by-one-day bugs across time zones.
