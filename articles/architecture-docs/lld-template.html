The Low-Level Design (LLD) is the developer's blueprint. Someone who did not attend design meetings should be able to build or maintain the solution from it. It turns HLD components into exact schemas, screens, logic, flows and APIs.

#LLD template

#Worked example (DMS) – excerpts

#1 · Naming conventions

Item Convention Example
Publisher prefix dms_ dms_deviation
Canvas controls type prefix galDeviations, frmDeviation, btnSubmit
Flows DMS – [Area] – [Trigger] – [Purpose] DMS – Approval – Row modified – Manager approval
Environment variables dms_[Name] dms_EvidenceSiteUrl

#2 · Data model: dms_deviation

Column Schema name Type Req. Default / rule Index/notes
Reference dms_reference Autonumber ✓ DEV-{DATETIMEUTC:yyyy}-{SEQNUM:5} Alternate key
Title dms_name Text 200 ✓ ≥ 5 chars (form) Primary name
Plant dms_plant Lookup → dms_plant ✓ From user profile Owning BU set by plug-in
Area dms_area Choice (global) ✓ — Production/Warehouse/Lab
Severity dms_severity Choice QA — Minor/Major/Critical
Status statuscode Status reason ✓ Submitted Draft, Submitted, Pending approval, Investigation, CAPA, Verification, Closed, Rejected
Due date dms_duedate Date only Cond. Critical ≤ 7 days Business rule
Owner ownerid Owner ✓ QA assigns
Days open dms_daysopen Formula — DateDiff('Created On', UTCNow(), TimeUnit.Days)

#4 · Screen spec: scrReport

Control Property Formula / value
txtTitle OnChange UpdateContext({locTitleValid: Len(Trim(Self.Text)) >= 5})
ddArea Items Choices(Deviations.Area)
dpDue Visible ddSeverity.Selected.Value in ["Major","Critical"]
btnSubmit DisplayMode If(locTitleValid && !IsBlank(ddArea.Selected), DisplayMode.Edit, DisplayMode.Disabled)
btnSubmit OnSelect IfError(Patch(Deviations, Defaults(Deviations), {...}), Notify(FirstError.Message, NotificationType.Error), Navigate(scrThanks))

#6 · Flow design: Manager approval

Step Action Details
1 Trigger Dataverse When a row is modified, table dms_deviation, select columns statuscode, filter statuscode eq 100000002 (Pending approval)
2 Get manager Lookup Area-Manager mapping table by dms_area + dms_plant
3 Approval Start and wait for an approval, Approve/Reject, timeout P2D
4a On approve Update row: status = Investigation; create dms_approval record
4b On reject Update row: status = Rejected; notify reporter with comments
4c On timeout Escalate: notify plant head; restart approval assigned to plant head
E Error scope Catch → log to dms_errorlog, Teams alert to support channel, terminate Failed

#7 · API contract (Azure Function: monthly report)

POST /api/reports/monthlyYAML
request:
  headers: { Authorization: "Bearer <token aud=api://dms-reports, role=Reports.Generate>" }
  body: { plantCode: "BLR", month: "2026-09" }
responses:
  202: { jobId: "c0ffee…", statusUrl: "/api/reports/jobs/c0ffee…" }
  400: { error: "Invalid month format (yyyy-MM)" }
  403: { error: "Missing role Reports.Generate" }

#Interview questions

Q1What level of detail should an LLD have?

Enough for a developer who wasn't in the design discussions to build and maintain the solution: exact schemas (names, types, rules), security mappings, screen and control logic, step-by-step flow designs with error handling, API contracts, configuration values per environment and naming conventions.

Q2How do you keep the LLD up to date in Agile projects?

Write it per feature just in time (sprint by sprint), store it next to the code (wiki or Git), review it as part of the definition of done, and generate parts automatically where possible (schema exports, solution documentation tools).
