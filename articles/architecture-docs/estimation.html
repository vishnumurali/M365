Estimating SharePoint, SPFx and Power Platform Work – Techniques and Reference Numbers

How to estimate Microsoft 365 projects credibly, covering work breakdown, complexity-based sizing for lists, flows, apps, web parts and migrations, three-point estimates, contingency, non-development effort (testing, documentation, deployment, hypercare), and a sample estimate sheet.

#Approach

#Indicative baselines (calibrate with your own history)

Component Simple Medium Complex
SharePoint list/library with views & formatting 2–4 h 4–8 h 1–2 d
Power Automate flow 0.5–1 d 2–3 d 5–8 d (state machine, integrations)
Canvas app screen 0.5–1 d 1–2 d 3–5 d
Model-driven table + forms/views 0.5 d 1–2 d 3 d
SPFx web part 2–3 d 5–8 d 10–15 d
SPFx extension 1–2 d 3–5 d 8 d
Azure Function API 1–2 d 3–5 d 8–10 d
InfoPath form conversion 1–2 d 3–5 d 8–15 d
Workflow migration (SPD/Nintex) 0.5–1 d 2–4 d 5–10 d
Site migration (ShareGate, per site) 1–2 h 0.5–1 d 2–5 d (restructure, issues)

#Non-development effort (typical share of build)

Activity % of build
Requirements & design (BRD, HLD, LLD) 15–20%
Testing (system + UAT support) 25–35%
Documentation & KT (SUD) 5–10%
Deployment & ALM setup 5–10%
Project management 10–15%
Hypercare 5–10%
Estimate risks explicitly

List the assumptions (licences available, data quality, SME availability, no premium connectors) in the estimate. When an assumption breaks, you have a basis for a change request.

#Interview questions

Q1How would you estimate a Power Platform project quickly but defensibly?

Break it into components (lists/tables, apps and screens, flows, integrations, reports), classify complexity, apply calibrated baselines with three-point estimates, add non-development activities (design, testing, documentation, deployment, PM, hypercare) and contingency based on risks, and document all assumptions.

Q2What's commonly forgotten in Microsoft 365 estimates?

Testing with real roles and permissions, data migration and cleansing, licensing and approval lead times, environment and ALM setup, documentation and KT, training and change management, and hypercare after go-live.
