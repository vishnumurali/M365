Design an inventory solution end to end, covering requirements, data model (products, warehouses, stock levels, movements), transactional stock updates with a plug-in, a barcode-scanning offline canvas app, a model-driven back office, reorder automation, ERP sync via Service Bus, and reporting.

A composite case

Based on common patterns in inventory projects on Power Platform. Details are illustrative.

#Goals

  • Real-time stock per warehouse and bin, with accurate movements (receipts, issues, transfers).
  • Mobile scanning in warehouses with poor connectivity.
  • Automatic reorder alerts and purchase requests.
  • Sync stock with the ERP nightly and on demand.

#Architecture

#Why a plug-in for stock updates?

Stock levels must change atomically with movements. If two operators issue the last item simultaneously, a flow (asynchronous) could let both succeed. A synchronous plug-in in the same transaction validates availability and updates the stock level, or rolls back.

Post-operation plug-in (simplified)C#
var mv = (Entity)ctx.InputParameters["Target"];
int qty = mv.GetAttributeValue<int>("ci_quantity");
var type = mv.GetAttributeValue<OptionSetValue>("ci_type").Value;   // 1 receipt, 2 issue, 3 transfer
var level = GetStockLevel(svc, mv.GetAttributeValue<EntityReference>("ci_product"), mv.GetAttributeValue<EntityReference>("ci_frombin"));
int current = level.GetAttributeValue<int>("ci_onhand");
if (type == 2 && current < qty) throw new InvalidPluginExecutionException($"Only {current} available.");
level["ci_onhand"] = type == 1 ? current + qty : current - qty;
svc.Update(level);            // same transaction as the movement

#Results

99.2%inventory accuracy (cycle counts)
−35%stock-outs in 4 months
2 minaverage receipt processing (from 9)

#Interview questions

Q1How do you prevent negative stock when many users issue items at the same time?

Process stock updates synchronously in the same transaction as the movement (a Dataverse plug-in or a custom API), validating availability before committing. Asynchronous flows can't guarantee consistency under concurrency.

Q2How would you support scanning in warehouses with poor connectivity?

Use a canvas app with the barcode scanner control and the Dataverse offline profile (scoped to the user's warehouse), sync when connected, and design conflict handling for movements recorded offline.
