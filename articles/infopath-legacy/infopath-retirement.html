InfoPath Retirement (2026) – What Changes and Your Migration Options

What the InfoPath 2013 end of support and the InfoPath Forms Services retirement in SharePoint Online mean, how to find every form, a decision matrix for Power Apps, list form formatting, Nintex/NAC, SPFx form customizer and Microsoft Forms, and a phased migration plan.

Microsoft announced in 2014 that InfoPath 2013 would be the last version. In 2026, InfoPath 2013 reached end of support and InfoPath Forms Services in SharePoint Online is being retired. Forms that still depend on it must move to a modern platform.

#Step 3 · Plan the data

  • List forms: data is already in columns, so the new form points to the same list.
  • Form libraries (XML): extract data from XML files (promoted and non-promoted fields) into a list or Dataverse table, with repeating tables as child lists. Keep the original XML/PDF for records if required.
Extract fields from InfoPath XML files (PnP PowerShell sketch)PowerShell
$items = Get-PnPListItem -List "Purchase Requests" -PageSize 500
foreach ($i in $items) {
  $xml = [xml](Get-PnPFile -Url $i["FileRef"] -AsString)
  $ns = New-Object System.Xml.XmlNamespaceManager($xml.NameTable)
  $ns.AddNamespace("my", $xml.DocumentElement.NamespaceURI)
  $req = Add-PnPListItem -List "PR Requests" -Values @{
    Title = $xml.SelectSingleNode("//my:RequestId", $ns).InnerText
    Department = $xml.SelectSingleNode("//my:Department", $ns).InnerText
  }
  foreach ($line in $xml.SelectNodes("//my:Items/my:Item", $ns)) {
    Add-PnPListItem -List "PR Lines" -Values @{
      RequestId = $req.Id; Product = $line.SelectSingleNode("my:Product", $ns).InnerText
      Qty = [int]$line.SelectSingleNode("my:Qty", $ns).InnerText
    } | Out-Null
  }
}

#Step 4 · Phased plan

  1. Retire unused forms (confirm with owners).
  2. Migrate simple list forms quickly (formatting or Power Apps list forms).
  3. Rebuild critical complex forms with proper data models and workflows.
  4. Convert historical XML data where needed, and archive the rest read-only.
  5. Train users, run in parallel briefly, then disable the InfoPath versions.

See InfoPath to Power Apps mapping.

#Interview questions

Q1How would you plan an InfoPath migration for 300 forms?

Inventory with the Microsoft 365 Assessment tool (or PowerShell on-prem), classify by usage and complexity, retire unused forms, pick a target per category (formatting, Power Apps, NAC, SPFx), redesign data for form libraries (XML to lists or Dataverse, repeating tables to child lists), migrate in waves by business area, and archive original XML where records rules require it.

Q2What makes form-library InfoPath forms harder to migrate than list forms?

Their data is stored as XML documents, often with non-promoted fields and repeating sections. You must design a relational target (parent and child lists or tables), extract and transform the XML, and rebuild views and rules, not just recreate a form.
