InfoPath Data Connections – SharePoint Lists, Web Services, SQL and UDCX Files

How InfoPath forms retrieve and submit data, covering receive and submit connections, SharePoint list lookups, SOAP and REST web services, SQL, the data connection library and UDCX files with authentication, and the cross-domain and admin-approval considerations.

Connection type Notes for migration
SharePoint list (receive) Lookups for dropdowns (Departments, Approvers). Rebuild with Power Apps data sources or NAC data lookup
Web service (receive/submit) Business logic often lives there. Expose via custom connector / Xtension / Azure Function
SQL Server Direct DB access. Move behind an API; never connect forms directly to SQL in the cloud
Submit to library Creates XML files. The target becomes a list item (+ child list) or Dataverse row
Email submit Replace with Power Automate / NAC notifications
UDCX in a data connection library Admin-managed connection files (URL, auth). Document them, because they hide endpoints and credentials
A UDCX file (simplified)XML
<udc:DataSource MajorVersion="2" MinorVersion="0" xmlns:udc="http://schemas.microsoft.com/office/infopath/2006/udc">
  <udc:Name>GetCostCentres</udc:Name>
  <udc:Type MajorVersion="2" MinorVersion="0" Type="WebService">
    <udc:SubType MajorVersion="0" MinorVersion="0" Type=""/>
  </udc:Type>
  <udc:ConnectionInfo Purpose="ReadOnly" AltDataSource="">
    <udc:WsdlUrl>https://erp.contoso.local/CostCentreService.asmx?WSDL</udc:WsdlUrl>
    <udc:SelectCommand><udc:ServiceUrl>https://erp.contoso.local/CostCentreService.asmx</udc:ServiceUrl></udc:SelectCommand>
    <udc:Authentication><udc:SSO AppId="ERPReadOnly" CredentialType="NTLM"/></udc:Authentication>
  </udc:ConnectionInfo>
</udc:DataSource>
Inventory hidden endpoints

UDCX files and web service connections reveal integrations nobody documented. List every endpoint and its owner early in a migration, because those systems need APIs or connectors in the new design.

#Interview questions

Q1What is a UDCX file used for?

A Universal Data Connection file stored in a SharePoint data connection library. It centralizes connection details (URLs, authentication such as Secure Store app IDs) so admins can change endpoints or credentials without republishing forms, and it enables cross-domain connections for browser forms.

Q2How do you replace an InfoPath web service connection in a modern solution?

Expose the service through a secure API (Azure Function, API Management) and consume it via a custom connector (Power Apps/Power Automate) or an Xtension (NAC), handling authentication with Entra ID instead of NTLM/Secure Store.
