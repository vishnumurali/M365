Classic to Modern Transformation – Pages, Sites, Navigation and Customizations in SPO

Modernize classic SharePoint Online (and migrated) sites, covering the Microsoft 365 Assessment tool, page transformation (wiki, web part, publishing pages), web part mapping, groupify, hub association, root site swap, and fixing classic customizations.

VM By Vishnu MuralikrishnanUpdated 8 Oct 2026 · 2 min read Advanced2018–20261 diagram1 code sample2 Q&As

Migrating classic sites "as-is" gives you classic sites in the cloud. Modernization turns them into modern experiences that work with hubs, Viva, mobile and Copilot.

Transform pages in a sitePowerShell
Connect-PnPOnline -Url https://contoso.sharepoint.com/sites/legacy-hr -Interactive -ClientId $clientId

# Wiki and web part pages in Site Pages
Get-PnPListItem -List "Site Pages" | ForEach-Object {
  $name = $_.FieldValues["FileLeafRef"]
  ConvertTo-PnPPage -Identity $name -Overwrite -TakeSourcePageName -CopyPageMetadata -AddPageAcceptBanner
}

# Publishing pages into a target modern site
ConvertTo-PnPPage -Identity "Policies.aspx" -PublishingPage -TargetWebUrl https://contoso.sharepoint.com/sites/hr -Overwrite
Classic web part Modern mapping
Content Editor (HTML) Text web part (or SPFx for scripts)
Content Query / Content Search Highlighted content
List View (XSLT) List / Document library web part
Image viewer Image web part
Script Editor No equivalent, so build SPFx
Summary links Quick links

#Interview questions

Q1What does PnP page transformation do?

It reads a classic page (wiki, web part or publishing), maps its web parts to modern equivalents using a mapping file, recreates the content as a modern client-side page (optionally in another site), and can keep the page name and metadata.

Q2What can't be transformed automatically?

Script Editor and other custom script web parts, custom classic web parts without modern equivalents, and master page or JSLink customizations. These need SPFx, formatting JSON or a redesign.
