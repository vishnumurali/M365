Pre-Migration Assessment – Inventory Scripts, ShareGate Reports, SMAT and the Microsoft 365 Assessment Tool

What to measure before migrating, covering sites and sizes, item counts, long paths, file types, versions, unique permissions, customizations (WSPs, workflows, InfoPath, add-ins), orphaned users, checked-out files, with PowerShell scripts and tool outputs.

You can&#39;t plan what you haven&#39;t measured

Assessment surfaces the 10% of content that causes 90% of migration problems: huge lists, long paths, unique permissions, customizations and orphaned users.

#What to inventory

#Tools

Tool Scope Output
SMAT (SharePoint Migration Assessment Tool) SharePoint 2010/2013/2016 farms CSV per risk (long paths, large lists, workflows, InfoPath, customizations)
ShareGate Migrate Explore / pre-migration check reports Interactive reports of issues per object, with fix suggestions
Microsoft 365 Assessment tool SharePoint Online Add-ins/ACS, workflows, InfoPath, classic pages, with Power BI reports
PowerShell (SSOM / PnP) Anything custom Your own CSVs

#Scripts

On-prem: large lists and unique permissions per list (SSOM)PowerShell
Add-PSSnapin Microsoft.SharePoint.PowerShell -ErrorAction SilentlyContinue
Get-SPSite -Limit All | ForEach-Object {
  foreach ($web in $_.AllWebs) {
    foreach ($list in $web.Lists | Where-Object { -not $_.Hidden }) {
      [pscustomobject]@{
        Web = $web.Url; List = $list.Title; Items = $list.ItemCount
        UniqueScopes = ($list.RoleAssignments.Count -gt 0 -and $list.HasUniqueRoleAssignments)
        ItemLevelUnique = ($list.Items | Where-Object HasUniqueRoleAssignments | Measure-Object).Count   # slow on huge lists
        Workflows = $list.WorkflowAssociations.Count
        LastModified = $list.LastItemModifiedDate
      }
    }
    $web.Dispose()
  }
  $_.Dispose()
} | Export-Csv C:\assess\lists.csv -NoTypeInformation
On-prem: file paths longer than 400 characters (decoded)PowerShell
Get-SPSite -Limit All | ForEach-Object {
  foreach ($web in $_.AllWebs) {
    foreach ($lib in $web.Lists | Where-Object { $_.BaseType -eq "DocumentLibrary" -and -not $_.Hidden }) {
      foreach ($item in $lib.Items) {
        $full = $web.Site.Url + "/" + $item.Url
        if ($full.Length -gt 400) { [pscustomobject]@{ Length = $full.Length; Url = $full } }
      }
    }
    $web.Dispose()
  }
  $_.Dispose()
} | Export-Csv C:\assess\long-paths.csv -NoTypeInformation
Run heavy scans off-hours

Enumerating every item in large farms is expensive. Use SQL-friendly approaches (SMAT, ShareGate) for big farms, or scan per content database at night.

#Turning findings into decisions

Finding Typical decision
40% of sites untouched for 3 years Archive, don't migrate
Library with 3M documents Split by year or business unit; migrate with Insane mode / Migration API
12,000 item-level permissions Redesign: folders, separate libraries or sites
180 SPD workflows Retire 40%, rebuild rest in Power Automate
60 InfoPath forms Power Apps / form formatting per complexity

#Interview questions

Q1What are the top technical risks you look for during assessment?

Very large lists and libraries, long paths and blocked characters or files, item-level unique permissions, orphaned users, customizations (WSPs, workflows, InfoPath, add-ins, event receivers), checked-out files and heavy version histories.

Q2What is SMAT?

The SharePoint Migration Assessment Tool, a Microsoft command-line tool run on SharePoint Server farms that scans for migration risks (long paths, large lists, workflows, InfoPath, customizations and more) and produces CSV reports.
