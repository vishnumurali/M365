Migration Performance & Throttling – Throughput Planning, the Migration API and Decorated Traffic

Estimate and maximize migration throughput, covering how SharePoint Online throttles, the Azure-backed Migration API, realistic GB-per-hour numbers, parallelism, off-peak windows, decorating traffic, versions and file count effects, and a capacity planning worksheet.

#What affects speed

Factor Effect
File count vs size Many small files are much slower per GB than few large files
Versions Each version is a file, so 10 versions ≈ 10× the work
Metadata & permissions Unique permissions and rich metadata add processing
Time of day Off-peak (nights, weekends in the tenant region) is faster
Network Upload bandwidth and latency from the migration VM
Parallelism More jobs help until throttling kicks in
Planning numbers

Microsoft's guidance gives indicative ranges (from a few hundred GB per day for small-file content to several TB per day for large-file content via the Migration API). Measure your pilot throughput and extrapolate rather than relying on published numbers.

#Capacity planning worksheet

Input Example
In-scope data (after ROT cleanup) 2.4 TB
Average file size 1.8 MB (≈ 1.4M files)
Versions migrated Last 5
Pilot throughput (measured) 45 GB/hour (Insane mode, off-peak, 4 parallel jobs)
Hours available per week (off-peak) 60
Bulk duration 2,400 / 45 ≈ 53 hours ≈ 1 week
Delta passes ~5% of bulk each

#Throttling hygiene

  • Use tools that honour Retry-After and back off automatically.
  • Decorate traffic with a user agent identifying the app (tools do this), so Microsoft can classify traffic.
  • Avoid running heavy scripts and migrations under the same account simultaneously.
  • Prefer app-only identities registered for migration where the tool supports it.

#Interview questions

Q1Why is migrating 1 TB of small files slower than 1 TB of large files?

Per-file overhead dominates: each file (and each version) needs metadata processing, permission and property updates, and API calls or package entries. Thousands of small files mean many more operations per gigabyte.

Q2What is the SharePoint Migration API?

A bulk import API where tools package content and metadata, upload them to Azure Blob storage (encrypted), and submit an import job that SharePoint processes asynchronously. It offers far higher throughput and less throttling than item-by-item CSOM.
