SPFx Connected to Azure Table Storage – Two Secure Patterns with Full Code

Store and query data in Azure Table Storage from a SharePoint web part, either through an Entra-protected Azure Function using managed identity (recommended) or directly from the browser with Entra ID tokens and Azure RBAC, with key design, CRUD code, CORS and cost notes.

Azure Table Storage is a cheap, massively scalable key-value (NoSQL) store, ideal for data that does not belong in a SharePoint list: high-volume logs, telemetry, user preferences, kiosk check-ins, survey responses, or anything that would blow past list thresholds. There are two secure ways to use it from SPFx.

PartitionKey + RowKeythe only index (design keys for your queries)
~$0.045/GBstorage per month (ballpark, region-dependent)
1 MBmax entity size, 252 custom properties
0secrets in the browser (both patterns below)

#Pattern A (recommended): SPFx → Azure Function → Table Storage

#The function (Node, @azure/data-tables)

src/functions/checkins.tsTypeScript
import { app, HttpRequest, HttpResponseInit } from '@azure/functions';
import { TableClient, odata } from '@azure/data-tables';
import { DefaultAzureCredential } from '@azure/identity';

// Managed identity in Azure, your az login locally — no account keys anywhere
const table = new TableClient(`https://${process.env.STORAGE_ACCOUNT}.table.core.windows.net`, 'CheckIns', new DefaultAzureCredential());

const inverted = () => String(8640000000000000 - Date.now()).padStart(16, '0');   // newest first

function caller(req: HttpRequest) {
  const p = JSON.parse(Buffer.from(req.headers.get('x-ms-client-principal') ?? '', 'base64').toString() || '{}');
  const c = (t: string) => p.claims?.find((x: any) => x.typ === t)?.val;
  return { oid: c('http://schemas.microsoft.com/identity/claims/objectidentifier'), name: c('name') };
}

app.http('checkins', {
  methods: ['GET', 'POST', 'PATCH', 'DELETE'],
  authLevel: 'anonymous',                 // Easy Auth enforces Entra ID
  route: 'checkins/{site}/{rowKey?}',
  handler: async (req: HttpRequest): Promise<HttpResponseInit> => {
    const site = req.params.site;
    const user = caller(req);
    const day = new Date().toISOString().slice(0, 10);
    const pk = `${site}|${day}`;

    switch (req.method) {
      case 'GET': {                                       // READ today's check-ins for a site
        const rows = [];
        const iter = table.listEntities({ queryOptions: { filter: odata`PartitionKey eq ${pk}` } });
        for await (const e of iter) { rows.push(e); if (rows.length >= 200) break; }
        return { jsonBody: rows };
      }
      case 'POST': {                                      // CREATE
        const body = await req.json() as { desk: string; note?: string };
        const entity = { partitionKey: pk, rowKey: `${inverted()}_${user.oid}`, desk: body.desk, note: body.note ?? '',
                         userName: user.name, userOid: user.oid };
        await table.createEntity(entity);
        return { status: 201, jsonBody: entity };
      }
      case 'PATCH': {                                     // UPDATE (merge) – only your own rows
        const rk = req.params.rowKey!;
        const existing = await table.getEntity<any>(pk, rk);
        if (existing.userOid !== user.oid) return { status: 403 };
        const changes = await req.json() as { note: string };
        await table.updateEntity({ partitionKey: pk, rowKey: rk, note: changes.note }, 'Merge', { etag: existing.etag });
        return { status: 204 };
      }
      case 'DELETE': {                                    // DELETE
        const rk = req.params.rowKey!;
        const existing = await table.getEntity<any>(pk, rk);
        if (existing.userOid !== user.oid) return { status: 403 };
        await table.deleteEntity(pk, rk);
        return { status: 204 };
      }
    }
    return { status: 405 };
  }
});

#The SPFx side

services/CheckInApi.tsTypeScript
import { AadHttpClient } from '@microsoft/sp-http';

export class CheckInApi {
  constructor(private factory: any, private base = 'https://fn-checkin.azurewebsites.net/api') {}
  private client?: AadHttpClient;
  private async c(): Promise<AadHttpClient> { return this.client ??= await this.factory.getClient('api://checkin-api'); }

  public async today(site: string) { return (await (await this.c()).get(`${this.base}/checkins/${site}`, AadHttpClient.configurations.v1)).json(); }
  public async checkIn(site: string, desk: string, note?: string) {
    return (await (await this.c()).post(`${this.base}/checkins/${site}`, AadHttpClient.configurations.v1,
      { headers: { 'Content-Type': 'application/json' }, body: JSON.stringify({ desk, note }) })).json();
  }
  public async updateNote(site: string, rowKey: string, note: string) {
    await (await this.c()).fetch(`${this.base}/checkins/${site}/${rowKey}`, AadHttpClient.configurations.v1,
      { method: 'PATCH', headers: { 'Content-Type': 'application/json' }, body: JSON.stringify({ note }) });
  }
  public async remove(site: string, rowKey: string) {
    await (await this.c()).fetch(`${this.base}/checkins/${site}/${rowKey}`, AadHttpClient.configurations.v1, { method: 'DELETE' });
  }
}
// in onInit: this.api = new CheckInApi(this.context.aadHttpClientFactory);

#Pattern B: SPFx → Table Storage directly (Entra ID + RBAC)

Azure Tables accept Entra ID tokens. An SPFx web part can request a token for Azure Storage and call the Table REST API itself, with no keys and no SAS. Users (or a group) need an RBAC role on the table, and the storage account needs CORS for your SharePoint domain.

package-solution.jsonJSON
"webApiPermissionRequests": [ { "resource": "Azure Storage", "scope": "user_impersonation" } ]
services/TableDirect.ts – REST CRUD with the user's tokenTypeScript
import { AadHttpClient, IHttpClientOptions } from '@microsoft/sp-http';

export class TableDirect {
  private client?: AadHttpClient;
  constructor(private factory: any, private account: string, private table: string) {}
  private get base() { return `https://${this.account}.table.core.windows.net`; }
  private async c() { return this.client ??= await this.factory.getClient('https://storage.azure.com'); }
  private headers(extra: Record<string, string> = {}) {
    return { 'x-ms-version': '2020-12-06', 'x-ms-date': new Date().toUTCString(),
             'Accept': 'application/json;odata=nometadata', 'Content-Type': 'application/json', ...extra };
  }
  private key(pk: string, rk: string) { return `(PartitionKey='${encodeURIComponent(pk)}',RowKey='${encodeURIComponent(rk)}')`; }

  public async query(pk: string): Promise<any[]> {
    const filter = encodeURIComponent(`PartitionKey eq '${pk.replace(/'/g, "''")}'`);
    const r = await (await this.c()).get(`${this.base}/${this.table}()?$filter=${filter}&$top=100`, AadHttpClient.configurations.v1, { headers: this.headers() });
    return (await r.json()).value;                         // continuation: x-ms-continuation-NextPartitionKey/NextRowKey headers
  }
  public async insert(entity: { PartitionKey: string; RowKey: string; [k: string]: any }) {
    await (await this.c()).post(`${this.base}/${this.table}`, AadHttpClient.configurations.v1,
      { headers: this.headers({ 'Prefer': 'return-no-content' }), body: JSON.stringify(entity) });
  }
  public async merge(pk: string, rk: string, changes: Record<string, any>, etag = '*') {
    const o: IHttpClientOptions = { method: 'MERGE', headers: this.headers({ 'If-Match': etag }), body: JSON.stringify(changes) };
    await (await this.c()).fetch(`${this.base}/${this.table}${this.key(pk, rk)}`, AadHttpClient.configurations.v1, o);
  }
  public async remove(pk: string, rk: string) {
    await (await this.c()).fetch(`${this.base}/${this.table}${this.key(pk, rk)}`, AadHttpClient.configurations.v1,
      { method: 'DELETE', headers: this.headers({ 'If-Match': '*' }) });
  }
}

Pattern B gives users direct table access

Anyone with the RBAC role can read and write any entity in that table with their own tools, not just through your web part. There are no row-level rules. Use pattern B only for low-risk data (for example personal preferences), and pattern A when you need validation, ownership rules or auditing.

#Which pattern?

A · Function + managed identity B · Direct with Entra + RBAC
Secrets in browser None None
Row-level authorization ✅ in code ❌ table-level only
Validation / business rules ✅ server-side Client-side only
Extra infrastructure Function App None
Latency +1 hop Lowest
Recommended ✅ default Low-risk, simple scenarios

#Interview questions

Q1Why use Table Storage instead of a SharePoint list for some SPFx data?

For high-volume or append-only data (logs, check-ins, telemetry) that would hit list thresholds, needs cheap massive scale, or doesn't need SharePoint features such as versioning, permissions per item and forms. Tables give single-digit-millisecond key lookups at very low cost.

Q2How can SPFx write to Azure Tables without exposing an account key?

Either call an Entra-protected Azure Function that uses a managed identity with the Storage Table Data Contributor role (recommended), or request an Azure Storage user_impersonation token in SPFx and call the Table REST API directly, with the user granted an RBAC role and CORS configured.

Q3What is a good PartitionKey for a desk check-in app?

Something that matches the main query and spreads load, for example site|yyyy-mm-dd, so "today's check-ins for Bangalore" is a single-partition query. Use inverted ticks plus the user ID as RowKey for uniqueness and newest-first ordering.
