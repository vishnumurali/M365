Application Customizer – Custom Headers, Footers, Banners and Page Scripts

Build an SPFx application customizer that renders into Top and Bottom placeholders, handles SPA navigation, reads properties from ClientSideComponentProperties, and deploys tenant-wide via the Tenant Wide Extensions list or per site.

An application customizer runs on every modern page of the sites where it is activated. It can render UI in the Top and Bottom placeholders (below the suite bar and at the end of the page) or run non-visual code such as analytics, cookie banners or redirects. It is the modern replacement for custom master page headers and footers.

#The code

src/extensions/contosoChrome/ContosoChromeApplicationCustomizer.tsTypeScript
import { BaseApplicationCustomizer, PlaceholderContent, PlaceholderName } from '@microsoft/sp-application-base';
import * as React from 'react';
import * as ReactDom from 'react-dom';
import { Banner } from './components/Banner';

export interface IContosoChromeProperties {
  message: string;          // passed via ClientSideComponentProperties JSON
  severity: 'info' | 'warning' | 'critical';
}

export default class ContosoChromeApplicationCustomizer
  extends BaseApplicationCustomizer<IContosoChromeProperties> {

  private _top: PlaceholderContent | undefined;
  private _bottom: PlaceholderContent | undefined;

  public async onInit(): Promise<void> {
    // Placeholders can appear later and are re-created on SPA navigation
    this.context.placeholderProvider.changedEvent.add(this, this._renderPlaceholders);
    this.context.application.navigatedEvent.add(this, this._renderPlaceholders);
    this._renderPlaceholders();
  }

  private _renderPlaceholders(): void {
    if (!this._top) {
      this._top = this.context.placeholderProvider.tryCreateContent(PlaceholderName.Top, { onDispose: this._onDispose });
      if (this._top) {
        ReactDom.render(React.createElement(Banner, {
          message: this.properties.message, severity: this.properties.severity,
          siteTitle: this.context.pageContext.web.title
        }), this._top.domElement);
      }
    }
    if (!this._bottom) {
      this._bottom = this.context.placeholderProvider.tryCreateContent(PlaceholderName.Bottom, { onDispose: this._onDispose });
      if (this._bottom) {
        this._bottom.domElement.innerHTML =
          `<footer style="padding:12px 24px;font-size:12px">© Contoso · <a href="/sites/help">Help</a> · <a href="/sites/privacy">Privacy</a></footer>`;
      }
    }
  }

  private _onDispose = (): void => {
    if (this._top) ReactDom.unmountComponentAtNode(this._top.domElement);
  };
}

Be lightweight

Application customizers load on every page. Keep the bundle small, lazy-load heavy components with dynamic import(), and cache data such as banner messages in sessionStorage.

#Interview questions

Q1Why must an application customizer subscribe to placeholder and navigation events?

Modern SharePoint is a single-page application. Placeholders may not exist on first onInit, and they are re-created when users navigate between pages without a full reload. Listening to placeholderProvider.changedEvent (and navigation) lets you render reliably.

Q2How do you deploy an application customizer to every site in the tenant?

Set skipFeatureDeployment: true, include a ClientSideInstance.xml (or add an entry to the app catalog's Tenant Wide Extensions list) with the component ID, location and properties, and deploy the package tenant-wide. You can target by web template or list template if needed.
