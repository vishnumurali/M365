What is the SharePoint Framework (SPFx)? Architecture, Components & History

SPFx explained end to end, covering how client-side components run in the page, the component types (web parts, extensions, ACEs, library components, form customizers), where code is hosted, the toolchain, versions from 2017 to 2026, and when to choose SPFx.

The SharePoint Framework (SPFx) is Microsoft's page and web part model for customizing SharePoint Online, Microsoft Teams, Viva Connections, Outlook and the Microsoft 365 app, and SharePoint Server 2016 FP2, 2019 and SE. You write TypeScript (usually with React), package it as an .sppkg, and SharePoint loads your bundle directly into the page: no iframes, no server code.

#How SPFx runs

Key implications:

  • Your code runs as the current user, with exactly their permissions. Nothing is elevated.
  • It is client-side only. Secrets must never be placed in SPFx code. Call a protected API instead.
  • It shares the page with other components, so be a good citizen: small bundles, no global CSS overrides, no jQuery conflicts.

#A short history

  1. 2016

    Announced

    Previewed at "The Future of SharePoint" event (May 2016).

  2. Feb 2017

    v1.0 GA

    Client-side web parts for SharePoint Online.

  3. 2017

    Extensions

    Application customizers, field customizers and command sets became generally available.

  4. 2018

    SharePoint 2019 support

    On-premises support for SPFx 1.4.1 (SharePoint 2016 FP2 supports 1.1).

  5. 2019

    Teams tabs

    SPFx web parts can be surfaced in Microsoft Teams.

  6. 2021

    Viva Connections ACEs

    Adaptive Card Extensions (v1.13).

  7. 2022

    Form customizers & Graph v3 client

    Custom list forms, MSGraphClientV3 (v1.15).

  8. 2023–2024

    Node 18, Teams/Outlook/M365 app hosting

    Modernized toolchain dependencies and broader hosting.

  9. 2025–2026

    Node 22 & Heft toolchain

    v1.21 moved to Node 22 LTS. v1.22 (December 2025) replaced the gulp-based build with Heft, driven by npm scripts.

#Interview questions

Q1Why can't you store an API key in an SPFx web part?

SPFx runs entirely in the browser. Anything in the bundle, including config, is downloadable by any user. Secrets belong in a back-end API (for example an Azure Function with Key Vault) that SPFx calls with an Entra ID token through AadHttpClient.

Q2What are the main SPFx component types?

Web parts, extensions (application customizer, field customizer, ListView command set, form customizer), Adaptive Card Extensions for Viva Connections, and library components for shared code.

Q3How does SPFx authenticate to SharePoint and Graph?

It uses the current user's session. SPHttpClient calls SharePoint REST with the page's authentication, and MSGraphClientV3 and AadHttpClient obtain Entra ID access tokens on behalf of the user for permissions approved by an admin in the API access page.
