The generator gives you a single class component. Real solutions need a structure that keeps data access, state and UI separate so you can test and change each piece independently.

#Recommended structure

Feature-oriented layoutText
src/webparts/deviations/
├─ DeviationsWebPart.ts            ← SPFx glue only (context, properties, render)
├─ components/
│  ├─ Deviations.tsx               ← container: uses hooks, composes UI
│  ├─ DeviationList.tsx            ← presentational
│  ├─ DeviationForm.tsx
│  └─ ErrorBoundary.tsx
├─ hooks/
│  └─ useDeviations.ts             ← loading/error/data state
├─ services/
│  ├─ IDeviationService.ts         ← interface (mockable)
│  └─ DeviationService.ts          ← PnPjs / SPHttpClient implementation
├─ models/Deviation.ts
└─ context/SpfxContext.tsx         ← React context for services & SPFx context

#Service layer

services/DeviationService.tsTypeScript
import { SPFI } from '@pnp/sp';
import '@pnp/sp/webs'; import '@pnp/sp/lists'; import '@pnp/sp/items';
import { IDeviation } from '../models/Deviation';

export interface IDeviationService {
  getOpen(top: number): Promise<IDeviation[]>;
  create(d: Partial<IDeviation>): Promise<number>;
  close(id: number): Promise<void>;
}

export class DeviationService implements IDeviationService {
  constructor(private sp: SPFI, private listTitle: string) {}

  public async getOpen(top: number): Promise<IDeviation[]> {
    return this.sp.web.lists.getByTitle(this.listTitle).items
      .select('Id', 'Title', 'Status', 'DueDate', 'Owner/Title').expand('Owner')
      .filter("Status ne 'Closed'").orderBy('DueDate', true).top(top)();
  }
  public async create(d: Partial<IDeviation>): Promise<number> {
    const r = await this.sp.web.lists.getByTitle(this.listTitle).items.add({ Title: d.Title, Status: 'Submitted' });
    return r.Id ?? r.data?.Id;   // PnPjs v4 returns the item data directly
  }
  public async close(id: number): Promise<void> {
    await this.sp.web.lists.getByTitle(this.listTitle).items.getById(id).update({ Status: 'Closed' });
  }
}

#Custom hook with loading, error and refresh

hooks/useDeviations.tsTypeScript
import * as React from 'react';
import { IDeviationService } from '../services/DeviationService';
import { IDeviation } from '../models/Deviation';

export function useDeviations(service: IDeviationService, top = 20) {
  const [items, setItems] = React.useState<IDeviation[]>([]);
  const [loading, setLoading] = React.useState(true);
  const [error, setError] = React.useState<string | undefined>();
  const [version, setVersion] = React.useState(0);

  React.useEffect(() => {
    let cancelled = false;
    setLoading(true);
    service.getOpen(top)
      .then(data => { if (!cancelled) { setItems(data); setError(undefined); } })
      .catch(e => { if (!cancelled) setError(e.message); })
      .finally(() => { if (!cancelled) setLoading(false); });
    return () => { cancelled = true; };   // avoid setting state after unmount
  }, [service, top, version]);

  return { items, loading, error, refresh: () => setVersion(v => v + 1) };
}

#Container component with states

components/Deviations.tsxTSX
import * as React from 'react';
import { Spinner, MessageBar, MessageBarType, PrimaryButton } from '@fluentui/react';
import { useDeviations } from '../hooks/useDeviations';
import { DeviationList } from './DeviationList';
import { IDeviationService } from '../services/DeviationService';

export const Deviations: React.FC<{ service: IDeviationService; title: string }> = ({ service, title }) => {
  const { items, loading, error, refresh } = useDeviations(service);
  const onClose = React.useCallback(async (id: number) => { await service.close(id); refresh(); }, [service, refresh]);

  if (loading) return <Spinner label="Loading deviations…" />;
  if (error) return <MessageBar messageBarType={MessageBarType.error}>{error}</MessageBar>;
  if (!items.length) return <MessageBar>No open deviations 🎉</MessageBar>;

  return (
    <section>
      <h2>{title}</h2>
      <DeviationList items={items} onClose={onClose} />
      <PrimaryButton text="Refresh" onClick={refresh} />
    </section>
  );
};

#Error boundary

components/ErrorBoundary.tsxTSX
export class ErrorBoundary extends React.Component<{ children: React.ReactNode }, { error?: Error }> {
  public state: { error?: Error } = {};
  public static getDerivedStateFromError(error: Error) { return { error }; }
  public componentDidCatch(error: Error) { console.error('[Deviations]', error); /* log to App Insights */ }
  public render() { return this.state.error ? <p>Something went wrong. Please refresh the page.</p> : this.props.children; }
}
React version

SPFx pins the React version (for example React 17 in recent releases). Do not upgrade React yourself, because the page loads SharePoint's own React. Use the versions from the generator.

#Interview questions

Q1Why separate a service layer from React components in SPFx?

It isolates data access (PnPjs, REST, Graph) behind an interface, so components stay presentational and testable with mocks. Changing the data source, for example from a list to an API, does not require UI changes, and the same service can be reused across web parts or a library component.

Q2How do you prevent "Can't perform a React state update on an unmounted component"?

Track cancellation in useEffect cleanup (a cancelled flag or AbortController), and only set state when still mounted. Also unmount the React tree in the web part's onDispose.
