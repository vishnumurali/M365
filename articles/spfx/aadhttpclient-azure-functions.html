SPFx + Azure Functions with AadHttpClient – Secure Custom APIs End to End

Protect an Azure Function with Entra ID (Easy Auth), expose an API scope, request it from SPFx, call it with AadHttpClient, read the user's identity server-side, and use on-behalf-of or managed identity for back-end resources, with full code and setup steps.

When a web part needs secrets, elevated access, heavy processing or non-SharePoint data, put that logic in an Azure Function and let SPFx call it with AadHttpClient. The function is protected by Entra ID, so only your tenant's users (through SPFx) can call it, and it knows exactly who the caller is.

#Architecture

#Step 1 · Create the Function and its Entra app

  1. Create a Function App (Node 20/22 or .NET 8 isolated).
  2. Authentication → Add identity provider → Microsoft (creates an app registration). Set Require authentication and Return HTTP 401 for unauthenticated requests.
  3. In the app registration → Expose an API: set the App ID URI (e.g. api://deviation-api or the default api://<client-id>) and the scope user_impersonation.
  4. Under Authentication of the Function, add https://contoso.sharepoint.com (or the client principal) to allowed token audiences if you use a custom URI.
  5. CORS: allow https://contoso.sharepoint.com (and https://localhost:4321 for dev).

#Step 2 · The function

src/functions/deviations.ts (Azure Functions v4, Node)TypeScript
import { app, HttpRequest, HttpResponseInit, InvocationContext } from '@azure/functions';

function getCaller(req: HttpRequest): { name: string; oid: string } {
  // Easy Auth injects the validated principal as base64 JSON
  const raw = req.headers.get('x-ms-client-principal');
  if (!raw) throw new Error('unauthenticated');
  const p = JSON.parse(Buffer.from(raw, 'base64').toString('utf8'));
  const claim = (t: string) => p.claims.find((c: any) => c.typ === t)?.val;
  return { name: claim('name'), oid: claim('http://schemas.microsoft.com/identity/claims/objectidentifier') };
}

app.http('deviations', {
  methods: ['GET', 'POST'],
  authLevel: 'anonymous',            // auth handled by Easy Auth (Entra ID), not function keys
  handler: async (req: HttpRequest, ctx: InvocationContext): Promise<HttpResponseInit> => {
    const caller = getCaller(req);
    if (req.method === 'GET') {
      const status = req.query.get('status') ?? 'Open';
      const rows = await repository.list(status);          // SQL / Table Storage via managed identity
      return { jsonBody: { requestedBy: caller.name, items: rows } };
    }
    const body = await req.json() as { title: string };
    if (!body.title || body.title.length < 5) return { status: 400, jsonBody: { error: 'Title too short' } };
    const created = await repository.create({ ...body, createdBy: caller.oid });
    return { status: 201, jsonBody: created };
  }
});

#Step 3 · Request the permission in SPFx

config/package-solution.jsonJSON
"webApiPermissionRequests": [
  { "resource": "deviation-api", "scope": "user_impersonation" }
]

resource is the display name of the API's app registration (or its app ID URI). After deployment, approve it in SharePoint admin center → Advanced → API access.

#Step 4 · Call it from the web part

services/DeviationApi.tsTypeScript
import { AadHttpClient, HttpClientResponse } from '@microsoft/sp-http';
import { WebPartContext } from '@microsoft/sp-webpart-base';

export class DeviationApi {
  private client!: AadHttpClient;
  private readonly base = 'https://contoso-deviation-api.azurewebsites.net/api';

  constructor(private context: WebPartContext) {}

  private async getClient(): Promise<AadHttpClient> {
    if (!this.client) this.client = await this.context.aadHttpClientFactory.getClient('api://deviation-api');
    return this.client;
  }

  public async list(status = 'Open'): Promise<any[]> {
    const c = await this.getClient();
    const res: HttpClientResponse = await c.get(`${this.base}/deviations?status=${encodeURIComponent(status)}`, AadHttpClient.configurations.v1);
    if (!res.ok) throw new Error(`API ${res.status}`);
    return (await res.json()).items;
  }

  public async create(title: string): Promise<any> {
    const c = await this.getClient();
    const res = await c.post(`${this.base}/deviations`, AadHttpClient.configurations.v1, {
      headers: { 'Content-Type': 'application/json' }, body: JSON.stringify({ title })
    });
    if (!res.ok) throw new Error((await res.json()).error ?? `API ${res.status}`);
    return res.json();
  }
}

#Going further: acting as the user on Graph (on-behalf-of)

If the function must call Graph as the user (for example to send mail on their behalf), exchange the incoming token with the OBO flow using MSAL (acquireTokenOnBehalfOf) with the function's app credentials (certificate or federated identity credential). Grant the API app the delegated Graph scopes it needs.

Checklist

Require authentication in Easy Auth (401 on anonymous). Validate the audience and tenant. Use managed identity for Azure resources, not connection strings. Restrict CORS to your SharePoint domain. Authorize per operation (roles or group claims), because "authenticated" is not the same as "allowed".

#Interview questions

Q1How does SPFx get a token for a custom API?

this.context.aadHttpClientFactory.getClient('<App ID URI or client ID>') asks Entra ID for an access token for that resource on behalf of the user, using the SharePoint Online Client Extensibility principal, which must have been granted the API's scope through webApiPermissionRequests and admin approval.

Q2How does the Azure Function know who called it?

With App Service Authentication (Easy Auth) the platform validates the bearer token and passes the claims in the x-ms-client-principal header (base64 JSON). Alternatively, the function can validate the JWT itself with a library and read the oid, upn and roles claims.

Q3Why not call Azure SQL or Storage directly from SPFx?

It would expose connection strings or keys to the browser, or require broad user permissions on the data store. A function in the middle keeps secrets server-side, enforces business rules, and can use managed identity.
