SPFx Connected to Dataverse – Web API CRUD from a SharePoint Web Part

Read and write Dataverse tables directly from SPFx with AadHttpClient, covering permission requests, environment URLs, OData queries, formatted values, lookups with @odata.bind, create/update/delete, security roles, CORS and when to put a custom API in the middle.

Many organizations keep business data in Dataverse (model-driven apps, Dynamics 365) but want it on the SharePoint intranet or in Teams. An SPFx web part can call the Dataverse Web API directly as the signed-in user. Dataverse security roles still apply, so users only see and change what they are allowed to.

#Architecture

#Prerequisites

  1. Environment URL, e.g. https://contoso.crm4.dynamics.com (from Power Platform admin center → environment → Environment URL).
  2. Users must exist in that environment (licensed, with a security role granting the table privileges).
  3. Request the Dataverse scope in package-solution.json:
config/package-solution.jsonJSON
"webApiPermissionRequests": [
  { "resource": "Dataverse", "scope": "user_impersonation" }
]
Resource display name

The Entra service principal for Dataverse appears as "Dataverse" in most tenants (older tenants may show Common Data Service or Dynamics CRM). Use the name exactly as shown under Enterprise applications (app ID 00000007-0000-0000-c000-000000000000). Then approve the request in SharePoint admin center → API access.

#A typed Dataverse service

services/DataverseService.tsTypeScript
import { AadHttpClient, HttpClientResponse, IHttpClientOptions } from '@microsoft/sp-http';
import { WebPartContext } from '@microsoft/sp-webpart-base';

export interface IDeviation {
  cr8a1_deviationid?: string;
  cr8a1_name: string;                       // primary name column
  cr8a1_severity?: number;                  // choice (option set) value
  'cr8a1_severity@OData.Community.Display.V1.FormattedValue'?: string;
  cr8a1_duedate?: string;
  _cr8a1_plant_value?: string;              // lookup id (read)
  '_cr8a1_plant_value@OData.Community.Display.V1.FormattedValue'?: string;
}

export class DataverseService {
  private client!: AadHttpClient;
  private readonly api: string;

  constructor(private context: WebPartContext, private envUrl: string) {
    this.api = `${envUrl.replace(/\/$/, '')}/api/data/v9.2`;
  }

  private async http(): Promise<AadHttpClient> {
    if (!this.client) this.client = await this.context.aadHttpClientFactory.getClient(this.envUrl);
    return this.client;
  }

  private headers(extra: Record<string, string> = {}): Record<string, string> {
    return {
      'Accept': 'application/json',
      'Content-Type': 'application/json; charset=utf-8',
      'OData-MaxVersion': '4.0',
      'OData-Version': '4.0',
      'Prefer': 'odata.include-annotations="OData.Community.Display.V1.FormattedValue"',
      ...extra
    };
  }

  // READ: select, filter, order, top + formatted values for choices/lookups
  public async list(top = 25): Promise<IDeviation[]> {
    const q = `$select=cr8a1_name,cr8a1_severity,cr8a1_duedate,_cr8a1_plant_value` +
              `&$filter=statecode eq 0&$orderby=cr8a1_duedate asc&$top=${top}`;
    const res = await (await this.http()).get(`${this.api}/cr8a1_deviations?${q}`, AadHttpClient.configurations.v1,
                                               { headers: this.headers() });
    return (await this.ok(res)).value;
  }

  // CREATE: lookup via @odata.bind, return the created row
  public async create(d: { name: string; severity: number; dueDate?: string; plantId?: string }): Promise<IDeviation> {
    const body: any = { cr8a1_name: d.name, cr8a1_severity: d.severity, cr8a1_duedate: d.dueDate };
    if (d.plantId) body['cr8a1_Plant@odata.bind'] = `/cr8a1_plants(${d.plantId})`;   // navigation property name (case-sensitive)
    const res = await (await this.http()).post(`${this.api}/cr8a1_deviations`, AadHttpClient.configurations.v1, {
      headers: this.headers({ 'Prefer': 'return=representation' }), body: JSON.stringify(body)
    });
    return this.ok(res);
  }

  // UPDATE: PATCH with If-Match to avoid creating a row by accident (upsert)
  public async update(id: string, changes: Partial<IDeviation>): Promise<void> {
    const opts: IHttpClientOptions = { method: 'PATCH', headers: this.headers({ 'If-Match': '*' }), body: JSON.stringify(changes) };
    const res = await (await this.http()).fetch(`${this.api}/cr8a1_deviations(${id})`, AadHttpClient.configurations.v1, opts);
    await this.ok(res, true);
  }

  // DELETE
  public async remove(id: string): Promise<void> {
    const res = await (await this.http()).fetch(`${this.api}/cr8a1_deviations(${id})`, AadHttpClient.configurations.v1,
                                                 { method: 'DELETE', headers: this.headers() });
    await this.ok(res, true);
  }

  // WhoAmI – handy to verify the user exists in the environment
  public async whoAmI(): Promise<{ UserId: string; BusinessUnitId: string }> {
    const res = await (await this.http()).get(`${this.api}/WhoAmI`, AadHttpClient.configurations.v1, { headers: this.headers() });
    return this.ok(res);
  }

  private async ok(res: HttpClientResponse, noBody = false): Promise<any> {
    if (res.ok) return noBody || res.status === 204 ? undefined : res.json();
    const err = await res.json().catch(() => ({}));
    throw new Error(err?.error?.message ?? `Dataverse ${res.status}`);
  }
}

#Using it in React

components/DeviationGrid.tsx (excerpt)TSX
const svc = React.useMemo(() => new DataverseService(context, 'https://contoso.crm4.dynamics.com'), [context]);
const [rows, setRows] = React.useState<IDeviation[]>([]);

React.useEffect(() => { svc.list().then(setRows).catch(e => setError(e.message)); }, [svc]);

return (
  <DetailsList
    items={rows}
    columns={[
      { key: 'n', name: 'Deviation', fieldName: 'cr8a1_name', minWidth: 200 },
      { key: 's', name: 'Severity', minWidth: 90, onRender: r => r['cr8a1_severity@OData.Community.Display.V1.FormattedValue'] },
      { key: 'p', name: 'Plant', minWidth: 120, onRender: r => r['_cr8a1_plant_value@OData.Community.Display.V1.FormattedValue'] },
      { key: 'd', name: 'Due', minWidth: 100, onRender: r => r.cr8a1_duedate && new Date(r.cr8a1_duedate).toLocaleDateString() }
    ]}
  />
);

#Request flow

#Direct call vs custom API

SPFx → Dataverse directly SPFx → Azure Function → Dataverse
Identity User (delegated) User (OBO) or application user
Users need Dataverse licence/role ✅ yes Not if the function uses an application user
Extra infrastructure None Function App
Business logic placement Dataverse (plug-ins, rules) + client Function + Dataverse
Best for Internal users already in the environment Broad audiences, aggregation, hiding schema, complex orchestration
Licensing and access

Every user calling Dataverse directly must be a user in the environment with an appropriate licence and security role. If thousands of intranet readers only need a read-only view, consider an API with an application user (and check licensing terms for multiplexing), or replicate the needed data to SharePoint with a dataflow.

#Troubleshooting

Problem Fix
AADSTS65001 / no consent Approve the Dataverse – user_impersonation request in API access
401 from Dataverse Wrong resource URL (must be the environment URL), token for a different environment
403 principal user is missing prvReadcr8a1_deviation Give the user a security role with Read on the table
400 on @odata.bind Use the navigation property name (often schema-name casing, e.g. cr8a1_Plant) and the entity set name (cr8a1_plants)
Choice shows a number Add the Prefer: odata.include-annotations header and read the FormattedValue annotation

#Interview questions

Q1How does an SPFx web part authenticate to Dataverse?

With AadHttpClient from aadHttpClientFactory.getClient(environmentUrl). The token is issued for the Dataverse environment with the user_impersonation scope, which must be requested in webApiPermissionRequests (resource "Dataverse") and approved by an admin.

Q2How do you set a lookup column when creating a Dataverse row through the Web API?

Use @odata.bind on the single-valued navigation property, for example "cr8a1_Plant@odata.bind": "/cr8a1_plants(<guid>)". The property name is case-sensitive and uses the navigation property name, not the logical column name.

Q3Why would you put an Azure Function between SPFx and Dataverse?

To avoid requiring every reader to have Dataverse access, to aggregate or reshape data, to keep schema and business logic server-side, to use an application user, or to combine Dataverse with other back ends behind one API.
