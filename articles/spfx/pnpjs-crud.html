PnPjs in SPFx – Fluent CRUD, Batching, Caching, Files and Large Lists

Set up PnPjs v3/v4 with SPFx behaviours and a context-aware factory, then cover CRUD, select/expand/filter, batching, file upload with chunking, caching, paging large lists, error handling and Graph access.

PnPjs is the community's fluent TypeScript library for SharePoint REST and Microsoft Graph. It turns string-built URLs into discoverable, typed calls and adds batching, caching and paging. It is the most common data layer in production SPFx solutions.

#Setup

Install (match versions across @pnp packages)PowerShell
npm install @pnp/sp @pnp/graph @pnp/logging --save
pnpjsConfig.ts – a single place to get configured instancesTypeScript
import { WebPartContext } from '@microsoft/sp-webpart-base';
import { spfi, SPFI, SPFx } from '@pnp/sp';
import { graphfi, GraphFI, SPFx as graphSPFx } from '@pnp/graph';
import { LogLevel, PnPLogging } from '@pnp/logging';
import '@pnp/sp/webs'; import '@pnp/sp/lists'; import '@pnp/sp/items'; import '@pnp/sp/batching';
import '@pnp/sp/files'; import '@pnp/sp/folders'; import '@pnp/sp/site-users/web';
import '@pnp/graph/users';

let _sp: SPFI | undefined;
let _graph: GraphFI | undefined;

export const getSP = (context?: WebPartContext): SPFI => {
  if (context) _sp = spfi().using(SPFx(context)).using(PnPLogging(LogLevel.Warning));
  return _sp!;
};
export const getGraph = (context?: WebPartContext): GraphFI => {
  if (context) _graph = graphfi().using(graphSPFx(context)).using(PnPLogging(LogLevel.Warning));
  return _graph!;
};
Web part onInitTypeScript
protected async onInit(): Promise<void> {
  await super.onInit();
  getSP(this.context);
  getGraph(this.context);
}

#CRUD

Create · Read · Update · DeleteTypeScript
const sp = getSP();
const list = sp.web.lists.getByTitle('Deviations');

// CREATE
const created = await list.items.add({ Title: 'Cold room excursion', Status: 'Submitted', OwnerId: 12 });

// READ – select / expand / filter / order / top
const open = await list.items
  .select('Id', 'Title', 'Status', 'DueDate', 'Owner/Title', 'Owner/EMail')
  .expand('Owner')
  .filter("Status ne 'Closed' and DueDate le datetime'2026-12-31T00:00:00Z'")
  .orderBy('DueDate', true)
  .top(100)();

// READ one
const one = await list.items.getById(42).select('Title', 'Status')();

// UPDATE (pass an etag as 2nd arg for concurrency, default '*')
await list.items.getById(42).update({ Status: 'In Review' });

// DELETE → recycle bin (or .delete() for permanent)
await list.items.getById(42).recycle();

#Files

Upload (chunked for big files) and set metadataTypeScript
const folder = sp.web.getFolderByServerRelativePath('/sites/quality/Shared Documents/Reports');
const file = (input.files as FileList)[0];
const result = file.size <= 10 * 1024 * 1024
  ? await folder.files.addUsingPath(file.name, file, { Overwrite: true })
  : await folder.files.addChunked(file.name, file, { progress: d => console.log(`${d.stage} ${d.offset}`), Overwrite: true });

const item = await sp.web.getFileByServerRelativePath(result.data?.ServerRelativeUrl ?? result.ServerRelativeUrl).getItem();
await item.update({ DocumentType: 'Report', Department: 'Quality' });

#Caching

Cache reference data in session storageTypeScript
import { Caching } from '@pnp/queryable';
const cachedSP = sp.using(Caching({ store: 'session', keyFactory: url => `codex-${url}`, expireFunc: () => new Date(Date.now() + 10 * 60 * 1000) }));
const departments = await cachedSP.web.lists.getByTitle('Departments').items.select('Id', 'Title')();

#Graph with PnPjs

Current user's manager and direct reportsTypeScript
const graph = getGraph();
const me = await graph.me.select('displayName', 'mail', 'jobTitle')();
const manager = await graph.me.manager();          // requires User.Read.All (approved in API access)
Version pitfalls

Keep all @pnp/* packages on the same version. Remember that PnPjs v3+ uses selective imports (import '@pnp/sp/items'), so a missing import means the method "doesn't exist" at runtime. Return shapes changed between v3 and v4 (for example add() results), so check the upgrade guide when migrating.

#Interview questions

Q1Why use PnPjs instead of SPHttpClient?

PnPjs offers a fluent, typed API, batching, caching, async paging, chunked file uploads, Graph support and consistent error handling, which cuts boilerplate and bugs. It still uses SPFx authentication through the SPFx(context) behavior.

Q2What does spfi().using(SPFx(this.context)) do?

It creates a PnPjs SharePoint instance and attaches the SPFx behavior, which sets the base URL from the page context and uses SPFx's authentication (digest and tokens) for requests.

Q3How do you avoid "property does not exist on type" errors after upgrading PnPjs?

Add the selective import for the feature, for example import "@pnp/sp/items", and keep all @pnp packages at the same version.
