SPFx CRUD with SPHttpClient – Create, Read, Update, Delete via SharePoint REST

A complete, typed service for SharePoint list CRUD in SPFx using SPHttpClient, covering configurations, OData queries, ETags and concurrency, person and lookup fields, batching, error handling, and the full React usage.

SPHttpClient is SPFx's built-in HTTP client for SharePoint REST. It automatically adds authentication, the request digest for writes, and the right OData headers. No extra libraries are needed.

#A reusable, typed list service

services/ListService.tsTypeScript
import { SPHttpClient, SPHttpClientResponse, ISPHttpClientOptions } from '@microsoft/sp-http';

export interface IListItem { Id: number; Title: string; Status: string; DueDate?: string; OwnerId?: number; '@odata.etag'?: string; }

export class ListService {
  private readonly headers = { 'Accept': 'application/json;odata=nometadata', 'Content-Type': 'application/json;odata=nometadata', 'odata-version': '' };

  constructor(private client: SPHttpClient, private webUrl: string, private listTitle: string) {}

  private get itemsUrl(): string {
    return `${this.webUrl}/_api/web/lists/getbytitle('${encodeURIComponent(this.listTitle.replace(/'/g, "''"))}')/items`;
  }

  // READ (filter + select + expand + paging)
  public async getItems(filter = "Status ne 'Closed'", top = 50): Promise<IListItem[]> {
    const url = `${this.itemsUrl}?$select=Id,Title,Status,DueDate,OwnerId,Owner/Title&$expand=Owner` +
                `&$filter=${encodeURIComponent(filter)}&$orderby=DueDate asc&$top=${top}`;
    const res = await this.client.get(url, SPHttpClient.configurations.v1, { headers: this.headers });
    const json = await this.ensureOk(res);
    return json.value as IListItem[];
  }

  public async getItem(id: number): Promise<IListItem> {
    const res = await this.client.get(`${this.itemsUrl}(${id})?$select=Id,Title,Status,DueDate,OwnerId`,
      SPHttpClient.configurations.v1, { headers: this.headers });
    return this.ensureOk(res);
  }

  // CREATE
  public async create(item: Partial<IListItem>): Promise<IListItem> {
    const res = await this.client.post(this.itemsUrl, SPHttpClient.configurations.v1, {
      headers: this.headers,
      body: JSON.stringify({ Title: item.Title, Status: item.Status ?? 'Submitted', DueDate: item.DueDate, OwnerId: item.OwnerId })
    });
    return this.ensureOk(res);
  }

  // UPDATE with optimistic concurrency (pass the ETag you read)
  public async update(id: number, changes: Partial<IListItem>, etag = '*'): Promise<void> {
    const options: ISPHttpClientOptions = {
      headers: { ...this.headers, 'IF-MATCH': etag, 'X-HTTP-Method': 'MERGE' },
      body: JSON.stringify(changes)
    };
    const res = await this.client.post(`${this.itemsUrl}(${id})`, SPHttpClient.configurations.v1, options);
    if (res.status === 412) throw new Error('This item was changed by someone else. Reload and try again.');
    await this.ensureOk(res, true);
  }

  // DELETE (recycle bin)
  public async recycle(id: number): Promise<void> {
    const res = await this.client.post(`${this.itemsUrl}(${id})/recycle()`, SPHttpClient.configurations.v1, { headers: this.headers });
    await this.ensureOk(res, true);
  }

  private async ensureOk(res: SPHttpClientResponse, noBody = false): Promise<any> {
    if (res.ok) return noBody || res.status === 204 ? undefined : res.json();
    let message = `${res.status} ${res.statusText}`;
    try { const e = await res.json(); message = e['odata.error']?.message?.value ?? e.error?.message ?? message; } catch { /* no body */ }
    throw new Error(message);
  }
}

#Batching many operations

SPHttpClient also supports $batch (this.context.spHttpClient.beginBatch() in older versions). In practice PnPjs batching is simpler and better maintained. See PnPjs CRUD.

Errors you will see

400 with "Column 'X' does not exist" means an internal name typo. 403 means the user lacks permission. 412 is an ETag conflict. 429/503 means throttling, so respect Retry-After. 500 with "exceeds the list view threshold" means you need an indexed filter.

#Interview questions

Q1Why use SPHttpClient instead of fetch in SPFx?

SPHttpClient handles authentication context and the form digest for write requests automatically, adds SharePoint-specific headers, and integrates with SPFx telemetry and throttling behaviour. fetch would require you to manage the digest manually.

Q2What does SPHttpClient.configurations.v1 do?

It selects the default configuration (headers such as odata-version, digest handling, and credentials). It is required on every call and allows future configuration versions without breaking existing code.

Q3How do you implement optimistic concurrency on updates?

Read the item including its @odata.etag. On update, send IF-MATCH: <etag> with X-HTTP-Method: MERGE. A 412 Precondition Failed response means someone else changed the item, so show a conflict message.
