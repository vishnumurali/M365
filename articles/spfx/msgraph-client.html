Calling Microsoft Graph from SPFx with MSGraphClientV3

Use MSGraphClientV3 to read users, groups, mail, calendar, files and Teams data from SPFx, request permissions with webApiPermissionRequests, handle paging and batching, and avoid the common consent and throttling mistakes.

MSGraphClientV3 (SPFx 1.15+) wraps the Microsoft Graph JavaScript SDK v3 and authenticates as the current user with delegated permissions that a tenant admin approves once. It is the easiest way for a web part to show people, calendars, mail, Planner tasks, Teams or files across Microsoft 365.

#Token flow

All SPFx solutions share one Entra service principal (SharePoint Online Client Extensibility Web Application Principal). Permissions approved for one solution are available to every SPFx solution in the tenant. Approve the minimum.

#Request permissions

config/package-solution.jsonJSON
"webApiPermissionRequests": [
  { "resource": "Microsoft Graph", "scope": "User.ReadBasic.All" },
  { "resource": "Microsoft Graph", "scope": "Calendars.Read" },
  { "resource": "Microsoft Graph", "scope": "Sites.Read.All" }
]

After deployment an admin approves them in SharePoint admin center → Advanced → API access (or with m365 spo serviceprincipal permissionrequest approve). See API permissions.

#Examples

Users, calendar, files and TeamsTypeScript
import { MSGraphClientV3 } from '@microsoft/sp-http';

const client: MSGraphClientV3 = await this.context.msGraphClientFactory.getClient('3');

// 1) Search people (User.ReadBasic.All)
const people = await client.api('/users')
  .header('ConsistencyLevel', 'eventual')
  .search('"displayName:jan"').select('id,displayName,mail,jobTitle').top(10).get();

// 2) My next 5 meetings (Calendars.Read)
const now = new Date().toISOString();
const inAWeek = new Date(Date.now() + 7 * 864e5).toISOString();
const events = await client.api('/me/calendarView')
  .query({ startDateTime: now, endDateTime: inAWeek })
  .select('subject,start,end,onlineMeeting,location').orderby('start/dateTime').top(5).get();

// 3) Recent files (Files.Read)
const recent = await client.api('/me/drive/recent').top(10).get();

// 4) Teams I'm a member of (Team.ReadBasic.All)
const teams = await client.api('/me/joinedTeams').select('id,displayName').get();

// 5) Profile photo as blob URL
const photo: Blob = await client.api('/me/photo/$value').responseType('blob' as any).get();
const photoUrl = URL.createObjectURL(photo);

#Paging and batching

Follow @odata.nextLinkTypeScript
let res = await client.api('/groups').select('id,displayName').top(100).get();
const groups = [...res.value];
while (res['@odata.nextLink']) {
  res = await client.api(res['@odata.nextLink']).get();
  groups.push(...res.value);
}
JSON batching (up to 20 requests per batch)TypeScript
const batch = {
  requests: [
    { id: '1', method: 'GET', url: '/me?$select=displayName' },
    { id: '2', method: 'GET', url: '/me/manager?$select=displayName,mail' },
    { id: '3', method: 'GET', url: '/me/memberOf?$select=displayName&$top=20' }
  ]
};
const result = await client.api('/$batch').post(batch);
const byId = Object.fromEntries(result.responses.map((r: any) => [r.id, r.body]));
Pick the smallest scope

User.ReadBasic.All is enough for people cards (name, mail, photo). User.Read.All exposes far more. Sites.Read.All lets every SPFx solution read every site the user can see through Graph. Approve it only if needed.

#Common errors

Error Cause / fix
403 Forbidden / Insufficient privileges Scope not requested or not approved, so approve it in API access
AADSTS65001: user or administrator has not consented Pending permission request not approved
Works for admin, fails for users Graph scope requires admin consent that was only granted personally, or the user lacks a licence/mailbox
429 Too Many Requests Throttled, so honour Retry-After and reduce chatty calls (batch)

#Interview questions

Q1Which identity does MSGraphClientV3 use?

Delegated permissions on behalf of the signed-in user, through the shared SharePoint Online Client Extensibility Web Application Principal in Entra ID. Results are trimmed to what that user can access.

Q2Why are approved Graph permissions a tenant-wide decision?

All SPFx solutions use the same service principal, so a scope approved for one solution can be used by any SPFx code in the tenant. Review requests carefully and use the least-privileged scopes. For high-privilege needs, call your own API protected by a dedicated Entra app (AadHttpClient).
