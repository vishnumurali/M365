Debugging & Testing SPFx – Workbench, Source Maps, VS Code, Jest and Mocks

Debug web parts and extensions in the hosted workbench and real pages with source maps and VS Code, read SPFx logs, and write Jest unit tests with mocked services and React Testing Library.

#Debugging options

.vscode/launch.json (hosted workbench)JSON
{
  "version": "0.2.0",
  "configurations": [
    {
      "name": "Hosted workbench (Edge)",
      "type": "msedge",
      "request": "launch",
      "url": "https://contoso.sharepoint.com/sites/dev/_layouts/15/workbench.aspx",
      "webRoot": "${workspaceRoot}",
      "sourceMaps": true,
      "sourceMapPathOverrides": { "webpack:///.././src/*": "${webRoot}/src/*" },
      "runtimeArgs": ["--remote-debugging-port=9222", "-inprivate"]
    }
  ]
}

Run gulp serve --nobrowser (or the npm start script), then press F5. Breakpoints in your TypeScript files are hit through source maps.

#Debugging an extension on a real page

config/serve.json – serveConfigurationsJSON
"serveConfigurations": {
  "default": {
    "pageUrl": "https://contoso.sharepoint.com/sites/dev/Lists/Deviations/AllItems.aspx",
    "customActions": {
      "a1b2c3d4-e5f6-4a7b-8c9d-0e1f2a3b4c5d": { "location": "ClientSideExtension.ListViewCommandSet.CommandBar", "properties": {} }
    }
  }
}

#Production debugging

  • Append ?debug=true&noredir=true&debugManifestsFile=https://localhost:4321/temp/manifests.js to load your local bundle on a production page, without deploying.
  • Use Log.info/warn/error from @microsoft/sp-core-library with a source name, then filter in DevTools.
  • Press Ctrl+F12 on a modern page to open the SharePoint developer dashboard (component load times, manifests, logs).

#Unit testing with Jest

Install test toolingBash
npm i -D jest ts-jest @types/jest jest-environment-jsdom @testing-library/react@12 @testing-library/jest-dom identity-obj-proxy
jest.config.jsJavaScript
module.exports = {
  preset: 'ts-jest',
  testEnvironment: 'jsdom',
  roots: ['<rootDir>/src'],
  moduleNameMapper: { '\\.(css|scss)$': 'identity-obj-proxy', '^@microsoft/sp-(.*)$': '<rootDir>/__mocks__/sp-stub.js' },
  reporters: ['default'],
};
Deviations.test.tsx – component with a mocked serviceTSX
import * as React from 'react';
import { render, screen, waitFor } from '@testing-library/react';
import '@testing-library/jest-dom';
import { Deviations } from '../components/Deviations';
import { IDeviationService } from '../services/DeviationService';

const fakeService: IDeviationService = {
  getOpen: jest.fn().mockResolvedValue([{ Id: 1, Title: 'Cold room excursion', Status: 'Submitted' }]),
  create: jest.fn(), close: jest.fn().mockResolvedValue(undefined)
};

test('renders open deviations from the service', async () => {
  render(<Deviations service={fakeService} title="Open deviations" />);
  expect(screen.getByText(/Loading/)).toBeInTheDocument();
  await waitFor(() => expect(screen.getByText('Cold room excursion')).toBeInTheDocument());
  expect(fakeService.getOpen).toHaveBeenCalledWith(20);
});

test('shows an error message when the service fails', async () => {
  (fakeService.getOpen as jest.Mock).mockRejectedValueOnce(new Error('403 Forbidden'));
  render(<Deviations service={fakeService} title="x" />);
  await waitFor(() => expect(screen.getByText('403 Forbidden')).toBeInTheDocument());
});
Make code testable

Keep SPFx context out of components. Pass interfaces (services) as props or through React context, and the tests can supply fakes without SharePoint. Test services separately by mocking SPHttpClient or PnPjs calls.

#Interview questions

Q1How do you debug an SPFx extension?

Extensions need a real page. Run the local serve with a serveConfigurations entry (page URL plus customActions or fieldCustomizers with the component ID), or append ?loadSPFX=true&debugManifestsFile=https://localhost:4321/temp/manifests.js&customActions={...} to a page URL, then use DevTools or VS Code with source maps.

Q2How do you unit test a web part that calls SharePoint?

Isolate data access in services behind interfaces, inject them into React components, and in Jest replace them with mocks (jest.fn().mockResolvedValue(...)). Use React Testing Library to assert on rendered output for loading, success, empty and error states.
