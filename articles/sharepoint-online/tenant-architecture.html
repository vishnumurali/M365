Tenant Architecture – How SharePoint Online Is Organized Behind the Scenes

Tenants, the admin center, the root site, URLs and geos, how Microsoft 365 groups and Teams create sites, where identity and permissions come from, and the request path from browser to content.

A tenant is your organization's dedicated instance of Microsoft 365. For SharePoint, it means a set of URLs, a pool of storage, an admin center and policies that apply to every site.

#URLs you should know

URL What lives there
https://contoso.sharepoint.com Root site (often the intranet home)
https://contoso.sharepoint.com/sites/<name> Communication sites and most team sites
https://contoso.sharepoint.com/teams/<name> Team sites (configurable managed path)
https://contoso-my.sharepoint.com/personal/<user> OneDrive for each user
https://contoso-admin.sharepoint.com SharePoint admin center
https://contoso.sharepoint.com/sites/appcatalog Tenant app catalog (name varies)
https://contoso.sharepoint.com/_layouts/15/sharepoint.aspx SharePoint start page

#The logical picture

#How a Teams team creates a SharePoint site

Permissions on a group-connected team site come from the group: owners → Site Owners, members → Site Members. Adding someone to the team adds them to the site. Private and shared channels get their own site with separate membership. That matters for governance and migrations.

#Storage and quotas

  • Tenant storage pool = 1 TB + 10 GB per licensed user (plus purchased add-on storage).
  • Each site can go up to 25 TB. Admins can switch between automatic and manual site quotas.
  • OneDrive default storage per user is set separately (commonly 1 TB).

#Multi-Geo

Multinational tenants with Multi-Geo can place sites and OneDrives in specific geographies (contosoEUR.sharepoint.com) to meet data-residency requirements. A user's preferred data location decides where their OneDrive and the group sites they create are stored.

#Request path (simplified)

Files are stored encrypted in Azure Storage (each file split into chunks with separate keys), while metadata lives in SQL databases. Microsoft operates many SharePoint farms per region, and your tenant lives on one of them.

#Interview questions

Q1What is the difference between /sites/ and /teams/ URLs?

Both are managed paths for site collections. Communication sites default to /sites/. Team sites can be configured (admin center → Settings → Site creation) to use /teams/. Functionally they are the same.

Q2How are permissions managed for a Teams-connected site?

Through the Microsoft 365 group. Group owners become site owners and group members become site members. Additional SharePoint permissions can be granted, but they are not visible in Teams. Private and shared channels have separate sites with their own membership.

Q3What determines the tenant's SharePoint storage?

The pooled tenant quota: 1 TB plus 10 GB per eligible licence, plus any purchased storage. Sites draw from this pool up to 25 TB each. OneDrive storage is separate, per user.
