Document Library, List, File & Embed Web Parts – Bringing Data onto Pages

How to put libraries, lists, files, Power BI, Power Apps and external content on modern pages, with connected (dynamic data) web parts, view and folder selection, iframe allow-lists and common limitations.

Pages become useful dashboards when they show live data. Modern SharePoint provides Document library, List, File and media, Power BI, Power Apps and Embed web parts. Several of them can be connected, so selecting an item in one filters another.

#Connected web parts (dynamic data)

List · Projects (select a row)List properties · Manager, Budget, StatusDocument library · files of the selected projectFile and media · preview of the selected document

A no-code project dashboard built from four connected web parts

Supported connections include List → Document library, List → List properties, Document library → File and media, Page properties and search-box-like scenarios. Configure them in the target web part's property pane under Connect to source.

#Document library & List web parts

Setting Notes
Library / list Any in the current site (cross-site requires the source site's web part or an SPFx solution)
View Pick a view, including views with view formatting JSON
Folder Show a specific folder
Size Fixed height for consistent page design
Hide command bar Cleaner read-only display
Same-site limitation

These web parts show libraries and lists from the current site. For cross-site roll-ups use Highlighted content (search-based) or an SPFx web part.

#File and media

Previews 270+ file types inline: Office documents, PDFs, images, 3D models, videos and Visio. Choose a start page for PDFs and toggle the download and print toolbar.

#Power BI & Power Apps

  • Power BI: paste the report link and choose the page and display options. Viewers need access to the report (and appropriate licences or Premium capacity). Use filters in the URL for context (?filter=Table/Column eq 'Value').
  • Power Apps: paste the app's web link or ID. Pass context with URL parameters, then read them in the app with Param("project").
Read a parameter passed from the SharePoint page into an embedded canvas appPower Fx
// App.OnStart
Set(varProjectId, Value(Param("projectId")));
ClearCollect(colTasks, Filter(Tasks, ProjectId = varProjectId));

#Embed web part & HTML field security

The Embed web part accepts a URL or <iframe> code. Admins control which domains are allowed:

  • Site level: Site settings → HTML Field Security (allow iframes from any domain, none, or a list of domains).
  • Tenant level: Microsoft provides default trusted domains such as YouTube, Vimeo, Microsoft Stream and Forms.
Typical embed codeHTML
<iframe src="https://forms.office.com/Pages/ResponsePage.aspx?id=XXXX&embed=true"
        width="100%" height="640" frameborder="0" allowfullscreen></iframe>
Embed is not a scripting backdoor

Scripts inside the Embed web part are not executed on the page, and only iframes from allowed domains render. For real interactivity build an SPFx web part.

#Interview questions

Q1How can you build a dashboard where selecting a project filters its documents, without code?

Put a List web part (Projects) and a Document library web part on the page, then in the library web part choose Connect to source → the List web part, and filter the library's Project column by the selected item. Optionally add List properties and File and media web parts.

Q2Why might an iframe not render in the Embed web part?

The domain is not on the site's HTML Field Security allow-list, the target site sends X-Frame-Options or CSP headers that forbid framing, or the content requires third-party cookies that the browser blocks.
