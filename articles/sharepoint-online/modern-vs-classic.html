Modern vs Classic SharePoint – Differences, Why It Matters & How to Modernize

A side-by-side comparison of the classic and modern experiences (pages, lists, customization, performance, mobile), how to detect classic sites in your tenant, and the modernization options from no-code to scripted transformation.

Classic SharePoint is the 2007–2013 user interface (ribbon, master pages, wiki and web part pages, server-rendered lists). Modern SharePoint (from 2016) is a client-side, responsive experience built with React. Both still exist in SharePoint Online, but every new investment, including Copilot, agents, the new web parts and SPFx extensions, targets modern.

#Side by side

Area Classic Modern
Pages Wiki/web part/publishing pages, page layouts Site pages with sections and web parts, page templates
Navigation Structural/managed navigation per site Hub navigation, global navigation, audience targeting
Lists Server-rendered views, JSLink Client-rendered, column/view/form formatting JSON
Branding Master pages, alternate CSS Themes, brand center, SPFx application customizer
Customization Script Editor, JSLink, add-ins, farm (on-prem) SPFx (web parts, extensions, ACEs)
Mobile Limited Fully responsive, SharePoint mobile app
Performance Heavy server rendering Client-side, CDN-hosted assets
Copilot / agents Limited value Full support

#Modernization options

Groupify a classic team site and swap the root sitePowerShell
Connect-SPOService -Url https://contoso-admin.sharepoint.com

# Attach a Microsoft 365 group to an existing team site
Set-SPOSiteOffice365Group -Site https://contoso.sharepoint.com/sites/finance `
  -DisplayName "Finance" -Alias "finance" -IsPublic $false

# Replace the classic root site with a modern communication site
Invoke-SPOSiteSwap -SourceUrl https://contoso.sharepoint.com/sites/newhome `
  -TargetUrl https://contoso.sharepoint.com `
  -ArchiveUrl https://contoso.sharepoint.com/sites/oldhome
Transform classic pages to modern (PnP PowerShell)PowerShell
Connect-PnPOnline -Url https://contoso.sharepoint.com/sites/finance -Interactive -ClientId $clientId
Get-PnPListItem -List "Site Pages" | ForEach-Object {
  ConvertTo-PnPPage -Identity $_.FieldValues["FileLeafRef"] -Overwrite -TakeSourcePageName -AddPageAcceptBanner
}

To detect classic usage at scale, run the Microsoft 365 Assessment tool or the older SharePoint Modernization Scanner. They report classic pages, customizations, workflows and InfoPath per site. See Classic to modern transformation.

#Interview questions

Q1Name three reasons to move from classic to modern.

Responsive and mobile-friendly UI with better performance; support for current customization (SPFx, formatting JSON) and features such as hubs, news, Copilot and agents; and lower maintenance, because there are no master pages or Script Editor code to break with updates.

Q2How do you convert classic pages to modern pages?

Use PnP page transformation (ConvertTo-PnPPage or the .NET framework). It maps classic web parts to modern equivalents based on a mapping file, preserves content, and can keep the original page name. Run it after inventorying pages with the Assessment tool.

Q3What does "groupify" mean?

Connecting an existing classic team site to a new Microsoft 365 group (Set-SPOSiteOffice365Group), which adds group features such as a shared mailbox, Planner and the ability to add Microsoft Teams, without moving content.
