Large Lists in SharePoint Online – The 5,000 Threshold, Indexes and Query Patterns

What the list view threshold means in SharePoint Online, automatic and manual indexing, modern view behaviour, and safe patterns for REST, Graph, Power Automate, Power Apps and PnPjs against lists with millions of items.

SharePoint Online lists can hold 30 million items, but any single query that must scan more than 5,000 items without an index fails with "The attempted operation is prohibited because it exceeds the list view threshold". Unlike on-premises, the threshold cannot be changed in SharePoint Online.

#What SharePoint Online does for you

#Safe query patterns per technology

Technology Pattern
REST $filter on an indexed column first; $top ≤ 5000; follow odata.nextLink
Graph /items?$filter=fields/Status eq 'Open' with indexed column, $top, @odata.nextLink; header Prefer: HonorNonIndexedQueriesWarningMayFailRandomly only for small lists
CSOM CamlQuery with RowLimit Paged=TRUE + ListItemCollectionPosition; OrderBy ID
PnPjs items.top(5000) + async iteration over pages, or getItemsByCAMLQuery with paging
Power Automate Get items with Filter Query on indexed columns, Top Count, and Pagination threshold (settings)
Power Apps Delegable Filter on indexed columns; delegation limit (500–2,000) for non-delegable functions
PnPjs: iterate all items of a huge list safelyTypeScript
import { spfi } from "@pnp/sp";
import "@pnp/sp/webs"; import "@pnp/sp/lists"; import "@pnp/sp/items";

const sp = spfi(/* SPFx context or Node config */);
const all: any[] = [];
// async iterator pages through results (default page size 2000 here via top)
for await (const page of sp.web.lists.getByTitle("Deviations").items
                           .select("Id", "Title", "Status")
                           .filter("Status eq 'Open'")      // Status must be indexed!
                           .top(2000)) {
  all.push(...page);
}
console.log(all.length);
REST: indexed filter + pagingHTTP
GET /_api/web/lists/getbytitle('Deviations')/items?$select=Id,Title,Status&$filter=Status eq 'Open'&$top=5000
Accept: application/json;odata=nometadata

→ response contains "odata.nextLink": ".../items?%24skiptoken=Paged%3dTRUE%26p_ID%3d5000&..."
Index before you grow

You cannot easily add an index through the UI on a list with more than 20,000 items. Plan indexes on day one (Status, Created, Modified, foreign keys, dates you filter by) and create them in your provisioning script.

#Design patterns for very large data

  • Partition: one list per year or business unit, with roll-up through search.
  • Archive: a scheduled flow or function moves closed items older than N months to an archive list.
  • Dataverse: if you need relational queries, complex security or millions of transactional rows, use Dataverse instead. See Dataverse vs SharePoint lists.

#Interview questions

Q1Can you increase the 5,000 list view threshold in SharePoint Online?

No. It is fixed in SharePoint Online. You design around it with indexed columns, filtered views, folders, paging in code and archiving.

Q2A Power Automate "Get items" returns only 100 items from a 20,000-item list. Why?

The default Top Count is 100. Set Top Count (up to 5,000 per page), turn on Pagination in the action settings with a threshold, and use an OData filter on an indexed column to reduce rows.

Q3What is the maximum number of indexed columns per list?

20 per list. Choose them based on the filters and sorts your views and queries actually use.
