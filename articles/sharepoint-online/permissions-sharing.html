Permissions & Sharing – Groups, Permission Levels, Sharing Links and Oversharing Control

How SharePoint Online permissions really work, covering site groups, Microsoft 365 group membership, permission levels, inheritance, sharing link types, external sharing settings at tenant and site level, and how to audit and fix oversharing.

Permissions answer who can do what with which content. In SharePoint Online they come from three sources at once: SharePoint groups, the Microsoft 365 group (for group-connected sites), and sharing links. Understanding all three is the key to preventing oversharing, which matters more than ever now that Copilot can find anything a user has access to.

#The permission model

Default group Group-connected team site Communication site Permission level
Owners M365 group owners Added directly Full Control
Members M365 group members Added directly Edit
Visitors (added directly) Added directly Read

#Inheritance

By default everything inherits from its parent: site → library → folder → file. Breaking inheritance creates a unique permission scope. Each unique scope:

  • adds complexity users cannot see,
  • slows permission checks and search,
  • counts toward limits (50,000 unique scopes per list; keep it far lower).
Golden rules

Grant to groups, not individuals. Break inheritance at site or library level, not on thousands of items. Use separate sites for genuinely different audiences. Document every exception.

#Sharing links

Link type Who can open Risk
Anyone Anyone with the link, no sign-in Highest: forwardable, anonymous
People in your organization Any signed-in employee with the link Medium: discoverable by Copilot/search once used
People with existing access Only those who already have permission None: just a URL
Specific people Named users (internal or guests) Lowest: explicit grant

Sharing settings are configured at tenant level (the maximum) and can be more restrictive per site:

Tenant and site sharing settingsPowerShell
Connect-SPOService -Url https://contoso-admin.sharepoint.com

# Tenant: allow guests (new and existing) but no anonymous links; default link = specific people
Set-SPOTenant -SharingCapability ExternalUserSharingOnly `
  -DefaultSharingLinkType Direct -DefaultLinkPermission View `
  -RequireAcceptingAccountMatchInvitedAccount $true

# Site: internal only for HR
Set-SPOSite -Identity https://contoso.sharepoint.com/sites/hr -SharingCapability Disabled

# Site: restrict sharing to owners only (members can't share)
Set-SPOSite -Identity https://contoso.sharepoint.com/sites/legal -DisableSharingForNonOwners

#Checking who has access

PnP: who has access to a library and its items?PowerShell
Connect-PnPOnline -Url https://contoso.sharepoint.com/sites/legal -Interactive -ClientId $clientId

# Site-level role assignments
Get-PnPSiteGroup | Select-Object Title, Roles, Users

# Items with unique permissions in "Contracts"
Get-PnPListItem -List "Contracts" -PageSize 2000 -Fields "FileRef","HasUniqueRoleAssignments" |
  Where-Object { $_["HasUniqueRoleAssignments"] } |
  ForEach-Object {
    $ra = Get-PnPProperty -ClientObject $_ -Property RoleAssignments
    foreach ($r in $ra) {
      $m = Get-PnPProperty -ClientObject $r -Property Member, RoleDefinitionBindings
      [pscustomobject]@{ File = $_["FileRef"]; Principal = $r.Member.Title; Roles = ($r.RoleDefinitionBindings.Name -join ",") }
    }
  } | Export-Csv .\contracts-permissions.csv -NoTypeInformation

#Oversharing and Copilot

SharePoint Advanced Management (included with Microsoft 365 Copilot licences) provides data access governance reports, site access reviews by owners, restricted access control (limit a site to a group) and restricted content discovery (hide a site from Copilot and org-wide search). See Copilot content readiness.

#Interview questions

Q1What is the difference between "People in your organization" and "Specific people" links?

An organization link works for any signed-in employee who has the link and can be forwarded internally. A specific-people link grants access only to the named users (or guests). Others who receive the URL cannot open it.

Q2How do Microsoft 365 group members get access to a team site?

Group members are placed in the site's Members SharePoint group (Edit) and owners in Owners (Full Control). Membership changes in Teams or Entra ID are reflected automatically.

Q3Why is breaking inheritance on many items a problem?

Every unique scope adds ACL complexity, slows permission checks, search crawling and sharing UI, approaches list limits, and makes access impossible to audit. Use separate libraries, folders or sites for different audiences.

Q4What tools help you find oversharing before rolling out Copilot?

SharePoint Advanced Management data access governance reports (sharing links, "Everyone" grants, sensitivity labels), site access reviews, restricted access control, restricted content discovery, sensitivity labels, and Purview content explorer.
