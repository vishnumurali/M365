Hub Sites & Information Architecture – Designing a Flat, Scalable Intranet

How to design modern information architecture with hubs, global navigation, hub navigation, audience targeting, site naming and metadata, with a worked example of an intranet IA and the scripts to build it.

Information architecture (IA) is how content is organized, labelled and navigated so people can find it. In modern SharePoint the IA building blocks are sites (one per topic, team or project), hubs (to group sites), navigation at three levels, and metadata inside sites.

#The three levels of navigation

#Why hubs instead of subsites

Subsites (classic) Hubs (modern)
Permissions inherit down the tree Each site keeps its own permissions
Hard to move (re-parenting means a migration) Re-associate a site with another hub in seconds
Navigation built per site collection Hub navigation shared automatically
Fixed by org chart Flexible when the organization changes

#Hub features

  • Shared navigation bar and theme for associated sites.
  • Search scope: searching from a hub site returns results from all associated sites.
  • Roll-ups: the News, Events, Highlighted content and Sites web parts can show content from all hub sites.
  • Hub permissions sync (optional): add hub visitors to associated sites.
  • Associated hubs: link hubs together for search and roll-ups (up to 3 levels).

#Worked example: intranet IA

Hub Sites (examples) Owner Audience
Home (home site) Intranet home, News center Internal Comms Everyone
People & HR HR Portal (comm), Policies (comm), Learning (comm), HR Team (team) HR Everyone / HR
Operations Quality (comm), Deviations app (team), Plant A (team), Plant B (team) COO office Ops staff
Finance Finance Portal (comm), AP (team), Audit (team, private) CFO office Finance / Everyone
IT IT Help (comm), Projects hub sites CIO office Everyone / IT
Build the hub structure with PnP PowerShellPowerShell
$hubs = @(
  @{ Url = "/sites/people";     Title = "People & HR" },
  @{ Url = "/sites/operations"; Title = "Operations" },
  @{ Url = "/sites/finance";    Title = "Finance" }
)
foreach ($h in $hubs) {
  $full = "https://contoso.sharepoint.com$($h.Url)"
  if (-not (Get-PnPTenantSite -Identity $full -ErrorAction SilentlyContinue)) {
    New-PnPSite -Type CommunicationSite -Title $h.Title -Url $full | Out-Null
  }
  Register-PnPHubSite -Site $full -ErrorAction SilentlyContinue
}

# Associate sites
Add-PnPHubSiteAssociation -Site "https://contoso.sharepoint.com/sites/quality" -HubSite "https://contoso.sharepoint.com/sites/operations"

# Hub navigation (run against the hub site)
Connect-PnPOnline -Url "https://contoso.sharepoint.com/sites/operations" -Interactive -ClientId $clientId
Add-PnPNavigationNode -Location TopNavigationBar -Title "Quality" -Url "https://contoso.sharepoint.com/sites/quality"
Add-PnPNavigationNode -Location TopNavigationBar -Title "Plants" -Url "#"

#Audience targeting

Navigation links, news posts, Quick Links and Highlighted content items can be targeted to Entra ID or Microsoft 365 groups. Enable it in Site settings → Navigation or per web part, then set audiences per item. Targeting hides content from people outside the audience. It is not security, so do not use it to protect confidential content.

#IA design checklist

  • One site per topic or team, with clear owners (at least 2) and a purpose statement.
  • Naming convention for URLs (short, no dates, lowercase, no spaces).
  • 5–10 top-level hubs aligned with how employees think (not only the org chart).
  • Global navigation from the home site pointing to hubs and key resources.
  • Metadata over folders: content types and site columns for document classification.
  • Search tuned: promoted results, synonyms, managed properties for key metadata.
  • Governance: who can create sites, associate with hubs, and change hub navigation.

#Interview questions

Q1What is the maximum depth of hub navigation, and how do associated hubs work?

Hub navigation supports up to three levels of links. Associated hubs let you connect hubs together (up to three levels) so search and roll-up web parts span them. They do not share a navigation bar automatically.

Q2Is audience targeting a security feature?

No. It only filters what is displayed in navigation and web parts. Users who are not in the audience can still open the content if they have permission. Use permissions or sensitivity labels to protect data.

Q3How would you restructure an intranet built with deep subsites?

Inventory the subsites, define target hubs and sites, migrate each significant subsite to its own site collection (with ShareGate or similar), re-create navigation as hub navigation, set up redirects, and archive the old structure.
