Events & Calendar Web Parts – Events Lists, Group Calendars and Migrating Classic Calendars

How the Events web part, events lists and Group calendar work, with filmstrip, compact and carousel layouts, hub roll-ups, category filters, the classic calendar list problem, and options to migrate or replace calendars.

Most intranets need "what's on" calendars. Modern SharePoint offers two different tools that people often confuse: the Events web part (backed by a SharePoint events list) and the Group calendar web part (backed by the Outlook calendar of a Microsoft 365 group).

#Events web part vs Group calendar

Events web part Group calendar web part
Data source SharePoint events list (site, hub or multiple sites) Exchange calendar of a Microsoft 365 group
Who adds events Site members (or anyone with list permissions) Group members via Outlook/Teams
Roll-ups across sites ✅ Hub, selected sites, all sites in a hub ❌ One group per web part
Categories & filters ✅ Category column, date ranges, audience targeting ❌
Add to my calendar ✅ Download .ics Native Outlook
Online meeting links ✅ Teams link field ✅
Best for Public intranet events, trainings Team-internal schedule

#The classic calendar list problem

Classic Calendar lists (template 106) from SharePoint 2010–2016 still exist in many tenants. In modern SharePoint:

  • The Events web part can use them as a source (events lists are calendar lists).
  • Recurring events created in classic calendars render, but editing recurrence in the modern UI is limited.
  • The classic calendar view (month grid with overlays) is classic-only. Modern lists offer a Calendar view (list view type) for any list with date columns.
Migration options for classic calendars
  1. Keep as events list: works for simple calendars, so add an Events web part on the modern page.
  2. Modern list + calendar view: create a Microsoft List with start/end date columns and a calendar view; migrate items (ShareGate maps calendar → list).
  3. Group calendar: if the calendar was a team schedule, move it to the M365 group's Outlook calendar.
  4. Recurring events: expand recurrences to individual items during migration when the target does not support recurrence editing.
Find classic calendar lists across sites (PnP PowerShell)PowerShell
$sites = Get-PnPTenantSite -Detailed | Where-Object Template -notlike "SPSPERS*"
foreach ($s in $sites) {
  Connect-PnPOnline -Url $s.Url -Interactive -ClientId $clientId
  Get-PnPList | Where-Object BaseTemplate -eq 106 |
    Select-Object @{n='Site';e={$s.Url}}, Title, ItemCount, LastItemModifiedDate
}
Read upcoming events via REST (for an SPFx web part or script)JavaScript
const now = new Date().toISOString();
const url = `${siteUrl}/_api/web/lists/getbytitle('Events')/items` +
  `?$select=Title,EventDate,EndDate,Location,Category,fAllDayEvent` +
  `&$filter=EventDate ge datetime'${now}'&$orderby=EventDate asc&$top=10`;
const { value } = await (await fetch(url, { headers: { Accept: "application/json;odata=nometadata" } })).json();

#Interview questions

Q1What is the difference between the Events and Group calendar web parts?

Events reads SharePoint events lists and can roll up events across sites and hubs with categories and audience targeting. Group calendar shows the Outlook calendar of one Microsoft 365 group and is managed through Outlook or Teams.

Q2How do you show events from several department sites on the intranet home?

Associate the department sites with a hub (or select them explicitly), add an Events web part on the home or hub page with the source set to all sites in the hub (or selected sites), and filter by category or date range.

Q3How should recurring events in classic calendars be handled during migration?

Check whether the target supports recurrence. Often the safest approach is to expand recurrences into individual items for the needed date range, or migrate the calendar to an Outlook group calendar where recurrence is native.
