PnP Provisioning Templates – Export, Edit and Apply Complete Site Blueprints

How the PnP provisioning engine captures and applies sites (lists, content types, pages, navigation, security, files, term sets), template anatomy, tokens, tenant templates, and running provisioning from Azure Functions or Azure Automation.

The PnP provisioning engine (part of PnP Framework and PnP PowerShell) is the community's answer to "make every new site look exactly like this one". It can export a configured site to a template (XML or .pnp package) and apply it to other sites, idempotently.

#Exporting and applying

Capture a golden sitePowerShell
Connect-PnPOnline -Url https://contoso.sharepoint.com/sites/golden-quality -Interactive -ClientId $clientId

Get-PnPSiteTemplate -Out ".\quality-site.xml" `
  -Handlers Lists, ContentTypes, Fields, Pages, Navigation, Theme, SiteSecurity `
  -IncludeAllPages -PersistBrandingFiles -ExcludeHandlers Workflows
Apply to a new site with parametersPowerShell
Connect-PnPOnline -Url https://contoso.sharepoint.com/sites/plant-b-quality -Interactive -ClientId $clientId
Invoke-PnPSiteTemplate -Path ".\quality-site.xml" -Parameters @{ "PlantName" = "Plant B"; "QualityLead" = "ravi@contoso.com" }

#Template anatomy (trimmed)

quality-site.xmlXML
<pnp:Provisioning xmlns:pnp="http://schemas.dev.office.com/PnP/2022/09/ProvisioningSchema">
  <pnp:Preferences Generator="PnP.Framework">
    <pnp:Parameters>
      <pnp:Parameter Key="PlantName">Plant A</pnp:Parameter>
    </pnp:Parameters>
  </pnp:Preferences>
  <pnp:Templates ID="CONTAINER-QUALITY">
    <pnp:ProvisioningTemplate ID="QUALITY" Version="1">
      <pnp:SiteFields>
        <Field Type="Choice" Name="ContosoSeverity" DisplayName="Severity" ID="{a1b2c3d4-0000-4000-8000-000000000001}" Group="Contoso Quality">
          <CHOICES><CHOICE>Minor</CHOICE><CHOICE>Major</CHOICE><CHOICE>Critical</CHOICE></CHOICES>
        </Field>
      </pnp:SiteFields>
      <pnp:Lists>
        <pnp:ListInstance Title="Deviations" TemplateType="100" Url="Lists/Deviations" EnableVersioning="true" MaxVersionLimit="100">
          <pnp:FieldRefs>
            <pnp:FieldRef ID="{a1b2c3d4-0000-4000-8000-000000000001}" Name="ContosoSeverity" />
          </pnp:FieldRefs>
          <pnp:Views>
            <View DisplayName="Open" DefaultView="TRUE" Type="HTML">
              <ViewFields><FieldRef Name="LinkTitle" /><FieldRef Name="ContosoSeverity" /></ViewFields>
              <Query><Where><Neq><FieldRef Name="Status"/><Value Type="Choice">Closed</Value></Neq></Where></Query>
            </View>
          </pnp:Views>
        </pnp:ListInstance>
      </pnp:Lists>
      <pnp:ClientSidePages>
        <pnp:ClientSidePage PageName="Home.aspx" Title="{parameter:PlantName} Quality" PromoteAsNewsArticle="false" Overwrite="true">
          <pnp:Sections>
            <pnp:Section Order="1" Type="OneColumn">
              <pnp:Controls>
                <pnp:CanvasControl WebPartType="List" JsonControlData="{&quot;serverProcessedContent&quot;:{},&quot;properties&quot;:{&quot;selectedListUrl&quot;:&quot;{site}/Lists/Deviations&quot;}}" />
              </pnp:Controls>
            </pnp:Section>
          </pnp:Sections>
        </pnp:ClientSidePage>
      </pnp:ClientSidePages>
    </pnp:ProvisioningTemplate>
  </pnp:Templates>
</pnp:Provisioning>

Tokens such as {site}, {sitecollection}, {listid:Deviations}, {parameter:PlantName}, {termsetid:…} and {hubsiteid} are resolved at apply time, so the same template works on any URL.

#Running provisioning unattended

Keep templates small and composable

Export with only the handlers you need, delete noise (default lists, system fields) from the XML, and split large blueprints into several templates (base, quality add-on, finance add-on). Store templates in Git and version them.

#Interview questions

Q1How is PnP provisioning different from site scripts?

Site scripts are a limited JSON action set executed by SharePoint itself, triggered from the site creation UI. PnP templates are far richer (pages with web parts, security, files, terms, data rows) but must be applied by an engine you run, such as PnP PowerShell or PnP Framework in an Azure Function or pipeline.

Q2What are provisioning tokens and why do they matter?

Placeholders like {site}, {listid:Name} or {parameter:X} that the engine resolves when applying the template. They make templates portable across sites and tenants instead of hard-coding URLs and IDs.
